罗福莉访谈审读：Agent框架、后训练、算力配置与组织平权

本期背景与内容导览

本期是张小珺对小米大模型团队负责人罗福莉的长访谈。官方简介说明，她曾供职阿里达摩院、DeepSeek，主导MiMo-V2系列；本期是其第一次长时间技术访谈。对话从她在2026年春节期间使用OpenClaw的经历出发，依次讨论Agent框架与模型的关系、从Chat到Agent的后训练迁移、MiMo-V2 Pro/Omni/TTS、算力分配、组织平权、行业竞争和个人研究经历。开场预告中的“环境比经验重要”“1T是入场券”“研究、预训练、后训练用卡3:1:1”，分别在后文03:22:41、01:44:39和01:47:14展开，不应把剪辑预告当成三个已经证明的普遍定律。 嘉宾提供的直接经历包括：连续三天深入使用并改造OpenClaw，与Agent共同构建User Agent；让团队在近百人群里共同使用、修改框架；将MiMo-V2 Flash和端侧3B模型接入框架；围绕长上下文效率设计Hybrid Attention并使用MTP；在1T量级模型训练中排查loss spike；以及让预训练、后训练、Infra成员围绕问题流动协作。这些是嘉宾对内部工作的自述，其中“第三四天还没训就跟Claude差不多”“三四周做完过去三四十周的研究”等是体验性估计，原文同时承认扩大测试后仍不如Claude稳定。 她进一步提出的行业判断是：Agent竞争要求强基座与后训练敏捷性共同存在，后训练算力应与预训练接近，RL Infra要从以推理Rollout为中心转向以Agent及其环境为中心。她把Code“拉上限”、其他领域训练“保下限”，并主张通过真实使用发现场景、还原环境、设置reward。具体环境构造、reward和RL Scaling结果在访谈中明确保密，因此不能根据这些方向性描述补出已验证配方。 在多模态方面，嘉宾区分了已经尝试的音频离散化、仍在探索的图像离散化，以及Omni实际仍使用连续ViT表征。Omni更强的世界感知和TTS风格泛化主要来自内部体感，嘉宾明确说Benchmark没有体现提升、缺少小模型对照，且TTS尚未达到生产可用。她把AI辅助研究视作AGI加速变量，但“AI训出更强模型”“两年实现AGI”“国内两三个月追上当期Opus 4.6”均为预测，不是本期给出的已完成结果。组织平权也应放回约100人全链路团队、每代模型约二三十名核心成员、公司授权和热爱驱动选人这些条件中理解。

00:01:31–00:11:01从交互产品到研究助手：三天使用OpenClaw的认知变化

  • 你提到过去几个月技术已经变天，能否阐述一下你所说的技术突变？

主持人先问过去两个月的技术突变。罗福莉把使用OpenClaw前后视作分界，但最初在1月也认为它只是Claude Code加IM交互、Skillhub及本地化等产品包装，因运营感太强而排斥。春节期间她花两小时安装，从凌晨2点聊到6点。第一天感受到的是“有灵魂”：它会提醒深夜休息，她追溯到每轮context前拼当前时间等精细编排。转录中的“搜索.md”无法确认，不能补成某个记忆文件。

第二天她讨论如何筛选有好奇心的人、建设大模型团队，Agent把对话整理成体系并沉淀Skills，她因此在团队管理这类任务上称其为“数字分身”。第三天她让它参与构建User Agent：在Agent后训练中，用模拟用户与模型多轮交互，生成更丰富的场景数据，供SFT或RL使用。她自述一两小时后已有可用成果，这是内部使用经历，不等于公开复现或证明研究已全自动。

她随后比较框架：OpenClaw的分层分级memory、多模型联合使用、消息通道等单项并不炫目，组合完成度却高。视频理解的例子是主模型不行时，框架另找合适的模型补齐，而不是主模型凭空获得视频能力。团队把当时未做很多针对性训练的MiMo-V2 Flash及一个端侧3B模型接入后，发现能完成超出其预期的任务。由此产生的新问题是：面对多种复杂框架，模型如何稳定泛化，后训练怎样从Chat迁移到Agent。

Agent框架连接人、模型、工具与环境的中间层。本期明确给出的部件包括记忆、消息渠道、定时任务、Skills和多模型调度；它改变提供给模型的信息和执行条件，不自动等于模型权重更新。
Context（上下文）既指送入模型的token、历史和环境信息，也被嘉宾借来指研究员长期知识背景。两种含义相关但不能互换：补入近期文本不证明模型获得人的全部经验。
Skills把任务执行规范、业务知识和流程沉淀给Agent复用，常由人机多轮交互形成。它能补充互联网预训练缺少的内部信息；在本期语境中首先属于框架层资产。
User Agent模拟用户与待训练模型多轮交互的代理。它产生更丰富的Agent场景和轨迹，可用于SFT或RL；其价值取决于模拟是否覆盖真实需求及评价是否可靠。

主持人追问为何曾经抵触、OpenClaw是否只是把Coding泛化，以及它是否只是释放Opus 4.6能力的“壳”。罗福莉仍认为严肃编程的顶尖体验是Claude Code加Opus 4.6；但Code上的优化不保证非Code任务同样稳定。OpenClaw增加消息通道、定时和心跳任务，更适合日常场景，同时保留持久记忆。她把Claude Code的session压缩、按plan保存记忆视作面向软件工程的设计，把OpenClaw视作更面向端到端通用任务的编排。她说近一两个月设计被Claude Code吸纳，属于其观察，未在本期核验版本历史。

“激发中层模型上限”有明确例外：写算子等严肃编程仍可能差距明显。她所谓中层，是在其估计约85%的任务上能达到Sonnet水准的模型，不是严格模型分级。对于“壳”的说法，她先认可上限依赖Opus 4.6，再补充开源的可操纵性：她用Opus改memory和当时2.x版本混乱的Multi-Agent逻辑，再切回Sonnet、国内模型和正在训练的MiMo-V2 Pro，体感明显变强。她进而把自学习描述为模型训练进步与框架改变同步发生，静态部分包括新session送入哪些memory、Skills，动态部分包括Agent架构。这里主要指上下文、技能和代码的更新，不能等同模型参数已自动持续学习。

她最后把产品定义为人直接感知的一层，把Agent框架定义为连接人、模型、工具和调度的厚中间层，UI反而很薄。Claude Code并非没有复杂框架，而是黑盒不易看见和修改；OpenClaw让她及其他使用者能按场景改造。2.x到3.x更好用的叙述用于说明群体改进的可能性，不证明所有社区贡献都提高了核心架构。

高强度使用第一周，嘉宾自述第一天四五个小时的Opus 4.6花费接近1000美元，曾因太贵切到Sonnet，但当时只有Opus能给她改造框架所需的惊艳感。随着框架被打磨好，她关注点转向还能做什么、成本和速度；第一天的惊喜很快变“boring”，说明体验评价会随熟悉程度变化。

春节时她在群里推荐却少有人响应，节后实际使用者仍少。她买几台Mac Mini统一部署，按方向拉不同飞书群，并要求第二天对话不足100轮者可以quit。她随即说明并未打算据此开除人，也没有实际考核，100轮只是表达“不用可能落后”的态度。强制在公共群使用，是为了让别人的任务激发自己的想象力。她把群消息很多形容为“999+”，又立即补充“没有这么夸张”，不应写成精确运营数据。

玩了两天后，团队开始思考用框架提升模型、再用模型改变框架；她估计三四周完成了过去三四十周的研究量，这是个人回顾而非项目审计。最有冲击的是近百人共同改框架，既能保持不同人的画像和memory不太串，也没有把系统改坏。她一方面把这种稳定性归为模型能力强而非单靠框架，另一方面认为群体修改让迭代可能几小时一轮。第三四天接入自家模型时体感接近Claude，但原话紧接着说“测得更多会发现还有很多东西没有Claude稳定”。这条反证必须与“接近Claude”并列保留。

嘉宾认为Agent把想法、代码和评估设计的循环从数天或数周压缩到数小时，使研究taste更重要：十个想法可分给不同subagent并行，且可交叉验证，不再只串行排队。但“更快得到结果”不等于结果自动可靠，后文她仍强调进入深水区需要精细评估。

她用Code解释长上下文能力：极长的天然数据主要是代码和书籍，书籍信号发散，代码文件间依赖更密集，因此有助于长上下文建模。团队在做V2之前已经重视这一准备。春节后则要把Code能力外延到其他场景，她的概括是“Code拉上限，其他领域训练保下限”：未专门训练的场景也可能泛化，但稳定性不足。软件工程不仅训练长程任务，也推动plan、压缩、跨session回顾等框架机制发展。

实际做法是构造真正长程的Agent任务并扩大SFT/RL，同时先在公司内部推广模型，从真实使用中发现更多领域，再合成数据。关键难点是还原用户使用环境：环境支持长程交互，也使reward能针对任务状态设置。主持人追问具体实现时，她明确说保密，待规模化后再公开，所以不能补写奖励模型、数据清洗或训练配比。

她还说，当时未必要用一个塞满1M token的任务做后训练，完整长轨迹运行很慢；预训练有长上下文基础、后训练用相应任务“激活”是她描述的路线。80–100 TPS及“一两分钟”的具体口径不清，不能据此推算完整训练吞吐。对于量化因子挖掘，她限定取决于资产：很多资产reward不清、回测缺乏价值，真实结果受长期或模型未覆盖的因素影响，并未给出可交易策略。

主持人观察OpenClaw在中国更热，嘉宾只从自己和身边人的视角给出两种解释：国内用代码提效的需求迫切；便宜好用的模型配合框架，能覆盖许多不需要顶尖模型的任务。她用“85%场景”和“10元API做1000元工作”说明替换系数，均是感受性估算，不是普查或财务核算。

核心判断：Harness 不是“壳”，而是能力分配器

把 Agent 框架理解为模型外的一层 UI，会错过这场访谈的主线。框架决定哪些事实进入上下文、何时检索或遗忘、调用哪个模型和工具、失败后怎样恢复、结果怎样验证、任务怎样分给 subagents。模型参数定义潜在能力，框架把有限计算预算映射到任务路径；最终能力是模型、harness、工具、状态、验证器与成本的联合函数。

进一步推演：六条值得长期跟踪的 Insight

  1. 模型与 harness 会形成协同进化，而不是互相替代。 更强模型能生成更好的 skills 和环境；更好环境又产生更高价值训练轨迹。竞争单位将从单模型变成运行闭环。
  2. Skills 的护城河是失败闭环，不是文件数量。 真正资产是错误被发现、归因、修订、验证和安全发布的速度。
  3. 长上下文的经济学会反向塑造模型架构。 Agent 轨迹越长，训练和 serving 越受 KV、Attention 与 speculative decoding 支配，效率不再是部署后优化，而是能力扩张条件。
  4. Post-training 的稀缺品将从 GPU 迁移到 evaluator。 算力可以买，真实且不易 reward hack 的环境更难规模化；拥有任务与反馈的一方可能比拥有更多通用语料的一方更有优势。
  5. 多 Agent 的第一阶段是并行计算，第二阶段才是制度设计。 角色分工、冲突处理、权限与证据合并，实际上在重演组织科学问题。
  6. 扁平组织与 Agent 系统一样需要可观察控制面。 不显式记录决策权、资源和回滚，表面自由会变成难审计的隐性路由。
