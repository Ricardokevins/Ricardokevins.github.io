从 AI Coding 工作流质变到 Clawdbot：黄东旭谈 Agent 工程、Box 组织与创造的主体性

本期背景与内容导览

本期 42 章经由曲凯对谈 PingCAP 联合创始人、CTO 黄东旭，围绕 Clawdbot（本期时已更名 OpenClaw）、Claude Code、Cowork、Skills 与 AI Coding 的工作流变化展开。黄东旭的核心一手观察是：当模型长上下文利用、agentic loop 和 context engineering 同时改善，部分编程任务从“AI 写大部分、人收尾”变成“人定义目标和验收、Agent 连续执行”。他把这种主观临界感称作奇点，并给出 10 万行项目、每天近 billion token 等个人尺度；这些是重度用户体验，不是统一工程测评。 对话将 Clawdbot 解释为本地优先、能控制完整计算环境的 Coding Agent：缺少专用工具时可操作浏览器或写代码补能力，成功后把流程保存成 Skill。定时邮件与 LinkedIn、Whisper 语音转写、自制博客发布和 AI 论坛学习构成具体案例。它们支持运行时能力扩展，不证明模型权重、目标或安全边界已自主演化；完全权限、记忆 bug、云端端口暴露和券商接入也提示了独立风险。 随后话题从工具扩展到组织与个人。黄东旭预测 Coding Agent 内核向设计和有 API 的现实服务外溢，采用瓶颈从能力转向 token ROI、配置与信任；严肃工程仍需 architect 选择方向和触发重构，多 Agent 依靠模块边界并行。Box 构想把 Skill 与可重置环境、上下文绑定，以减少环境污染，但支付和账号变更等外部副作用仍需显式协议与验收。 最后，他把创业机会概括为极致效率和人与人的连接，把个人价值归于审美、造物心流和人际关系。AI 可替代功能型代码或配乐，却不消除主体性艺术、现场连接与亲手创造的意义。全篇最有价值的是从真实工作流到组织设想的连续推理；最需要克制的是把个人强判断、2026 预测和转录疑点写成已验证行业事实。

00:00:19–00:03:17AI Coding跨越“奇点”

  • 近期 AI Coding 的体验发生了什么变化，为什么 Clawdbot 的火可能不只是一个孤立热点？

曲凯从黄东旭近期密集试用 AI 产品、撰写相关文章谈起，引出 Clawdbot；黄东旭当场补充其已更名 OpenClaw，并以“三天连改三次名”说明产品仍处于快速变化期。本文在叙述历史时保留 Clawdbot，在指当前名称时写 OpenClaw，不把它与 Anthropic 的 Claude Code 混为一个产品。

黄东旭说，自己从 2025 年 12 月底开始感到 AI Coding 的终端体验发生飞跃：过去只是“能干活”，如今已能在一些任务上完全放手，且这种能力正在向非编程任务扩展。这里的 offhand 是他的个人使用感受，不是所有项目均无需监督的统一结论。

他把临界点解释为工作流瓶颈的变化：AI 以前也许能写出 90% 的代码，但余下调试仍需要人，整个系统就被人类阻塞；当他感受到需要人介入的地方降到约 0.1%，任务便能连续自动运行。90% 和 0.1% 都是形象化估计，并非本期提供的统计测量。他将这一变化归因于 agentic loop、context engineering 和底层模型共同改进，而不是某个单一产品的突然发明。曲凯则补充，Clawdbot 的走红因而可能具有方向性，而不仅是一个短期热点。

Agentic loopAgent 反复观察环境与历史、规划动作、调用工具或改代码、读取结果并修正的循环。真正闭环还需停止条件和验收，不是无限自动运行。
Context Engineering在模型之外组织 system prompt、代码与文档检索、工具描述、历史状态和压缩，让每一步获得合适信息。它可与 RAG 共存，不等于抛弃检索。
Claude Code 与 Clawdbot / OpenClawClaude Code 是 Anthropic 的编程工具；Clawdbot 是本期讨论、当时已更名 OpenClaw 的另一项目。机器转录大量混写，本稿按语境校正，不能把产品历史合并。
Skill 与 MCP本期的 Skill 主要指以自然语言及配套资源保存可复用流程；MCP 是连接模型与外部工具／数据的结构化协议。两者可在系统中共存，组合性、权限、依赖和工具选择需分别评估。

00:03:18–00:06:48从不及格到90分：AI编程能力评估与“禁止人类写代码”

  • 过去一年 AI Coding 从多少分涨到多少分，各分数对应怎样的任务范围？
  • 任初安所说的“禁止人类写代码”，黄东旭在自己的项目中如何实践？

黄东旭用主观分数描述能力跃迁：年初不及格，指生成代码大概率有幻觉或错误；60 分指能做好局部小任务；80 分指能在大模块中自行组织和设计架构，但设计质量未必理想；90 分指复杂项目中能较好设计、减少 bug 并仔细 review 细节。这些分数不是标准化 benchmark，价值在于区分任务范围和人的介入方式。

他进一步给出很强的个人判断：对 10 万行代码以内的项目，只要人能提出需求并验证结果，AI 的输出会比 senior engineer 团队更好、更快。这里“只要你能验证”是决定性前提，代码行数也不能代表需求清晰度、遗留系统复杂度、数据迁移、安全性和线上可靠性；本期没有展示跨团队对照实验。

曲凯转述任初安团队默认 AI 先写、绝大多数代码由 AI 生成，并以半开玩笑的口吻说“未来禁止人类写代码”。黄东旭认同，把自己的实践分为两种：把手写代码当艺术品，或在生产任务中完全交给 AI，避免人手修改破坏其上下文。他在自己的项目里规定“不允许人类提交代码”。

黄东旭还称，个人一天 token consumption 接近 billion 级，最终产出几万行代码，并把工作量类比为几十人月。数字保留为个人自述：token 含输入、输出和重复上下文的口径未拆分，代码行数与几十人月不等于已验收价值。曲凯另转述 Cowork 团队“100% 代码由 AI 编写”，同样属于第三方公开表达。

话题推进：量化体验之后，曲凯请他为非技术听众梳理 Claude Code、Cowork、Skills 和 Clawdbot 的技术脉络。

00:06:49–00:13:44两条发展主线：模型进步与上下文工程

  • Claude Code、Cowork、Skills、Clawdbot 这些产品怎样串成一条技术演进线？

这一段原转录多次把 Claude Code 误写为 Clawdbot。依据“Anthropic 的编程工具”“2025 年初”“编程场景”以及 shownotes 的章节标题，本稿将该产品线校正为 Claude Code；仍保留黄东旭对其历史作用的个人判断，不把“最早”“开创”当成行业唯一史实。

黄东旭认为 Claude Code 把语言模型与外部工具放进同一 agent 框架，先从相对可控的编程任务切入，使模型能读写代码、调用工具并影响实际环境。他由此提出更强的猜想：general agent 的基础可能仍是 coding agent，因为面对缺少专门工具的任务，Agent 可以现场写程序补足能力。这是技术路线判断，不意味着所有非编程问题都能仅靠代码解决。

第一条进步线是长上下文的信息召回：在整个代码库或长历史中找到与当前问题相关的位置。黄东旭称，GPT-5.1 thinking 在某类相关 benchmark 上召回率约百分之二三十至三四十，而 GPT-5.2 接近 90%。节目没有给出 benchmark 名称、上下文长度、评分和推理预算，故只能作为嘉宾转述，不能外推为所有长上下文任务。召回率也不能独立代表代码正确率，但多轮 agent 中反复漏掉历史信息会加剧状态错误。

第二条线是 context engineering：在模型不变时，通过 system prompt、工具描述、检索和上下文编排改善表现。黄东旭认为 RAG 一词热度下降，是因为社区逐渐积累更好的 tool use 实践，而不是检索本身消失。最佳实践在 X 和开源工具中迅速扩散；转录的“raffle loop”无法确定专名，本文不猜补。

他以 OpenCode＋Oh My OpenCode 为自己的 ah-ha moment：底层可使用 Opus、Claude Code、GPT-5.2 等能力，外层靠复杂编排取得比未优化原生工具更好的体验。这里的依赖关系按嘉宾原话保留，具体实现需另查项目资料。两条线在 2025 年底叠加后，他认为人的工作更多移向“要什么”和“怎样验收”，即写清需求、plan 和验证条件，而非逐行改代码。

00:13:46–00:19:05Skill优于MCP，Prompt依然重要

  • Cowork 与 Claude Code 的关系是什么，为什么说通用 Agent 可能是 Coding Agent 的套壳？
  • MCP 和 Skill 在可修改性、组合性与工具选择上各有什么限制？
  • 当 prompt 工程师不再热门，需求描述和评价标准为什么仍然重要？

黄东旭认为 Cowork 不是独立的大范式跃迁，而是编程 Agent 向 computer use 外溢：底层让 Agent 通过写代码或直接操作电脑完成任务，可把它理解为 Claude Code 的一种插件式封装。他进一步判断，未来许多 general agent 都可能是“Coding Agent 的套壳”。这里的“套壳”并非没有工程价值，而是核心通用能力来自模型、工具循环和代码生成。

他比较 MCP 与 Skill 时，重点不是网络协议是否标准化，而是能力能否被理解、修改和组合。他认为远程 MCP 常提供较原子的调用，使用者难以按自己的环境修改；挂得太多还会增加工具选择负担。Skill 以自然语言描述可复用流程，对大模型与人更友好，能把简单技能组合成复杂流程，甚至由 Agent 现场写出。因此他个人更看好 Skill。

这是一种有立场的简化比较，不能据此推出 MCP 必然过时或 Skill 天然可靠。MCP 可以提供结构化、权限明确的连接，Skill 也可能相互冲突、含恶意指令或依赖特定环境。原稿把 MCP 的选择困难称为“灾难性遗忘”，更准确的本文表述应是工具选择与上下文干扰，不把它直接等同于神经网络训练中的灾难性遗忘。

对 prompt，黄东旭与曲凯的“已经不重要”印象不同：他认为 prompt 仍重要，只是从事无巨细的奇怪技巧，转为需求、设计文档、计划和评价标准。过度 detail 可能限制 Agent 探索，但目标与验收模糊又会使结果不可用。因而问题不是“还要不要 prompt”，而是哪些内容应明确、哪些实现选择应留给 Agent。

00:19:06–00:25:39Clawdbot是什么：一个本地优先、拥有完全权限的套壳Coding Bot

  • Clawdbot 到底是什么，为什么需要完整的电脑控制权限？
  • 本地、树莓派和云端运行有什么本质区别，各自有什么安全风险？
  • 它与 Manus 的 E2B＋Browser Use 方案相比，差异主要在技术还是分发与使用环境？

黄东旭把 Clawdbot 定义为运行在用户电脑上的全能助手：用户用自然语言下指令，它通过浏览器、工具或现场生成代码完成原本需要鼠标键盘的操作。查邮件的例子说明其回退路径：若没有邮件 API，可打开浏览器并请求账号密码登录。这也说明“能完成”与“应当授予多少权限”必须同时考虑，凭证和邮件内容都进入高风险操作面。

Mac mini、树莓派或云服务并非本质区别。关键是 Agent 是否有一个可完整控制、便于隔离和接管的运行环境。黄东旭将底层理解为接近 Claude Code 的 Coding Agent，去掉部分确认与权限限制；local first、内置常用 Skill、开源及记忆模块共同塑造体验。原稿“完全权限”描述的是使用方式，不应被理解成安全推荐。

本地环境出现异常时可拔网线或关机，云端若误开公网端口则可能成为攻击入口。他用“为完成任务下载 Redis 却错误暴露端口”说明自动化配置的风险；这是风险示例，不是已发生事故。完整隔离还涉及文件系统、凭据、网络、支付、人工接管和日志，而非只买一台单独电脑。

与 Manus＋E2B／Browser Use 等方案相比，黄东旭认为底层思路差别不大，走红更多来自开源、local first、预置 Skill 和极客传播；对 C 端最直观的是能控制自己的电脑。曲凯提到 GitHub 十几万 Star 是录制时的粗略观察，未作独立核验。黄东旭还提出一个未来操作系统猜想：聪明 Coding Agent 是内核，Skills 在其上，语音或 Chatbot 是人际交互层。他把 memory 看作重要体验，但明确说当前系统仍稚嫩且有很多 bug，不能写成已经“永不忘事”。

00:25:40–00:32:59Clawdbot的真实用例与“自我演化”的潜力

  • 哪些灵活、长期、定时任务值得 Clawdbot 24 小时运行？
  • 它怎样通过写代码补足语音转写能力，又怎样把发布博客固化为 Skill？
  • AI 论坛里的技巧分享是否足以证明自主进化，黄东旭的新项目已经取得什么结果？

黄东旭的第一类真实用例是灵活、长期的 routine：每两小时检查 Gmail，删除垃圾邮件、找出需回复内容并拟好草稿；在签证等表格中利用 LinkedIn profile 填入学业和工作信息；定期检查 LinkedIn 好友申请，按“过滤纯推销、保留靠谱朋友”的个人规则处理。这里仍保留“他看过大差不差再发出”的人工验收，不能改写成完全无人审核。

第二类是接入个人工作流。他提到自己把 bot 接入美股券商和 Polymarket，并明确“说起来不推荐大家干”。这只能作为高风险个人实验，不能当成投资建议、稳定收益证明或通用最佳实践。长期记忆帮助把三分钟热度变成持续 routine，但其可靠性仍需失败记录验证。

语音例子展示了能力补缺：Clawdbot 原本没有 Telegram 音频转写功能，黄东旭直接发语音后，它为理解指令写程序调用 OpenAI Whisper，获得 transcript 再回答。博客例子则是它从 GitHub 下载并理解黄东旭自制博客系统，成功发文，再把流程写成新 Skill 供下次复用。这两个案例支持“运行时生成工具＋保存流程”的能力扩展，不等同于模型权重自主训练、目标改变或无需人类监督的自我进化。

他把这种机制延伸到转录所称 Modbook 的 AI 社交实验：不同用户的 bot 在 TIL（Today I Learned）板块分享技巧，他的 bot 在其睡觉时读取并用来改工作流。关于论坛中“建立不被人类看到的通信方式”，黄东旭反而认为实际内容更像写科幻小说，不应直接当作已形成隐蔽协作能力的证据。

独立判断：这些对话改变了什么理解

【本文推断】本期所谓“奇点”更适合理解为工作流交接点的变化，而非模型已普遍超过资深工程团队。

推理：当任务可自动验证、环境可控且模型能连续修复错误时，人的位置可从逐行编辑转为规格、架构和验收。变化发生在整个系统，不能仅由模型分数解释。这也说明为什么 OpenCode 编排、权限环境和长上下文历史会同时影响体验。

竞争解释与边界：模糊需求、跨系统变更、隐性业务约束和线上事故仍难形式化；代码量与生成速度可能增加审查债务。若把这些成本算入，人工混合编辑在某些场景仍更优，不能将“禁止人写代码”普遍化。

【本文推断】Clawdbot 的能力扩展值得重视，但“自主改目标”不是判断自我演化的必要条件；真正需要分层衡量学习发生在哪。

推理：生成新工具、保存 Skill、读取外部经验都可构成系统能力增长，无需先讨论意识。应区分：一次任务中的临时代码、跨任务 Skill 复用、模型参数训练、以及目标与权限自主变化。黄东旭案例主要支持前两层，AI 论坛提供第三层外部知识传播，均不等于第四层。

竞争解释与边界：如果 Skill 可在新任务稳定复用、经独立测试证明成功率提高，这将比“自我进化”口号更有证据。反之，未审核经验可能传播错误和恶意操作，权限与评估必须先于自动扩张。

【本文推断】Box 与组织设想的共同核心是把高速生成转化为可验收工程，而非消除协作。

推理：Box 通过环境和状态接口减少副作用，模块所有权通过边界减少代码冲突，architect 通过方向和重构处理全局一致性。三者都把不可控的自由操作变成可测试协议。关键研究对象因此是状态、契约、验证和恢复，而不只是怎样让更多 Agent 同时写代码。

竞争解释与边界：过度隔离会重复环境、丢失必要共享状态并推迟集成冲突；登录、支付等动作也不能完全回滚。若模型未来能稳定理解大型共享代码库和协调变更，完全隔离的必要性可能下降。

【本文推断】“极致效率／极致人文”更接近资源配置提醒，而不是创业机会只剩两类。

推理：当软件生成本身变便宜，纯实现更难形成差异；理解特定人群、拥有关系和分发、承担真实责任，或把高价值流程大幅提效，都可能成为价值来源。黄东旭对音乐和 builder 的讨论又补充了主体性和过程价值，使后半期不只是技术替代叙事。

竞争解释与边界：大量优秀产品本就同时提高效率并改善人的体验，中间地带未必没有价值。企业改造还需要数据迁移、合规、培训和维护，一人外包能否承担长期责任需实证。
