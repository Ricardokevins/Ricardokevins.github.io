Gemini 3 的系统性翻盘、Agent 模型能力与 RL 创业：前 Google 创业者和硅谷投资人的一线观察

本期背景与内容导览

本期第 146 集（2025-12-26）由程曼祺主持，MoE Capital 的 Henry Yin、Naomi Xia 与 Precur 联创戴涵俊、Bethany Wang 共同讨论 Gemini 3、GPT-5.2、Agent 模型能力和 RL 创业。四位嘉宾同时具有前 Google 研究与产品、早期投资、被投创业团队等身份，因此本期适合作为一线观察和技术路线自述阅读，不应替代原始模型报告、客户数据或独立投资尽调。 对话从 Gemini 3 的高声量开始，解释 Google 可能的翻盘条件：预训练仍有迭代空间；TPU、XLA／JAX 和训练 infra 可协同优化；Workspace、Agent 应用和多种终端提供场景与潜在数据反馈；Brain 与 DeepMind 合并在磨合后集中研究方向；Google Labs 又把编辑、创作者和产品传播纳入模型应用。这里的“全面 SOTA”“数据反哺”和 TPU 优势均为嘉宾判断，具体效果取决于模型、规模、数据权限与组织执行。 在 Agent 创业上，嘉宾没有把模型和应用写成简单替代。通用工具交互可能被基础模型内化，企业专有流程、私有数据、云约束和具体延迟／质量需求仍留下空间；成功 Agent 场景也会反向塑造模型训练。Precur 选择“可训练工具层”，希望保存失败轨迹，用 RL、代码和状态管理改善工具，但自动归因、可靠奖励、稳定更新和效果验证仍是未解环节。早期客户“好约 12%”缺少指标口径与样本信息，只能作为团队自述。 RL 创业被分为环境、即服务和垂直应用：Jira 复制品说明原型构建成本下降，网络安全环境体现领域与奖励设计壁垒，Tinker 则代表仍需专业用户的底层训练 primitive。企业选模型往往先看数据所在云和折扣，再看 coding、Agent 生态、token 效率与延迟。最后，嘉宾期待含高质量 agent trace 的开源基座、更强多模态和原生长程能力；“模型内化旧功能”与“新能力创造增量市场”谁更快，是本期留下的核心商业悬念。

主持人连续追问软件栈，目的是弄清 CUDA 护城河是否会被复制。嘉宾解释 PyTorch、JAX 可通过 XLA 等底层支持使用 TPU，vLLM、SGLang 也在降低部署感知；JAX 在 Google 更原生，但框架与硬件并非一一绑定。原分析把 Flax 误写成 Flex、把 Optax 误写成“存权重”，本稿纠正为神经网络框架和优化器库。其他听不清的底层库名不猜补。

推理：TPU、模型、应用和终端分别只是资源。真正的因果步骤应是：真实场景暴露失败→形成可训练数据或系统需求→模型和 infra 改进→产品再次验证。Brain／DeepMind 合并说明，资产集中初期反而可能增加 infra 和政治成本；只有当评价指标和交付方向明确时，规模才变成速度。这个视角也适用于其他大厂。

【本文推断】“可训练工具”的最大技术门槛不是保存失败，而是判断谁该为失败负责，并证明更新没有引入新问题。

推理：多步任务失败可能来自错误目标、错误工具参数、工具自身缺陷、环境变化或评分器误判。若直接把最终失败作为整个工具的负奖励，可能惩罚正确步骤或学到投机行为。早期产品更适合从可验证错误切入，如返回格式、超时、覆盖遗漏和确定性单元测试，再逐渐进入质量模糊的任务。

竞争解释与边界：Precur 可能通过限定工具边界、代码执行断言和客户私有评价降低归因难度；早期 12% 自述提示有潜在价值，但不足以判断通用自我演化已成立。更强基础模型也可能吸收部分功能，工具层需靠企业状态、可验证更新和集成成本形成独立价值。

【本文推断】RL 环境创业的关键供给不是“更多轨迹”，而是可迁移、难投机且能区分策略的评价。

推理：Jira 原型可在一个周末复制，说明界面搭建不再稀缺；但若成功判据只看最终页面文字，Agent 可能直接改数据库或绕过流程。网络安全、零售和自动驾驶例子的共同难点是：环境是否覆盖真实约束、奖励是否对应实际目标、训练后能否跨环境工作。环境数量和训练时长不能替代这些证据。

竞争解释与边界：简单环境仍可作为早期教学和回归测试，不必追求一次做到完整真实。随着模型能力增强，动态任务生成和隐藏测试可能提高区分度；但若环境本身由弱模型生成，错误也会进入反馈，需要独立验收。

【本文推断】“生态优先”实际上改变了 Agent 创业的竞争单位：比较的是完整交付系统的每个成功任务成本，而不是模型名单。

推理：云、credit、模型、工具、parser、上下文和延迟共同决定结果。强模型若不在客户云里，可能根本不在候选集；较小模型若调用更少、延迟更低，也可能在单位成功成本上胜出。工具层的商业机会因此不只是补模型智力，而是减少系统摩擦并保留企业已有投资。

竞争解释与边界：生态优势会随云目录、价格、监管和模型代差变化。若某模型能力出现数量级领先，企业可能重构数据或采用新架构；若平台把同样工具原生集成，第三方工具层则会被压价，需用独立效果和跨平台可迁移性证明价值。

尚未解决的问题与可检验的下一步

待解问题：可训练工具如何把最终失败归因到具体工具或步骤，并避免在线更新破坏旧能力？

下一步信息或小实验：【本文建议】在同一任务集设置工具错误、模型参数错误、环境变化和评分器错误四类可控故障；比较人工标注归因、规则归因和学习归因。每次更新同时在旧任务回归集与新故障集验收，记录恢复时间和回滚率。

怎样的结果会改变判断：若系统能稳定定位原因、只在相应测试改善且旧能力不回退，才支持“自动从失败学习”。若更新只提高表面指标、真实任务反而退化，则说明反馈或归因尚不可靠。

待解问题：早期客户约 12% 的改善究竟是什么指标，能否在不同客户和任务复现？

下一步信息或小实验：【本文建议】取得任务定义、样本量、现有基线、模型版本、绝对分数、方差、延迟和每个成功任务成本；区分百分点与相对百分比，并保留客户未告知优化细节的盲测。

怎样的结果会改变判断：若多客户、预先固定的盲测都有一致改善且总成本下降，产品价值显著增强；若只在单一数据集或更换基线后消失，则不能把 12% 当作普遍能力。

待解问题：RL 环境训练的能力能否迁移到真实企业软件和未见异常，而不是只学会环境漏洞？

下一步信息或小实验：【本文建议】在 Jira 类环境保留未见页面、权限错误、网络重试和字段歧义，分别测试专家示范、RL 训练及仅用更强基础模型的方案，再在不调参的真实沙箱复测。

怎样的结果会改变判断：若 RL 在真实沙箱和异常上仍优于同预算基线，才支持环境价值；若只在训练环境提升，说明可能过拟合或奖励投机。

待解问题：模型内化 Agent 功能后，新增市场是否真的大于被替代的旧市场？

下一步信息或小实验：【本文建议】按同一批企业跟踪模型升级前后的任务覆盖、人工接管、留存、价格和新增用例，区分“旧功能被平台免费吸收”与“过去做不起的新流程变得可行”。

怎样的结果会改变判断：若新增收入和活跃任务持续超过旧功能流失，支持 Naomi 的增量判断；若平台整合后独立 Agent 的留存和定价同步下降，则需要下修该判断。
