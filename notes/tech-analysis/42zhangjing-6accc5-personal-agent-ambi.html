莫子皓谈 Personal Agent：把智能带到现场，而不只是放进一个更聪明的聊天框

本期背景与内容导览

曲凯与 Ambi 创始人莫子皓讨论 Personal Agent，重点不是“哪个模型最聪明”，而是普通人为什么愿意让智能持续参与生活。对话先从近期产品与模型能力的变化说起：莫子皓认为，新模型在长程、模糊任务上的进步改变了他的预期，但普通人是否使用，还取决于安装、配置和每次解释需求的成本。随后话题进入 Personal Agent 的需求与商业模式：他主张降低“获取智能的交互成本”，用 Agent 之间在授权下的协作形成新的价值，并比较 To C、To B 和硬件渠道的差别。中场他点评几款产品，解释 Ambi 为什么强调线下 context、持续在场和软硬件结合，而不是只做一个异步执行任务的聊天框。后半段回到他自己的创业经历：溜冰场门票分销、保险用户路径、销售激励和人才招募，用来说明识别需求、设计交付与激励的方式。最后他提出“AI 是主体的延伸”、主动服务应该由环境变化触发，以及 AI 的增量价值在屏幕之外的并行工作。所有市场判断、融资观察和成功率预测都按录制时观点保留，本文另行讨论其成立条件。

主持人曲凯首先询问嘉宾莫子皓，其创办的Ambi是否从一开始就定位为Personal Agent。莫子皓确认，尽管团队并未主动使用这个标签，但其初始技术架构（为每个用户设一个虚拟机环境）和改变人与AI交互方式的初衷，都与Personal Agent的方向一致。他提到，创业的愿景是让AI像水电煤一样普及，而非局限于少数场景，做一个能被大多数人使用的产品。

随后，曲凯将话题转向近期Personal Agent概念的火热，并追溯其发展脉络：从早期的AI做事概念，到主持人提到的早期产品，再到 OpenClaw，最终与AI Coding等方向融合。他询问这波热潮与之前的区别，以及是否只是昙花一现。

莫子皓认为，这波热潮并非“诈骗”，而是满足了许多产品经理看到的趋势，具备持续火爆的潜力。他以Muse和Grok为例，指出这类产品降低了使用门槛，普通用户无需技术背景即可轻松上手，体验类似成熟的互联网应用。他进一步解释，Openclaw虽然曾引发关注，但存在两个核心问题：首先，它虽然强大，但缺乏明确的应用场景和价值点；其次，普通用户要获得并配置这种能力的链条过长，安装和设置成本极高，这更多是产品和传播问题，而非技术问题。

莫子皓分享了自己从年初开始持续使用和迭代Hermes（替代Openclaw）的经验，结合代码与工具环境，将其应用于工作、生活、健康等多个方面，并设置定时和主动性任务。他强调，随着模型（如从5.6升级到6）的不断进步，系统的价值感和能力都得到了巨大提升。因此，他总结道，Personal Agent的火热是产品体验优化和模型能力增强共同推动的结果，使其越来越接近成为一个大众化产品。

Personal Agent在本对话中，指一种能代表个人、在数字世界中自主执行任务的AI程序。它不仅仅是问答工具，而是被赋予了用户的个人数据（如记忆、文件、偏好），并能在虚拟机等环境中模拟人的操作（如点击、输入），主动或被动地为用户完成订票、处理邮件、信息整理等一系列复杂任务。
Hermes在这里指一个开源的Agent框架或系统。嘉宾提到用它替代了Openclaw，并结合Codec（可能指代码生成或执行能力）来构建自己的个人AI系统，用于处理工作、生活、健康等方面的任务。
Computer Use指AI模型直接理解和操作图形用户界面（GUI）的能力。输入是屏幕截图或视觉信息，输出是模拟人类的鼠标点击、滚动、键盘输入等操作指令，从而让AI能够使用任何软件或网站，即使没有专门的API接口。
Harness / System PromptHarness 是模型外部的任务执行环境：它向模型提供指令、历史上下文和工具，接收模型输出后调用代码、浏览器或其他工具，再把结果带回下一步。System Prompt 是其中的行为指令。嘉宾说模型升级后要“剪一层”Harness，指减少不再需要的约束和补偿逻辑，而不是只缩短一句提示词。

主持人曲凯提起一年前与嘉宾的讨论，当时普遍认为“智能已经足够了”。他询问，近半年的新模型是否改变了这一看法。

莫子皓修正了自己去年的观点，认为当时觉得“智能足够”是因为设计的任务不够复杂，给模型的上下文（context）不够丰富和多元，视野受到了局限，主要停留在聊天场景。他指出，在更复杂的工作场景中，新模型的提升是巨大的。他以GPT-6 级模型发布时的亲身经历为例：在调整完自己的Harness和System Prompt以适配新模型后，他发现对于处理公司内部Lark、GitHub、Figma等平台上的长程、模糊任务（如“某个功能与最初设计有何偏离”），新模型（GPT-6）的输出质量有肉眼可见的巨大提升。具体表现为，输出内容更精简，但表达更精确，甚至能总结出人类自己都想不到的洞见。这次经历让他感到“aha moment”，并意识到人类对智能的需求上限非常高。

接着，曲凯询问嘉宾对“Computer Use”（计算机使用）能力的看法，指出该能力在模型厂商内部评价很高，但在外部感知较弱。莫子皓回应，他们将Computer Use视为模型自身能力演进的明确方向。他解释了团队的产品哲学：要么利用技术优势创造当前模型“刚刚好能做到”的惊艳体验，要么避免投入过多精力去实现那些模型在3-6个月后就能天然具备的能力。Computer Use属于后者。尽管目前可能还存在速度慢、需要反复尝试等问题，但这些都会随着模型迭代而改善。因此，Ambi团队选择乐观关注，但不会在当前阶段投入资源去调优这些corner case，而是将其当作未来可以直接利用的基础能力。

00:10:07–00:15:33Personal Agent的成本与需求：交互成本决定需求真伪

主持人曲凯提出，尽管模型能力在提升，但供给侧仍面临两大问题。首先是成本，他询问Personal Agent产品是否非常烧钱。

莫子皓认为成本不是大问题。他观察到，在当前这波热潮中，用户并不关心背后用了什么模型。对于订餐厅、订票这类任务，用户对延迟不敏感，更看重成功率和质量。这意味着在速度上可以做一些权衡（trade-off）。他表示，Ambi的原则是不因成本阉割用户体验，而目前的模型价格与智能交付的价值之间，已经可以找到一个商业上成立的平衡点。

接着，曲凯转向需求侧，质疑个人用户在工作场景之外，是否有足够高频的需求。莫子皓提出了一个核心观点：需求的强度取决于“获取智能的交互成本”。如果用户能像说话一样轻松地调用AI，那么许多“鸡毛蒜皮”的生活小事都会变成真实需求。但现状是，用户需要经过复杂的设置和交互才能使用，高昂的“行为成本”抑制了生活场景中的需求。他用“增程汽车”类比：人们可能一年也用不到一次增程，但为了避免那一次的“痛”而愿意买单。同理，如果能随时随地低成本获取智能，用户自然会高频使用。

莫子皓举例，一个同事在新疆自驾时，突然需要改酒店、找加油站和修车厂，这时对Agent的需求就变得非常强烈。他认为，简单地将人的需求划分为工作和生活是过于简化的，真实需求与时间、场景、环境都相关，而这一切都建立在“获取智能的成本是多少”这个前提之上。

最后，曲凯追问，既然如此，Muse这类产品的终局是否就是被ChatGPT等大平台整合。莫子皓表示同意，认为这些产品验证了个人生活场景中与“名和利”相关的需求是真实存在的，因为其ROI（投资回报率）可以被明确计算。一旦某个切入点被验证，所有玩家都会跟进。他透露，无论是OpenAI还是字节跳动，都在开发类似的产品，这是一个显而易见的趋势。

主持人曲凯询问嘉宾对不同AI Agent产品路线的看法，包括个人Agent和团队协作型的AI Coworker。

莫子皓认为，这些路线都有可能成功，就像不同组织架构（民企、外企、私企）的公司都能成功一样。他以桥水基金的极端透明为例，说明不存在唯一的正确模式。他指出，AI Coworker发展缓慢的根本原因在于，将其应用于现有组织会触及复杂的组织变革问题，其效率会被组织中最慢的一环限制。他引用“电发明后，按电力逻辑重建工厂需要30年”的例子，认为只有当新一代AI Native公司成长起来，才会完成对旧模式的淘汰。从逻辑上看，拥有更高效率、人才密度和知识复利的新型公司，假以时日必将取代旧公司，届时AI Coworker的市场才会真正扩大。

基于此，曲凯推断，面向个人的Agent更容易起步。莫子皓表示赞同，并犀利地指出，许多创业者“看硅谷看多了，有点魔怔了”，忘记了“能做To C谁做To B”的基本逻辑。他认为，美国公司之所以转向To B，是因为在移动互联网时代，To C市场已被巨头占据，渗透率高，网络效应强。但在AI这个新时代，不应再走老路。

针对To C市场赢家通吃的担忧，莫子皓认为，这主要取决于获客渠道是否依赖于有强网络效应的上游平台。如果依赖，创业公司就很难独立成长为巨头。他特别提到中国市场，直言由于分发渠道被巨头掌控，创业公司的成本被严格控制，创造力受到压榨，因此在中国做Personal Agent几乎没有机会。他将讨论范围限定在海外市场，认为通过硬件等线下渠道，仍有机会绕开巨头的封锁。

最后，莫子皓总结，他认可在中国市场，Personal Agent的机会属于拥有分发渠道的巨头，但在全球市场，创业公司仍有机会。

00:21:11–00:25:57Personal Agent的壁垒：网络效应体现在Agent之间

  • Personal Agent这个名字听起来天然不带网络效应，它要如何构建壁垒？
  • 能否具体分析一下Town、Grok Bot、Muse、Instinct等几款产品的特点和路线？

主持人曲凯提出一个疑问：Personal Agent这个概念听起来很“个人”，似乎天然不具备网络效应，那么它该如何构建壁垒？

莫子皓反驳了这一观点，他认为Agent之间（A2A, Agent-to-Agent）的交互是构建网络效应的关键。他解释，网络效应的核心在于用户间的连接能否为彼此带来正向价值。在Personal Agent的场景中，每个Agent都沉淀了其主人的记忆（memory）、文件系统（file system）和知识。当人与人需要沟通时，本质上是想获取对方的知识和时间。因此，如果一个用户的Agent可以与另一个用户的Agent进行交互，共享彼此的“个人数据”，就能为双方带来巨大帮助。他强调了因果关系：“不是因为可以A2A，所以才用你的产品；而是因为用了你的产品，沉淀了数据，才使得A2A成为可能并产生价值。”这与iPhone的逻辑类似，先有大量用户，再建立App Store生态。

为了证明A2A的实用性，莫子皓分享了自己公司内部的实践。他会将自己的Hermes Agent（以Lark Bot形式存在）拉入一些工作群。同事们可以直接@这个Bot，向它请教问题或审阅稿件，相当于在特定权限下调用了莫子皓的“知识库”。莫子皓本人在群里只起到一个权限监督的作用。他认为，这天然就是一个A2A协作的场景，证明了其可行性和价值。

随后，曲凯请嘉宾简评几款具体的Personal Agent产品。莫子皓首先分析了Town。他认为Town带有浓厚的金融科技背景（其CEO来自Plaid），因此产品设计极其注重权限（permission）和引用（reference），这使其天然适合处理邮件等To B场景。Town通过自动为邮件打标签、分类、写草稿等功能，精准满足了一部分特定人群（如需要处理大量学校通知的家长）的需求。然而，莫子皓也指出了Town的几个问题：首先，其产品信息架构复杂，不如“中国人做得好”；其次，它对智能的利用程度不高，过于聚焦在“回邮件”这个点上，而这并非在模型能力持续增长的延长线上。因此，他个人不看好Town的长远发展。

首先是Grok Bot。嘉宾认为这是一款非常好的产品，尤其在授权和透传方面做得很好。他解释，有些接口无法直接连接bot，Grok Bot会为此启动一个浏览器，让用户在弹窗中输入邮件和密码，这种有大厂（Cursor团队）背书的方式让普通用户感觉更安全。此外，它在bot之间的通信和上下文共享（context share）方面也做得比较出色。由于是Cursor的增长负责人主导，产品在传播方式和一些细节上处理得很好。

01:04:56–01:08:55硬件的三重优势：渠道、独占性与反直觉的用户体验逻辑
