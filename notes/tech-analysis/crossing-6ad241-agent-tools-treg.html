Treg：三次转型后，怎样在 Coding Agent 生态中找到产品位置

从设计 Agent、自动增长到数据和工具市场，一个小团队如何用真实运营检验“零人公司”，又怎样处理多 Agent 协作的新瓶颈？

完整对话脉络 · 机制与算例 · 独立判断 · 证据边界

完整对话脉络：九个月三次转型，与 Claude Code / Codex 周围长出的新生态

嘉宾 · Jason ZhouTreg 创始人，1993 年生（33 岁），重度 INTJ，处女座。本科毕业于重庆大学热能与动力工程专业，后赴澳大利亚攻读交互设计；创业前在澳洲 AI 创业公司 Relevance AI 负责产品与 AI 团队（三年多前即开始做全自动销售与 SDR），同时运营个人 YouTube 频道，2025 年底辞职创业。
嘉宾 · 石天鑫Treg 创始工程师（Founding Engineer），1994 年生（32 岁），INTP（自称比 Jason 更内向），白羊座。本科毕业于成都电子科技大学嵌入式系统专业；曾在苹果中国实习任测试工程师半年多，随后转向互联网，在阿里巴巴与字节跳动深耕前端开发 10 年。
公司与定位仅 4 人的小团队，创业 9 个多月经历三次转型：设计 Agent SuperDesign → 全自动增长 Agent Crewlet → 如今的 Treg（第三方转写多作 Trig，官方资料写作 Treg）。一句话定义：「面向数据和工具的 OpenRouter」——给 Agent 使用的数据与 API 市场，只需一个 Key 即可按量调用各类外部数据与工具，无需逐家购买月度订阅。

1. 第一与第二次转型：SuperDesign 的开源红利、模型吞噬应用与「零人公司」幻觉

Koji 开场点出整期核心追问：基础模型一路狂飙，Treg 在 9 个多月里接连转型三次，表面像在不断试错，实则是在替绝大多数 AI 应用创业者回答同一个生死问题——当通用模型与 Coding Agent 越来越强，独立应用公司还能在哪一层创造不可替代的价值？

第一站：SuperDesign（设计 Agent）。最初只是 Jason 的一个周末项目——他运营 YouTube 频道时发现 UI 设计类内容流量极高，便做了一款 IDE 插件（当时 Cursor 是最火的编程工具），用户一句描述就能生成三四个前端或海报设计版本供挑选。项目开源后，完全靠自然增长在几个月内斩获 6,000+ GitHub Star，让他深切体会到「开源是 AI 产品极强的营销杠杆」。

可正式辞职创业后，他们做的第一件事反而是放弃了开源 IDE 插件，转做独立网页版。回看背后有两重误判：一是当时看不清 IDE 插件如何收费；二是觉得绑定 Cursor、Claude Code 或 Codex 会限制人群，网页版才能触达大众——谁料随后一年，大批用户反倒一窝蜂涌进了 Codex 和 Claude Code。更致命的外部冲击随之降临：从 Gemini 3 开始，各家基模猛卷前端生成能力，倒逼 OpenAI 与 Anthropic 紧急补齐前端短板；与此同时，Claude Code 加上开源社区热门的前端设计 Skill 已能产出不错效果。经典的「模型吞噬应用」迎面撞来，团队陷入深刻焦虑。

第二站：Crewlet（全自动增长 Agent，2026 年 4 月—6 月）。2026 年 2 月到 6 月是 AI 应用圈极其魔幻的四个月——随着 OpenClaw 爆火，大批优秀创业者押注 AI Employee（AI 员工）与「零人公司」。令 Jason 动心的是 2 月冒出的产品 Posia（当时 ARR 仅十几万美元，后来几个月迅速拉升，体验震撼得堪比当年初用 Cursor）：注册时他没填任何背景，Posia 仅凭 Jason Zhou 这个邮箱就全网搜出他的身份，立刻生成两三个创业点子，挑中一个后瞬间搭好落地页、找客户发 Cold Email（冷启动开发信），而且真有人回复。Koji 也笑谈自己受 Jason 推荐去试用 Posia：系统同样靠邮箱搜出他是播客主，建议他做一个面向播客主的 AI 后台，他一时冲动充值几百美元开了 God Mode（上帝模式），结果「没帮我赚到钱，只帮我花了钱」。

等团队照着「服务真实已有企业、帮他们自动化规模化获客」的思路做出 Crewlet——把 SEO（搜索引擎优化）、内容营销、社交媒体与广告自动调预算全塞进去，甚至产品未完工先挂付费墙就收到了不少预购——真正上手交付结果时却狠狠撞墙。Jason 事后彻底看穿了 Posia 的巧妙之处：它嘴上卖的是「AI 掌管全公司」的宏大愿景，真正做到极致丝滑的只是「从 0 到 1 搭出网站和业务壳子」，并不接入真实企业的内部系统、产品分析或广告后台；可一旦真正背上「交付持续增长」的 KPI，难度瞬间飙升：

  • 工具分散与数据失真：营销相关数据源高度碎片化，Agent 拿到的信息未必准确。
  • 营销没有静态万能公式：真正有效的增长渠道往往是少数人发现、持续加码才跑出来的；一旦全行业都在用，红利立刻失效。Jason 举了个极具体的 SEO 例子：常规 Agent 会筛选「当前搜索量较高、竞争看似不激烈」的关键词去写内容，实操却发现这类好词早被老玩家抢空；真正有机会的，是当下流量不起眼、但能敏锐预判未来 1—3 个月即将爆发的新兴词——这种动态前瞻极难交给 Agent 独立完成。

2. 停工两个月做真实实验，与一个「改名 01」的 Codex 插件转折

Crewlet 做了个把月难交付结果，Jason 猛然刹车：团队是不是因为体验了 OpenClaw 和 Posia 就预设「零人公司一定是未来、模型 6 个月内一定够强」，步子迈得太大？他们做出一个艰难却极具回报的决定——暂停所有新产品开发两个月，拿仍有自然流量和转化漏斗优化空间的旧产品 SuperDesign（Jason 形容它「放到 Acquire.com 上肯定有人买」）做小白鼠，丢掉一切历史包袱，全员试用市面上最好的工具验证「AI 全自动运营公司」究竟行不行。

折腾两个月、搭出各式自动化循环（Loop）后，团队得出了后来指引一切决策的两大确定性判断：

  1. 未来 6—12 个月，「零人公司」不成立：客服与简单修 Bug 确实可以全自动，但业务增长需要密集的人类介入、测试与判断，当下真正值得解决的是人与 Agent 深度协作。
  2. 放弃自建 Harness，全面拥抱 Claude Code 与 Codex 生态：此前做 SuperDesign 和 Crewlet 时他们都自己搭了 Agent 运行框架（Harness）；卸下包袱直接用 Claude Code 和 Codex 后，发现体验远超自家写的框架。

就在这期间做了无数增长实验毫无起色时，一个意外转折改变了曲线：石天鑫顺手把 SuperDesign 原有的 CLI（命令行工具）和 Skill 发布到了刚起步的 Codex 插件市场，团队一分钱没花、零宣传，用户竟然成群涌入，且留存明显更高（流失率更低）。石天鑫还揭秘了一个令人莞尔的早期小插曲：他发现当时插件市场竟然按字母顺序排列，于是灵机一动把插件名从 Super Design 改成 01 Super Design，瞬间霸榜第一；尽管平台几天后就修改了排序规则，那几天的免费曝光却帮他们完成了关键冷启动。由此他悟出一条创业经验：新兴早期生态与分发市场永远值得第一时间试水。

3. Treg 诞生：拆出工具中转层、三周收入翻倍与「数据界 Costco」

看到插件曲线和低流失率后，团队把视线拉高到平台史：当年 Facebook 长出 Zynga、eBay 长出 PayPal，今天 Claude Code 和 Codex 聚集了海量重度用户，但原生体验仍有明显缺口。回头复盘 Crewlet 写过的代码，最有迁移价值的并不是端到端营销壳子，而是团队为了给客户接入各类外部数据而搭建的内部工具与数据中转层。

团队将这层能力剥离独立，以 Treg 发布——不收月费，纯粹按 API 与数据调用量付费。市场反响立竿见影：上线仅 3 周，收入已经是 SuperDesign 收入的好几倍（Jason 未披露绝对金额）。当前付费最集中的场景包括：

  • Go-to-market（获客与找人）：越来越多团队直接用 Codex/Claude Code 干原来在 SaaS 里干的活，尤其是海外 B2B 找潜在客户。过去用户要在 Apollo、RocketReach 等多家按月收费、覆盖各有残缺的供应商之间纠结选一家；Treg 把它们全部聚合，按场景挑最优端点（类似数据整合明星产品 Clay 的底层逻辑——上游大量垂直数据商本身就靠按量 API 盈利，缺少直达终端的渠道，乐于被聚合分发）。
  • SEO / AEO 与社媒 UGC 数据：整合几乎所有主流 SEO 排名与 AEO（AI Engine Optimization，AI 搜索引擎可见度优化） 数据源及社媒数据。
  • 上百种 AIGC 图片与视频模型：石天鑫举例 Seedance、MiniMax Hailuo 等视频模型效果惊艳，但普通人为了短期一次性需求办包月会员太贵。Treg 接入上百个 AIGC 模型，并附上写明「每个模型擅长什么、不擅长什么」的 Skill，让用户配合 Coding Agent 一站式生成 UGC 视频。

Koji 接连抛出两个尖锐的商业壁垒拷问。第一问：未来模型自己更强、会用浏览器抓网页后，还会需要 Treg 这层吗？Jason 给出两层防线：业务需要实时动态数据，不在模型静态参数里；且大量专业找人数据与受限社媒平台，根本不是靠浏览器去 Google 搜一下就能抓出来的。石天鑫补充了跨平台中立价值：就像他一位朋友因为 Kimi 接入了 Wind（万得）股票数据而选用 Kimi，未来不同 Harness 会有各自特色数据；Treg 做中立工具市场，确保用户在 Claude Code 与 Codex 之间自由切换时，沉淀的工具调用与数据完全无缝带走。

第二问：如果最强的数据供应商直接对接模型大厂，Treg 会不会只是过渡层？Jason 用 Costco（开市客） 作比：外界误以为每个行业只需接一家垄断巨头，现实却是任何细分领域都有几十家供应商、覆盖面与性价比千差万别，Treg 扮演严选买手帮用户低成本匹配最优解。更关键的是团队正在搭建的「大众点评式」Agent 数据飞轮——应用公司训不起基础模型，必须靠数据反哺产品。石天鑫指出，如今产品的真实用户早已不只是人类，还有直接调接口的 Agent：系统随机抽样让 Agent 评价每次 API 返回是否有用、具体哪个字段起了作用，简单 Bug 自动触发修复、新需求自动入库，同时把客观指标与 Agent 主观评分沉淀为透明榜单，帮后来的 Agent 按任务权衡选「最贵最准」还是「便宜广覆盖」。

4. Coding Agent 成为新平台：200 美元套餐红利与周边明星产品

Jason 总结三次转型的最大教训：过去创业团队贪大求全，恨不得把推理、沙盒、记忆、Harness 全自己造一遍，可每一层都有专门公司在疯狂迭代；如今不同工种（从用 Figma 的设计师到用邮件工具的营销）正统一汇入 Claude Code 与 Codex，创业团队只需把垂直一环做透、顺势嵌入生态。石天鑫更一针见血地揭示了隐藏在背后的经济套利红利：早先做 Crewlet 时（转写误作快手），他深感零人公司烧 Token 成本极其恐怖，创业公司向模型厂买 API 再转卖给用户压力山大；而今天终端用户花 200 美元买 Claude Code 或 Codex 包月套餐，实际能用出价值 6,000—7,000 美元的 API Token 用量！小团队站在这一巨大补贴红利上做周边产品，增长阻力截然不同。

两人与 Koji 随即盘点了一批正在 Claude Code 和 Codex 生态里爆发的新老工具：

产品 / 公司 定位与生态机会
Ego(lite) 专为 Codex、Claude Code 做 Computer Use（电脑操作）深度提速的浏览器（转写误作 Eagle）。
ChatCut / Hyperframe 解决视频生成「无中间状态」痛点的插件与工具。代码生成后可局部改，传统视频一改就要等 10—20 分钟重渲染烧海量 Token；ChatCut 在 Codex 里输出 3 条音轨、10 个片段的可编辑中间时间轴（团队做 SuperDesign 插件时专门借鉴了它的丝滑体验）。Jason 作为 Hyperframe 重度用户补充：即便有了时间轴，人也懒得亲手拖，而是打包反馈让 Agent 调用编辑器接口局部修改，大幅省时省钱。
Apify / DataForSEO / Paper / Exa / Composio / Firecrawl 一批传统或垂直基础设施全面翻红：Apify（长尾爬虫 API 市场）、DataForSEO（SEO 数据）、Paper（嵌入 Codex 的设计对比与微调画布）、Exa（Agent 专用搜索，已达 C 轮）、Composio 与 Firecrawl（OAuth 授权与网页抓取）。Jason 观察到，它们的用户已从纯开发者变成一半开发者 + 一半不懂编程的白领终端用户，后者接入 Coding Agent 即可直接调用。
Vibe Island Koji 的 AI Hacker House 周日黑客松冠军付费产品（Jason 与石天鑫双双付费）。把 MacBook 顶部「灵动岛」改造成多 Agent 状态面板，哪个线程跑完、哪个在等 Review，配合像素小人和音效直观提醒。
Orca Jason 朋友晶晶打造的 ADE（Agent 的 IDE），已收获 8 万 GitHub Star。界面极具审美，核心卖点之一是帮重度用户跨平台「薅羊毛」——Codex 额度用光后可将做到一半的任务平滑接力给 Claude Code；面对同时开 50—100 个 Session 的重度用户，正在探索全新人机交互范式。

5. Loop Engineering、多 Session 瓶颈与前沿模型实战横评

聊到前阵子风靡一时的 Loop Engineering（循环工程，围绕目标搭建自动检查与行动循环），石天鑫援引自己喜爱的《系统之美》将创业一分为二：创新不能靠 Loop 完成（喊一句「帮我造家创业公司」行不通），但运营中有大量清晰的小任务极适合 Loop。他讲了 4 人小团队遭遇的真实痛点：SuperDesign 和 Treg 一旦推出邀请送 Credits 的激励机制，黑客就会蜂拥而至疯狂攻击盗刷，单靠人工每天盯防极其痛苦。正确做法不是搭一个庞大脆弱的超级循环，而是搭十几个短小精炼、不易出错的小 Loop——一个专盯数据库异常、堵小安全漏洞，一个专理代码，另一个线上监控 Loop 负责校验前一个循环提交的改动有没有引入新问题，彼此制衡形成健壮系统。

随着 Fable 等强模型落地，两人近两三个月的日常协作也发生剧变：Jason 常同时开 5—10 个 Session 并行干活，并借 Grok Bot 跑通云端与本地混合交换 Context；石天鑫则发现单靠人脑切换分派、审查与整合已逼近上限，他从 YouTube 资深工程师 Kun 分享的 Firstmate（大副） 思路中获得启发——船长不再挨个跟所有会话聊天，而是借助新一代终端管理工具指定一个「大副 Agent」，由它去向其他编程 Session 协调传话。

在具体工具与模型偏好上，两人分享了极一线的使用体感：

  • Claude Code vs Codex：Jason 几个月前还是 Claude Code 死忠，直到 Astra 模型发布后切到了 Codex。实测用它配合 Hyperframe 做宣传视频时，直接丢进一段参考视频，Astra 竟然一次性一比一复刻出来，甚至聪明到自动从原视频截图裁剪素材嵌进新片。石天鑫则坚持双持择优——同一任务同时丢给两边挑更好的版本，因为 Fable 和 Astra 交替领先，必须始终沉浸在世界最强模型的一线体感里。
  • Grok Bot 与云端沙盒：团队把 Treg 与 SuperDesign 的全部 Loop 都搬到了 Grok Bot 上，看中其极高稳定性与随时可查的云端体验。Jason 提到 Grok Bot 收购 Cursor 后整合出的云端隔离沙盒极有价值——每个编程任务与 PR 都自带独立沙盒链接，点开即可测试，能轻松并发测试五六个环境，远非本地开几个 Workspace 可比，因此他已把简单前端修改与修 Bug 搬上云端。
  • 国产模型与 Jev：此前做 SuperDesign 时团队曾把 Kimi 当主模型（设计极强），接入了 MiniMax Hailuo 做高性价比视频，石天鑫非常喜欢 DeepSeek 4.1 Flash 的高速度与高效率（Jason 个人对 DeepSeek 主模型体感一般，生产环境第一层 Agent 仍因稳定性保留 Claude）。两人最后热赞刚爆火的 Jev（转写误作 Jeff）——凭类似 System 1 直觉的超低延迟，恰好击中 Treg 的两大工程痛点：①对每个进入的端点请求做毫秒级智能路由（大语言模型动辄几百毫秒太慢）；②召回 2,000—3,000 条外部数据后逐条高速清洗过滤，搭建比常规 LLM 快得多的召回引擎。

6. 「把才华埋葬在昨天」、4,000 美元盗刷低谷与 AGI 时代的创业信念

尾声，Koji 提起近期刷屏的 DeepSeek 研究员文章《我不得不把我的才华埋葬在昨天》。在阿里、字节写了 10 年 React 与前端代码的石天鑫感慨极深：从去年起就已经无比清晰——「对程序员来说，你再也写不过 AI 了；除非做到世界前几百名，否则过去这项技能很快用不上。」正是站在旧路即将消失的人生十字路口，他才义无反顾辞去大厂工作加入创业团队寻找新战场。设计师出身的 Jason 则看到了硬币的另一面：自己向来讨厌枯燥抠像素，偏爱从产品视角思考再亲手写点前端代码，AI 时代反倒把这类跨领域复合能力彻底释放了出来。

聊到九个月连番转型、亲手给刚做完一个月的项目宣判死刑，有没有想过放弃？Jason 坦承在 Crewlet 阶段最挣扎——每天面对巨大不确定性却想不出破局办法，何况自己本就能靠 YouTube 频道轻松过上小康生活。他的决策标尺很干脆：能想到真正改变处境的具体动作就继续干，想不到就果断换方向。石天鑫则吐露了一次令人崩溃的至暗时刻：某天一觉醒来，发现系统被人恶意盗刷 Credits，一夜蒸发 4,000 美元，「当时觉得天都塌了」。支撑 4 人团队挺过来的，是一边贯彻 Fail Fast（让注定失败的方向尽快结束），一边始终并行寻找新曙光。

最后一个问题直击终极信仰：既然相信 AGI（通用人工智能）会随着模型进化到来，为什么还要继续创业？Jason 回答，全员保持最前沿重度使用体验，就能看清未来 6—12 个月的 Frontier（能力边界）并卡住生态机会；石天鑫则用一句极其务实的工程逻辑画上句点：「哪怕有一天万能的 AGI 真的到来，它依然需要好工具和更便宜的数据——如果它自己绕弯花 1,000 美元 Token 才拿到一份数据，而我们能让它只花 100 美元就拿到，AGI 依然会选择我们。」

机制与算例：为什么「工具层」比端到端「零人增长」更早跑通

Treg 从 Crewlet 转向工具市场，背后是一次清晰的系统边界收缩：端到端自动增长的输入极其宽泛（「帮我把业务做大」），最终验收却是真实付费转化，中间串联了客群定位、实时数据、内容创意、渠道时效、合规与销售临门一脚，任何一环脱节都会导致客户零收益。工具层把其中最容易标准化、又最难靠模型静态参数解决的一段切了出来——接收结构化数据/工具请求，返回实时结果与价格，把最终业务判断交还给人类与上层 Coding Agent。

本文自拟算例（有效线索单价 vs 表面调用单价）：假设 Treg 聚合了两个 B2B 找人端点：供应商甲每次调用返回 10 个联系人、收费 5 元（表面单价 0.5 元/人）；供应商乙返回 20 个联系人、收费 12 元（表面单价 0.6 元/人）。若只看接口是否 200 OK 或返回条数，甲更便宜；但结合后续 Agent 反馈与任务核验后，甲的 10 人里仅 2 人职位与邮箱真实有效（单个有效线索成本 2.5 元），乙则有 8 人有效（单个有效线索成本 1.5 元）。只有把任务级有效性而非表面返回量纳入评分榜单，数据市场才真正替用户省钱（本算例为本文构造，非 Treg 实际运营数据）。

同样需要看清边界：拿到更便宜、更准确的数据只是增长漏斗的前半段，开发信是否合规、产品本身有没有真实 PMF（产品市场契合度）、客户是否买单，仍取决于企业自身，工具中转层本身无法单独包办营收增长。

独立判断：这段三次转型样本真正说明了什么

「演示惊艳」与「真实业务交付」之间隔着动态对抗与结果归因

Posia 让人爽快地充钱开上帝模式却没赚到钱，而 Crewlet 亲自拿自家 SuperDesign 停工实测两个月后推翻了「零人公司」假设——这是全期含金量最高的一课。从 0 到 1 搭网页、发邮件属于静态执行闭环，极易展示魔法感；但真实商业增长属于多方动态博弈（正如 SEO 蓝海词迅速红海化），判断系统行不行，必须把指标从「AI 干了多少活」切换为「新增有效线索、人工接管耗时与净 ROI」。

寄生 200 美元套餐红利极其聪明，但同时引入了平台依赖风险

石天鑫看穿「用户用 200 美元 Coding Agent 套餐撬动 6,000—7,000 美元等效 Token」的套利结构，是小团队在算力高昂阶段极其犀利的生存策略。不过正如当年 Facebook 调整政策重创 Zynga、Codex 几天内便改掉「01 字母排序」规则一样，寄生生态必然面对平台收紧接口、改变分成或把高利润工具原生收编的风险。Treg 选择跨 Claude Code、Codex 与自建 Agent 的中立工具层，恰好是对冲单一平台依赖的合理结构设计。

「大众点评式」Agent 反馈飞轮成立的前提是独立真值校验

让直接消费接口的 Agent 给工具打分听起来极富想象力，但存在明显的评估偏差陷阱：Agent 只能观察接口是否返回了字段齐全、格式工整的文本，极易偏爱「看起来丰富实则过期或注水」的数据源；若允许模型自行决定何时提交评价，还会产生样本选择偏差。要让榜单真正形成护城河，仍需引入抽样人工真值核查与下游业务结果回传（如邮件送达率、线索有效率），并用 Jev 类低延迟模型做好清洗与防刷控风。

多 Session 并发与小 Loop 矩阵，把瓶颈从「写代码」转移到了「审查与协同」

同时跑 5—10 个甚至 50—100 个 Session，表面上把人类产出放大了数十倍，但如果多个会话改到同一套底层架构、共享冲突上下文，或者全卡在人类审查队列里，整合与返工成本很快会吃掉并发红利。同样，用十几个短小精炼的 Loop 防黑客盗刷、理代码和互相监控，远比造一个全能大循环务实，但依然必须设计清晰的熔断阈值、权限隔离与异常人工接管机制，防止自动化循环在意外输入下互相放大错误。
