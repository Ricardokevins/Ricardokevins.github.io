AI Native (AI原生)在本段中，张月光对该术语提出了更严格的定义。它不仅指“没有这代AI技术就无法实现的产品”，更关键的特征是产品在输入和输出上都具有“开放性”。这导致产品设计范式从传统的“面向流程设计”转变为“面向上下文设计”，即设计的核心不再是预设用户的操作路径，而是管理和构建能让AI模型有效工作的上下文信息。
One Way Door (单向门) 产品指用户一旦体验了该产品提供的解决方案，就再也不会回到过去的方式去满足同一个需求。这种产品为旧需求提供了具有全方位优势的新解法，具备强大的用户粘性和市场替代潜力。张月光认为这类产品是值得长期投入的方向。
Live2D一种能让2D静态图像（如动漫角色“纸片人”）产生动态效果的技术。输入是2D原画，通过建模使其能够做出呼吸、眨眼、转头等动作，输出是可交互的动态形象。张月光在第一次创业产品“元音”中使用了该技术。
面向流程的设计 (Process-oriented design)传统的互联网产品设计方法。产品经理预先定义好用户可能的操作路径、界面元素和交互逻辑，形成一个相对封闭和确定的系统。用户在产品内的行为被限制在设计者规划的“有限自由度”之内。

张月光回顾了“妙鸭”的诞生过程。他表示，这最初是一个兴趣小组的项目。当时大语言模型虽火，但团队评估后认为只有图像技术（Diffusion Model）相对成熟，且周边生态较好。为了避免与Midjourney等巨头直接竞争，他们决定寻找一个足够垂直的细分领域。基于他过去做相册时“用户照片70%是人像”的经验，团队锁定了“写实人像”方向。最初团队考虑过做电商模特图，但他认为这个环节在长商业链条中议价权低，不是好生意。最终，他们选择了写真这个C端、可直接定价的场景，旨在解决传统写真“成本高、周期慢、重资产”的痛点。

妙鸭成功的关键在于效果上满足了“真、像、美”三个标准：“真”即看不出是AI生成；“像”即与用户高度相关，满足传播心理；“美”即适度美化。他强调，妙鸭并非首创，B612、美图等产品当时已有类似功能，但妙鸭在效果上做到了极致，这符合他偏爱“One Way Door”（单向门）产品的理念——即用户体验后就再也回不去旧的解决方案了。

然而，经过两年的思考，张月光得出一个核心结论：妙鸭并非一个真正的“AI Native”（AI原生）产品，而是一个将AI能力发挥得很好的“互联网产品”。他解释，AI Native的定义不应仅仅是“没有这代AI技术就做不了”，更关键的特征在于输入和输出的“开放性”。

他对比了两种产品设计范式：

1. 互联网产品设计是“面向流程的设计”：产品经理为用户设计好有限的路径和选项，即便是微信这样自由度高的产品，本质上也是一个“有限自由度”的游乐园。妙鸭就是典型例子：通过“上传20张照片-选择模板-生成写真”的固定流程，限制用户自由度以换取稳定和优质的效果。这是一种典型的互联网产品思维。

2. AI Native产品设计是“面向上下文的设计”：由于用户输入（如自然语言）和模型输出都具有高度的开放性和不确定性，产品经理无法预先设计所有流程。设计的核心不再是画出线性的交互流程图，而是思考如何构建和管理“上下文”（Context），即如何获取并利用各种信息，以确保模型在执行任务时能产出符合预期的结果。产品团队的协作方式也必须改变，不能再沿用“产品定义-设计出图-工程实现”的线性模式，因为模型的效果往往会推翻前置的设计。

张月光总结，从“流程设计”到“上下文设计”是AI时代产品经理需要跨越的巨大思维鸿沟。产品设计的重心，已从规划用户界面和交互流程，转变为研究如何为模型提供最佳的上下文，并引导用户提供这些必要信息。

00:42:56–00:45:32AI Native组织：从线性分工到两段式协作

嘉宾张月光主动探讨了AI时代所需的组织形式。他认为，如果AI时代的组织与互联网时代没有区别，那对创业公司而言是危险信号，因为这意味着大厂可以凭借其延续性优势轻松占据主导地位。他驳斥了“大厂掉头难、反应慢”的普遍看法，称其为“幻想”。他指出，真正的机会在于组织形式上出现“代差”。

张月光认为，AI Native产品设计正在催生组织变革。具体表现为：

1. 角色边界模糊：传统互联网公司中产品经理、设计师、工程师的线性工作流（需求->设计->开发）不再适用。AI项目要求更混合的协作方式，例如，产品经理需要懂模型和技术，设计师需要理解产品经理对模型输出结果的“品味”（taste）和预期。他强调，“品味”——即对模型产出效果的期望——变得至关重要，且通常需要跨工种共同定义。

2. 工作流程变革：传统基于Sprint的线性开发模式是为了保证流程不混乱。然而，AI Native产品在早期探索模型能力时，过程本身就是非规律性的。因此，组织需要从“线性工作”转变为“两段式”：第一阶段是混合团队共同探索模型，明确模型能做什么、需要用户提供什么上下文（context）；第二阶段，在模型能力边界清晰后，再进入传统分工，由产品经理设计获取用户上下文的流程，设计师配合实现，然后进入正式开发。

两段式工作嘉宾提出的适用于AI Native产品开发的组织工作流程。它将传统线性的“需求-设计-开发”流程分为两个阶段。第一阶段：一个由产品、设计、技术等角色组成的混合团队，共同探索和定义模型的能力边界、输入输出和所需的用户上下文（context）。第二阶段：在模型能力明确后，再回归相对线性的分工，由产品经理设计获取上下文的用户流程，设计师和工程师跟进实现。

Agent的两种价值取向嘉宾张月光在本段中将AI Agent的发展路径分为两种价值取向。第一种是“端到端替代”，以Manus为代表，目标是让AI独立完成整个任务流程，替代人类劳动，节省用户时间，其终极形态是走向完全自动化。第二种是“协作与增强”，是嘉宾自己选择的方向，目标是人与AI高频、低延迟地交互协作，让AI成为增强人类能力的伙伴，帮助用户做到原本做不到的事情。
单向门（One Way Door）产品在这里指一种体验达到了极高完整度和可用性的产品。用户一旦使用了这个产品，就再也不想或不需要回到原来的工作方式。就AI生成工具而言，特指其产出物的质量高到用户无需进行二次修改或加工，可以直接在正式场景（如工作汇报、对外发布）中使用，从而真正替代了传统的手动流程。
90分等于0分嘉宾的一种产品哲学。他认为，AI产品存在一个关键的“可用性阈值”。低于这个阈值，哪怕技术上已经实现了90%的效果（即“90分”），但因为用户能轻易识别出是AI生成、效果不够完美、无法直接用于正式工作流，导致其商业价值非常有限，约等于“0分”。只有跨越该阈值，达到与人类专业产出无异的“100分”水平，产品的价值和AI的成本优势才能完全释放。
上下文设计（Context Design）相对于传统互联网产品的“流程设计”，这是一种面向AI产品的设计范式。传统产品设计关注的是用户在一个确定性、有限自由度的界面流程中的操作。而AI产品由于输入和输出都是开放和不确定的，设计的核心就变成了如何为AI模型构建和提供精准、丰富的上下文（Context），以引导模型产生出高质量、符合预期的结果。工作流也从“先设计交互界面，再实现效果”变为“先打磨出理想效果，再倒推需要哪些上下文，最后设计获取这些上下文的交互流程”。

张月光借用 One Way Door 描述真正的产品突破：用户使用后，不想再回到原来的方式。它不是“增长快”，也不是“功能多”，而是用户的任务结构发生了变化。对于 PPT Agent，One Way Door 的标准不是它能生成幻灯片，而是用户不必再做后期修订，且最终内容、逻辑和设计都超过自己单独制作的水平。

四、AI 产品组织：先混合探索，再正式工程化

传统互联网的线性分工是产品经理写需求、设计师画界面、工程师实现。但生成式产品的输入、输出和中间状态都开放，需求本身会在试验中改变。张月光提出两阶段组织：第一阶段让产品、设计、工程、模型和内容共同探索模型与上下文；第二阶段当上下文结构稳定后，再把它工程化成可靠流程。

这个顺序非常关键。太早流程化会把未知的能力锁死；一直探索又会让产品无法交付。AI Native 组织的核心不是人人都懂模型，而是每个角色都能参与“什么上下文需要被保留、什么结果算成功、怎样让失败可见”的讨论。

探索期

跨学科、低成本、快速试错，关注能力边界与用户真实反应。

定型期

把上下文、评价器和权限写成产品协议，减少不可控的临时决定。

交付期

建立可靠性、成本、监控、人工介入和持续训练的工程账本。

五、AI companion、信息聚合与新内容平台：新媒介必须带来新交互

张月光对 AI companion 的判断并不止于“聊天更自然”：行业有三个难题——用户表达门槛高、token 很难直接变成合理价格、角色不会持续成长。他因此倾向游戏形式：用 PGC 降低表达门槛，用游戏付费机制承接价值，再用持续内容让角色和世界成长。内容不是模型生成的装饰，而是关系能够持续的资产。

信息聚合则遇到相反问题：如果产品只是把已有的信息源重新排列，用户会回到搜索、社交或专业工具；而“帮用户节省时间”的产品，又常与依赖注意力的广告模式冲突。张月光把 ChatGPT 视为一种新的对话媒介，甚至可能拥有影响决策的商业模式——这是嘉宾推演，不是已经验证的市场事实，也提醒我们注意决策自主性被侵蚀的风险。

新媒介

交互方式改变了人如何表达、选择和协作，产品才有机会成为平台。

旧包装

只是把短视频、图片或信息流换成 AI 生成，仍可能被旧平台的分发与注意力逻辑吸收。

六、Agent 的两条路：替人做，还是让人能做以前做不到的事

张月光把 Agent 的价值分成两条：第一条是自动化，替人完成已有任务；第二条是能力延伸，让人完成过去做不到的创作与表达。他明显更偏向后者，因为“替人做”最终会与模型公司的自动化路线正面竞争，而“扩展人”更容易形成新的创作形态。

Dokie 从 PPT 开始，是因为 PPT 不是最容易的 Agent 任务，而是能把内容、结构、视觉和上下文聚合到一个可验收结果中。成功标准是效果优先：用户的最终产物是否超过自己的能力，是否不需要返工，是否能把上下文沉淀为下一次创作的资产。模型公司依赖、云端成本与版权约束都必须进入同一个结果账本。

七、创业者的工作：诚实承认不确定，再在证据出现时 All-in

这期访谈最有用的创业方法不是某个产品点子，而是一套心力管理：对投资人和团队诚实声明尚未确定的事情；用最低成本实验检验方向；在证据不足时不扩张承诺；一旦确认用户价值，就集中资源。张月光把“不乱搞”看成保护心力，而不是缺少野心。

资本在这里更像耐心的缓冲器。它可以让团队做多轮试验，但也会带来压力：投资人希望听到确定叙事，团队容易把探索包装成路线。AI 创业者必须把“我们还不知道什么”写进产品计划，避免把模型热度误当作需求确定性。

核心判断：AI Native 的最小单位不是功能，而是一次不可逆的结果改善

“加一个模型”可以让旧产品变得更快，却不必然改变产品范式。张月光把 AI Native 说得很具体：互联网产品长期围绕有限的输入、流程和输出设计；模型让输入和输出都变得开放，因此产品的核心工作从 workflow design 转向 context design。只有当系统能捕获足够上下文，并稳定地产出用户愿意接受的结果，AI 才真正改变了工作。

开放输入

用户不必先学会产品规定的字段，问题、素材和意图可以以自然语言或多模态进入。

上下文设计

产品决定哪些背景、来源、约束和历史被带入模型，并让用户能检查。

开放输出

结果不是填完表格，而是可直接拿去发布、决策、协作或继续创作的交付物。

本文的中心推论“One Way Door”不是增长曲线，而是替代曲线：用户一旦体验过新的结果质量，就不愿再回到旧的工作方式。它要求产品同时控制结果、成本、可靠性和用户信任，因此比“AI 功能上线”高一个层级。

Insight：One Way Door 是结果阈值，不是模型阈值云模型的分数差距可能还存在，但只要跨过某个可用性阈值，产品就能把能力包装成新的工作习惯。真正的竞争是“结果是否让用户改变行为”，而不是“模型是否在所有榜单第一”。

进一步推演：这场访谈留下的八条 Insight

  1. AI Native 的核心资产是上下文，而不是提示词。 提示词可以复制，上下文需要长期捕获、验证、治理和迁移。
  2. One Way Door 是一种用户行为证据。 没有“回不去”的行为变化，所谓范式升级仍可能只是功能升级。
  3. 妙鸭证明了专用模型管线的商业价值，也暴露其边界。 串型模型能在明确的结果链上取胜，但不等于它自动拥有通用 AI 未来。
  4. AI 产品组织要先发现上下文，再固化流程。 顺序反过来，会把未知能力提前压成旧软件。
  5. Agent 的竞争将分化为自动化与赋能。 前者追求替代人工，后者重新定义人的产出边界；两者的产品、价格和责任完全不同。
  6. 新内容平台必须提供新的关系结构。 生成更多内容不等于新平台，新的媒介与互动才可能形成网络效应。
  7. 游戏是低表达门槛的 Agent 入口。 它把用户意图、内容生产、角色成长和付费统一到一个可观察环境。
  8. “效果优先”要求重新定义后编辑。 只要用户仍需大量修订，Agent 交付的其实是草稿，不是生产力。

怎样证伪或修正这套判断

  • 若简单的模型外挂在旧工作流上就能长期产生同等的用户不可逆行为，AI Native 的重构成本会被高估。
  • 若自动化 Agent 的成本与可靠性显著优于赋能型产品，赋能路线需要重新解释其防守位置。
  • 若用户长期愿意为信息节省时间付费，注意力商业模式与节省时间之间的冲突并非必然。
  • 若 PPT Agent 的结果仍需专业用户大量返工，One Way Door 只能作为愿景而不能称为已验证机制。
