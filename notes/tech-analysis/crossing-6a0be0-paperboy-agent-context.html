Paperboy：连续上下文与主动协作的边界

如果助手能从操作系统层面观察你的跨应用工作流，用即时通讯而非一次性会话组织协作，它能省去多少重复解释？它又怎样避免误解、越权与打扰？

对话脉络 · 从活动到记忆 · 独立判断 · 证据边界

先把访谈讲清楚

开场与快问快答：21 岁二次创业者与 19 岁 CMU 创始工程师

本期《十字路口》由 Koji 与 Ronghui 联合主持，对谈 Paperboy 创始人兼 CEO John Yang 与 Founding Engineer Jett Chen。因 John 用英文表达更自然，整期对话中英混杂，团队负责招聘等事务的 Vivian 也在现场短暂出声。开场快问快答先交代了团队基本面：

John Yang21 岁（2004 年生），就读于 Pratt Institute 建筑专业；ISTJ，双子座。Paperboy 是他的第二家公司：第一家公司 Million 入选 YC Winter 2024，早年在 React 生态做了大量开源开发工具，并向大企业售卖网页性能 RPA 机器人，后做出 same.new——输入一句话和 URL 即可复刻几乎一模一样的网站界面。创办 Paperboy 前，他曾在 Manus 工作过一段时间。
Jett Chen19 岁，毕业于上海新虹桥双语学校，刚读完卡内基梅隆大学（CMU）大一；INTJ，处女座。加入 Paperboy 前是高中生，热爱开源与 CTF（网络安全夺旗赛）；一两年前做过多模态定位项目 EarthKit，拍一张照片用多模态大模型推测拍摄地，效果超过传统纯神经网络模型。
团队与现状Paperboy 的使命是探索人与 AI 协作的最佳形态。团队现有 12 名全职员工（其中 10 位工程师），融资 470 万美元；产品尚未公开发布，当前收入为零、毛利率为负（John 直白笑称「每天都在亏钱」）。他们曾把让 Agent 从操作系统（OS）活动学习的原型发给朋友试用，但成本太高且效果不佳，正赶在录制当月收尾下一版迭代并准备重新推向市场。

起点：对现有 AI 交互的不满，与不断移动的球门

Koji 提到第一次见 John 时读过一份令人震撼的内部文档——去年 11 月 30 日团队仅四人（John、杜哥、陈、Jett）开首次全员会时 John 写下，开篇第一句就是：「人类和 AI 配合工作的最佳方式，很可能还没有被发明出来。」

John 回顾，做完 same.new 后，他对市面上所有 AI 产品都感到不满：为什么非要把文件、邮件和个人背景手动扔进对话框？为什么不能顺畅地让多人与一个 Agent 在同一个上下文窗口协作？为什么 Agent 知道了大量个人信息后，依然只能被动等提示，而不能主动（proactive）提前帮忙？在他看来，这全是模型能力与产品部署形态之间的落差。当年 Cursor 最先锁定了「与 AI 协作写代码」的球门并率先跑通，Paperboy 想去争夺通用工作场景的球门。

Koji 追问：创业至今这半年，Claude Code、Claude Cowork、OpenClaw、Hermes Agent 等重磅产品轮番登场，不少创业者感到绝望，Paperboy 的方向有没有因此剧变？John 回答「还真没有剧烈变化」。他将其称作「不断移动的球门（moving goalpost）」——每当新形态出现，有品味的用户总能看出新的摩擦点，只能持续演进。只要从人的真实需求出发，问题空间就聚焦在三点：

  1. 从环境中自主学习：Agent 必须原生接入用户已在使用的本地文件与各类集成，而不是等人手把手喂材料。
  2. 深度个性化与可靠性：足够懂你，你才不用频繁写 prompt，才敢放心交给它更复杂、更高风险、运行更久的任务。
  3. 极致直觉的设计：你不该像学全新专业软件一样去学怎么用它；一旦多个 Agent 开始主动产出想法，就需要一种自然存在于用户原环境且便于团队协作的形态。

打破 Session 模式：为什么必须从操作系统层采集上下文

面对已经重度使用 Claude Code 或 Manus 的听众，John 指出这两类最成功的 Agent 都有两个根本痛点：基于会话（session-based）与一对一被动问答（reactive）。侧边栏堆满工作区和几百上千个孤立会话，每次开新会话都像重新认识一次；旧会话里再宝贵的洞见，不刻意抄进 Agent.md 或技能文件就会随会话沉底丢失，而人的品味与判断根本无法靠手写纯文本完整转译。

Paperboy 正面回应这两个问题：一是在用户逐项授权下，让 Agent 通过观察日常电脑操作自己学习——涵盖屏幕截图、键盘输入、鼠标移动、会议音视频、浏览历史与 iMessage；二是抛弃一次性会话，改用类似微信或 iMessage 的持久聊天，让可搜索的对话历史远远长于单个模型上下文窗口。

Jett 补充了更细的工程区分：有人会说 Claude Code 和 Manus 靠上下文压缩（compaction）也能模拟无限窗口，而 Interaction 的 Poke、Zoo Computer 乃至 OpenAI 也在探索无 session 的持续聊天。但那些产品的上下文主要来自人与 Agent 的历史对话或导入邮件、消息。团队最早做原型时也试过全量导出微信和 iMessage 聊天记录，很快发现这条路既不具扩展性、信息浓度也太低——观察用户过去 60 分钟的微信聊天学不到太多东西，但从 OS 层观察他用电脑 60 分钟，就能高浓度掌握他当下真正在做什么。从 OS 层捕获上下文做用户适配，成了团队最早压下的重注。

屏幕上下文成为共识之后，真正的战场在哪里

Koji 提到此前采访过的 AirJelly、OpenAI 新推的桌面客户端 Chronicle，以及 Littlebird 都在做桌面上下文捕获，Paperboy 有何不同？John 坦承，抓取桌面原始活动流加工为记忆已成为「下一个显而易见的上下文前沿」，Codex、Claude Cowork 和 Claude Code 都会做。但不同应用场景决不能共用同一套记忆压缩管道——帮人回邮件与帮人做深度研究，该抽取什么细节、如何建模跨应用状态与人际关系截然不同。

Jett 也表示，采集屏幕数据已成行业共识，但在此之上如何做主动式 Agent——是预测用户下一个按键，还是预测接下来一小时的动作——目前无人找到公认「最佳配方」，仍需大量工程与研究探索，对创业公司依然是好机会。

前五分钟的信任破冰：从会前准备到团队里的「数字分身」

Ronghui 追问新用户装上后的头五分钟到一小时能获得什么价值。John 说团队计划从会前准备（meeting prep）切入：打开后不是干巴巴的提示框，而是真正的聊天窗口。用户授权日历与邮件后，系统先简短核实身份背景，随即针对即将到来的会议给出克制提议，比如「我看到你马上有一场会，要不要帮你提前查点资料？」早期必须通过几次「懂你又不令人厌烦」的短信式互动，建立「这个 Agent 能自然发消息帮忙」的信任预期。

John 接着展示了团队已在内部 Slack 实战的两个分身——AutoJohn 与 Mini Vivian（Vivian 曾任职小红书，在团队承担大量招聘）：

  • AutoJohn：常驻公司 Slack，产品和设计同事有疑问会直接找它，消化了大量原本要找 CEO 确认的背景。John 笑称期待有朝一日自己可以「直接躺平」，让 AutoJohn 成为比本人更聪明的存在。
  • Mini Vivian：充当 Vivian 的招聘实习生。它旁听过 John 在会议与 Slack 里关于用人的所有发言，理解团队的判断品味与招聘标准，能自动跨 GitHub、小红书和 X（Twitter）帮 Vivian 发掘候选人。自 2 月以来 Vivian 几乎不再用 Claude 调研候选人——用 Claude 得把无数隐性判断反复写成 prompt，而用 Mini Vivian 几乎不用写 prompt，像真人高带宽发消息一样默认对方懂你。

Jett 坦白说，日常很多时候跟 AutoJohn 聊确实比找 John 本人更顺手：作为一线工程师，他每天思考做什么研究或工程对公司价值最大，而 AutoJohn 同时握有 John 对全公司的上下文与相似的启发式判断。但他也划清红线：遇到必须由 CEO 批准授权的决定，或担心分身意志还不能完全代表本人时，仍会直接找 John。John 补充，用户必须为自己的 Agent 负责：接入 Slack 前有一套引导流程，Agent 会逐一确认对哪位同事可以分享多少信息，默认则镜像本人真实聊天尺度——比如对 Jett 分享极多，对新入职工程师则收敛。

跨应用自动补全 @pb、PR 起草与「防走神日报」

Jett 分享了自己最早的顿悟时刻——全局文本补全。底层上，团队先搭起 OS 数据采集与记忆框架，沉淀为一份实时更新的 Markdown 文档，同时记录用户职业、近几天在忙什么，以及过去几分钟乃至几秒钟的操作——距离当下越近，颗粒度越细。基于这套随身上下文，用户在系统任意输入框键入激活词 @pb 即可调用：

  • 命令行写提交说明：不少 AI 终端不如传统命令行流畅，而传统命令行缺 AI 集成；现在写完代码敲 @pb commit，系统直接写好完整 Git commit message，回车即发。
  • 零提示词的「眼神默契」：在微信或任何文本框里甚至只需打 @pb 不写指令，它能凭上下文猜出你要它干嘛，就像熟识的工程师指一下屏幕说「看这儿」，对方秒懂。
  • 跨应用起草 GitHub PR：Jett 发现它写的 PR 描述常胜过 Cursor 或 Claude Code 等单应用 Agent——开发大功能时人会在 Claude Code 写代码、微信里和 John 讨论、浏览器里做调研间频繁切换，只有跨应用聚合上下文的 Agent 才真正懂来龙去脉。
  • 「老大哥式」防走神督促：Jett 自嘲怀疑自己有 ADHD，听分享常忍不住点开旁边的 Hacker News，一篇文章看 30 分钟回来会议早结束十多分钟了。他曾让 Paperboy 每晚发效率报告「骂自己」，标出何时分神——光知道它在盯着，效率就显著提升。Ronghui 笑称这就是「Big Brother is watching you」。

John 则把它当成 CEO 思考外脑：如今他很少写代码，大量时间在试产品、做调研、见人，Paperboy 会帮他把不同维度的念头连点成线，适时提醒「你两个月前试过类似产品形态，当时记过这几个问题」。

抛弃定制侧边栏，向微信群聊借界面灵感

录制前两周，Paperboy 启动了一版全新界面，灵感正是 Paperboy 帮 John 推演出来的。团队最初瞄准 VC 等核心客群，设想在侧边栏塞入个人 CRM、日程提醒、季度交易、被投公司与 LP 追踪模块，却立刻撞墙：运营、创业者、房产经纪人各自要的侧边栏截然不同，难道让用户去插件或技能市场挨个拼装？

推演中冒出一个核心追问：人类日常使用的软件里，什么东西本质上是无限长列表、却不会让人烦躁？答案直指即时通讯（IM）——尤其是微信和 iMessage。同样的三个人可以按不同议题建四个群；Koji 当场附和，《十字路口》团队就是每录一期新播客建一个固定几人的群，否则全挤在一个群里一片混乱。IM 最妙的是自然沉淀：不聊的群自动沉底，也能随手隐藏，本身就是一个收件箱。团队于是放弃另造侧边栏与收件箱，直接用 IM 群聊组织人与多个 Agent 的协作。

竞争格局：只有两家巨头真正重要，以及为什么不做「AI Slack」

谈到竞争与壁垒，John 异常坦白：「今天真正重要的对手只有两家——OpenAI 和 Anthropic。」它们手握模型、算力与分发，其余玩家都在后面追赶。创业者能赌的，一是像 Cursor 那样靠产品品味抢先定义面向个人的新界面；二是切入有预算的企业市场。

他们最早也想过做「AI 版 Slack」。Koji 问起市场上几款团队协作 AI 产品（含 Moxt 及由 Richard 创立的协作工具）。John 称赞对方创始人极优秀，却指出「AI Slack」的三重硬障碍：① 迁移成本极高，即便做到数据一对一导入，企业已有的外部连接器仍需重接，Ronghui 也补充跨企业沟通已深度绑定 Slack Connect，网络效应如微信般难以撬动；② Slack 本身并不令人愉悦，频道加串评只是规模化后的无奈选择；③ 仅靠群聊学得太慢，忙碌的职场人没空训练机器人，期望开箱即用且越用越聪明。因此 Paperboy 放弃硬替 Slack（John 估计超 50 人团队极难迁走），选择在 OS 层做补充——把 Agent 送到人们原本工作的地方。

《The Last Interface》与 Pace Layers：任务速度决定产品形态

Koji 提到 Paperboy 官网唯一博客《The Last Interface》里的「五种速度」。John 解释「五」只是思考归类，灵感源自旧金山非营利组织 Long Now Foundation 创始人 Stewart Brand 的节奏分层（Pace Layers）理论：世界由变化速率迥异的六层构成——时尚、商业、治理与政治、基础设施、文明、自然规律，各层相互反身作用。映射到 AI 产品的任务时间尺度光谱上：

任务时间尺度典型工作场景团队判断的合适产品形态
极短期（1 秒—10 秒）微信回复一句话、命令行写提交说明输入处原地弹出的自动补全（如 @pb）
中期（数分钟—数小时）读十份长报告并作业务决策、跨应用起草文档IM 对话协作与持续上下文辅助（最佳形态仍在探索）
长周期（数周—跨月）长期研究推进、复杂业务项目交付产品形态高度开放，是团队最感兴趣的前沿空白区

核心观点是：你在哪一个速度层做自动化，直接决定了产品应该长成什么形态；时间跨度越长，现有界面的空白越大。

21 岁首次做 CEO：挑市场、管理书单、CEO 教练与两种工程师

多位成员向 Koji 感叹和 John 交流感觉不到他生于 2004 年。John 笑称和 Jett 在一起时依然很幼稚，但带队必须清晰、高效、聚焦——CEO 的头号职责是定义什么叫成功，并确保每人对目标与运作有完整准确的上下文。他回顾高中到大学间做过多份实习；Million 早年向大企业卖 B2B 网页性能 RPA 机器人，20 岁的他们吃尽苦头，深知自己不擅长拉企业关系。这让他把「选对市场」视为早期创始人最重要的特质——市场要能持续膨胀十年、支撑一条演进的产品线，并与团队特质匹配。

谈到首次做 CEO 与管理者，John 直言太难了：以前看工程师浪费一下午会郁闷，做了 CEO 才明白自己才是公司里杠杆最大、一个错决定最能烧钱的人。他从零摸索招聘、绩效、一对一沟通与避免微管理，学习路径极为务实：

  • 一线偷师：在 Manus 任职期间，向 CTO Pan Pan 多次一对一请教工程团队组织方法。
  • 三本管理书：安迪·格鲁夫《格鲁夫给经理人的第一课》、本·霍洛维茨《创业维艰》、比尔·坎贝尔传记《万亿美元教练》。
  • 每周一小时 CEO 教练：经投资人介绍聘请了一位前大厂与 VC 高管出身的专职 CEO 教练。John 坦言从不信心理治疗，觉得教练强得多——「既能聊情绪，又能紧接着聊公司业务里正在发生的一切，而且保密」，他还让 Paperboy 旁听教练通话并自动跟进自己承诺的行动项。

在 12 人团队里，John 明确只招两种截然不同的工程师：一种像 Jett 这样年轻、高智商、富于创造力，能把每个难题飞速搭出原型；另一种是系统基本功极其扎实的老兵，例如刚从 AWS 挖来一位做过 Windows 云基础设施内核开发的工程师——他断言这类深度专家短期绝不会被淘汰。

聊到 Palantir 直接招高中生、「AI 时代还要不要读大学」，仍在 CMU 读大一的 Jett 先调侃「因为有中国父母」，随后认真表示：CMU 身边多数同龄人并不确定未来方向，大学学业耗时不多，刚好提供 4 年探索期与技术积累；若已有笃定方向和稀缺机会，辍学同样理性。谈及为何加入 21 岁首次 CEO 的团队，Jett 用「截距与斜率」作比：选创始人斜率比截距重要得多，John 在极短时间交付过亮眼战绩，极富能动性、学习快、有产品和工程品味且具人格魅力。John 则表示自己招人绝不硬推销，更看重招进来后的兑现力；面试资深候选人时尤其爱问过去十年的关键人生决策，因为「轨迹没法造假」。

拒绝 Cognition、Vercel 与 Sentry：保持独立，以及对巨头与赛道的押注

Koji 透露 Million 时期他们收到过 Cognition（Devin）、Vercel 与 Sentry 的收购邀约。John 解释拒绝很干脆：这些本质是人才收购（acqui-hires），给钱不多，进去只是当普通员工执行别人的想法，何况自己本就不热衷开发者工具；能保持独立去实现梦想，就绝不轻易放弃。

聊起除 Paperboy 外最喜欢的 AI 产品，两人分化鲜明：

  • John 最爱 Cursor：坦言仍不用 Codex，把 Cursor 视为重要灵感来源，并祝愿对方相关并购顺利落地。
  • Jett 极推崇 Codex：认为 Claude Code 厉害的是 Opus 模型而非 CLI 本身；相比之下喜欢 Codex 四点——① 核心 Agent loop 与命令行在 GitHub 开源；② 桌面端工艺极精致（OpenAI 收购了苹果 Shortcuts 团队出身的 Sky，连 Codex Pets、computer use 和 browser use 都打磨得极好）；③ 率先将高并行多 Agent推为主界面；④ OpenAI 在算力基础设施上补贴能力更强、服务更稳，而 Anthropic 因算力受限闹出风波（如仓库里含 OpenClaw 或 Hermes Agent 时，Claude Code 可能直接按 10 倍计费）。

若能买二级市场老股，Jett 会配 80% OpenAI、20% Anthropic——赞赏 Anthropic 的可解释性与社会影响研究，但嫌它在道德与使用习惯上过于说教，偏自由意志主义的自己更喜欢 OpenAI 少设限的价值观与算力优势；John 则冷静补了一句：按当下估值两家都不会买，但同样敬重 Anthropic 的安全承诺。谈到「模型吞噬一切」，Jett 认为各家模型可能趋同，差异化仍靠产品，且公司不必画地为牢——Cursor 起步是产品公司，如今也能借 xAI 算力自研前沿代码模型；John 总结：「通常两者都是。」

最后 Koji 给出 300 万美元虚拟投资额请两人押注三个方向：John 投给欣赏的创业者 Richard、机器人与底层基础设施，并断言下一个 Cursor 级巨头不会出自企业级 AI，而会出自消费级市场；Jett 同样看好改造物理世界的机器人，更强烈看好 AI + 网络安全——模型越强攻防同步升级、需求近乎无限，只要多 Agent 漏洞挖掘系统比对手多挖 10% 漏洞就能胜出，是个极讲实力的市场。面对 John 反问怎么防 Anthropic 下场，Jett 认为最强模型之上的 harness（编排框架）、安全专家启发式经验注入，以及各国和机构对主权安全能力的刚需留出了巨大空间（两人顺带打趣「另一位 John Yang」——SWE-bench 作者——刚发了从规格复现完整代码库的新评测）。

面对「一年后希望 Paperboy 是什么状态」，John 的期待朴素而直接：「希望我们不要再每天亏钱了」——跑出真实正向现金流，同时把团队的人才密度推得比今天更高。

从活动到记忆：桌面记录如何变成一次有依据的主动帮助

本文自拟例子：一名研究者过去三天在三个地方推进同一课题：本地文档写下了假设，线上会议里合作者提出反例，终端实验日志显示初版参数跑偏。如果系统只压成一句「用户正在研究 X 方向」，下次起草周报或回复邮件几乎无用；只有按时间远近分层保留「当前假设、反例提出者、实验配置与失败现象」并附可回查来源，在用户键入 @pb 或临近下次组会时，它才能精准提醒「反例尚未回应、初版日志已证伪方案 A」。

要让这条链路在真实桌面稳健运转，系统需连续闯过五关：① 细粒度权限控制（按应用、目录、联系人与会议授权，随时暂停与屏蔽敏感窗）；② 多粒度任务归类（近期留细节、跨周收敛为状态与待决项，防任务串味）；③ 事实、建议与决定分层（防旧草稿被误当正式拍板）；④ 低干扰触发时机（借会议临近或 @pb 显式触发，先给本地草稿，未经授权不对外发消息）；⑤ 成本与纠错闭环（借事件触发与轻重模型分级控制算力开销，避免重演初代原型「太贵跑不通」，并支持一键修正过期记忆）。

独立判断：更多上下文不自动带来更可靠的理解

1. 看见操作流，依然不等于读懂意图与成本账

Jett 用「看 60 分钟电脑胜过看 60 分钟微信」点破了 OS 级上下文的信息浓度优势，洞察很犀利。但屏幕与键鼠动作天生充满歧义：反复翻看简历可能是准备发 offer，也可能只是帮朋友挑错字；网页停留半小时可能是深度研读，也可能只是起身倒了杯咖啡。再加上持续截屏与多模态实时更新记忆的高昂推理成本，直接解释了为何初代原型「太贵且还不好用」。评估这类产品不能只看演示瞬间，而应测算单位工作日成本、意图误判率与人工纠错耗时。

2. 团队「数字分身」面临权限漂移与责任归属难题

AutoJohn 与 Mini Vivian 的故事很迷人，却也暴露了企业落地最尖锐的灰色地带。按过往聊天习惯「镜像」分享尺度看似自然，但人际关系与信息密级是动态变化的：上个月能坦诚聊的融资或人事判断，本月可能已成机密；分身一旦把创始人尚未成熟的随口猜测包装成笃定回答，团队可能顺着错误方向白干一周。团队分身必须具备显式来源标注、置信度边界、单向降权撤回，以及「仅供参考、不代表本人批准」的硬性动作隔离。

3. 一人授权采集屏幕，天然会卷入他人的未授权隐私

相比手动粘贴文字，OS 级持续采集（截图、会议音视频、iMessage、浏览历史）会无差别收入同事私聊、客户合同、候选人隐私与亲友信息。能否把本地存储、脱敏机制、保留周期、敏感应用黑名单与彻底擦除做成透明可审计的默认能力，往往比多做一个炫酷功能更决定生死。

4. 「IM 群聊 + 节奏分层」是好框架，但长周期任务的界面远未收敛

用微信群聊化解侧边栏碎片化，用 Pace Layers 拆开 1 秒补全与跨月任务，体现了极佳的产品抽象力。然而 IM 擅长异步沟通，并不擅长承载跨周任务的依赖关系、版本比对与多方签核——这正是团队在群聊里依然常被刷屏淹没、不得不切回文档与任务系统的原因。面向数小时乃至跨月任务，如何在「像聊天一样零门槛」与「像工作台一样结构可控」之间取得平衡，仍是整个行业尚未交卷的难题。
