姚顺雨谈 Agent 研究的下半场：任务、上下文与评估

2025 年 4 月，姚顺雨发表《The Second Half》。5 月，张小珺和广密请这位当时任职 OpenAI 的研究员回看他做语言智能体的六年。他从一款文字游戏讲起。模型可以把游戏打通，换一个世界却又得从头学。如果把它交给网店顾客、程序员或刚换工作的同事，谁来说明要做什么，又凭什么判断它学会了？同一个问题贯穿了他的研究经历、产品判断和选题方法。

从文字游戏到真实工作

00:02:58 为什么会从视觉走到文字游戏？

主持人从文章里读出反叛，姚顺雨却把自己的前 28 年形容为按部就班。他从合肥考入清华，2015 年进姚班，2019 年去普林斯顿读博，2024 年毕业后进 OpenAI。转向发生在这条路径内部。2016 年李建课上的演示让他看到，词和图像都可以用向量表示。2018 年在 MIT 做视觉研究时，他开始怀疑仅靠视觉能否做出通用智能。普林斯顿以计算机视觉方向录取了他，他却主动去找做语言的老师。

导师 Karthik Narasimhan 早年用循环神经网络玩小型文字游戏。姚顺雨问，换上已经读过大量文本的 GPT-2，会不会学得更快？当时用 BERT 判断句子褒贬或从几个选项中作答很合理，游戏里的下一步却可能是任何一句指令。能生成动作解决了一道难题，Zork 又暴露了另一道难题。反复训练可以通关，换个游戏，原来那套动作未必有用。

他和导师在 2021 年讨论重新把互联网当作实验环境，次年做出了 WebShop。用户描述想买的商品，智能体要搜索、翻页、选择款式，再在模拟商店里下单。到这里解决的是“在哪里做什么”。GPT-3 和思维链提示带来了另一种机会，团队做了 ReAct，让模型在行动之间写下推理，依据新的观察调整下一步。

谈到初入陌生环境为什么需要推理，他用暗房解释这个动机。初到陌生游戏，看到四周漆黑，人会想到可能有怪物，再想起灯在身后，于是先往回走开灯。环境返回的新情况决定接下来做什么。这个例子解释了为什么同一种推理与行动的办法有机会跨环境，也解释了他为何偏爱简单方法。他见过为一种问答任务把检索和上下文拼得很精细的系统，每换一道任务，整套做法就可能得重搭。当时学界甚至质疑设计提示能否算研究。主持人问 ReAct 是否标志范式变革，他愿意再等五到十年判断。

00:17:50 “智能体”指什么，能力该怎样分？

按较宽的定义，能自行决策、与环境交互并争取奖励的系统就可以叫智能体，围棋程序和自动驾驶都是例子。在自然语言处理中，这个词还强调模型能走出对话，调用计算器、上网或操作工具。姚顺雨用两条线回顾它的历史。专家系统靠人写规则，心脏病规则即使很细也帮不了诊治肺病。深度强化学习（RL）让系统靠反复尝试掌握围棋、Dota 等游戏，成绩仍依赖那个游戏。到语言模型这一波，既有了可跨场景使用的语言知识和推理，也换成了购物、编程、操作电脑等数字环境。

主持人引入从聊天、推理、代理，到创新者、组织者的五级说法。他能理解前三步的联系，也把 ReAct 看作一种常用的通用起点。专门任务仍可以设计自己的工作流程。至于让一个系统凭自己的奖励探索，和让多个智能体协作成组织，他认为两件事可以并行，无法排定谁必须先到。被问到该优先提升哪项能力时，他说自己还没有满意的分类，个人最看重的是处理上下文和记忆，以便系统从后续经历中继续学习。

00:29:47 代码给了模型一双“手”，怎样知道问题解决了？

网页和小说原本写给人读，代码却是机器可以直接执行的东西。姚顺雨说它好比人的手，手能用笔和筷子，代码也让数字智能体有了做事的手段。早期的代码题往往只让模型一次写出答案，姚顺雨在 2022 年就想，为什么不把执行结果送回模型再试？他参与的 InterCode 将运行结果作为下一轮观察。另两个团队项目分工不同。SWE-bench 从真实 GitHub issue 和对应修复构造任务，用测试检验改动。SWE-agent 则给模型提供浏览仓库、编辑文件和运行测试的操作界面。往更多软件走，有的有 API，有的只有图形界面。他用修路和造车作比，两端都可以改进。

主持人追问，模型会了代码和上网，怎样排除它在预训练中已经见过这些能力？他承认这种解释可能成立。他最在意的迁移，是在一个环境中练出的思考方法能否帮到另一个环境。主持人设想的“2027 年最强软件工程师”和“能做电脑手机上 95% 或 99% 的任务”，也需要先说清任务是什么。一个人入职要先弄懂同事想要什么。模型推理再强，工作上若缺了这层背景，仍可能交错东西。这个瓶颈属于智能、产品设计还是别的环节，他当时没有定论。

《The Second Half》的起点是准备斯坦福的演讲。在 OpenAI 工作约半年，加上此前做研究的经验，让他觉得语言、推理和行动这条主线已经有了可复用的方法，任务和评估因而变得更重要。他特意把这句话限在这条主线，语音、多模态和机器人仍有方法上的难题。

设计 WebShop 时，费心之处是同时满足三个要求。任务值得做，难度合适，结果又能按清楚的规则计分。项目页上的一条真实指令要求找快拆替换表带，配蓝绿色 Fitbit，价格低于 40 美元。搜索词可以换，商品页可以多看，验收看最终买了什么、满足了哪些属性和选项、有没有超预算。姚顺雨个人偏好按结果算奖励。若把过程写得漂亮当作分数，模型交出来的代码完全可能很好看，却没有修好用户遇到的问题。

00:42:14 客服要次次可靠，难题可以百中取一

人会按资历或收入给工作排序，这个顺序搬到机器上容易失真。软件工程有执行环境和测试，相比之下，客服每次都要懂用户、守业务规则、正确操作。姚顺雨举例，客服做一百次，可能要求至少九十九次不出错。证明一道难题或写一部剧本，试一百次，只要有一份真正出色的结果就有价值。

这给出了两个不同的统计问题。pass@k 看同一任务试 k 次，至少一次成功的概率。团队在 τ-bench 中提出的 pass^k 看 k 次全部成功的概率。该基准让模拟用户和客服对话，并将会话结束后后台数据库的状态与目标状态对照。单看一次成功率，读者看不出系统是否经得起反复托付。

他又区分了深度和广度。修改一处文件也许只花三秒，要维持三小时或三天的任务就得记住前面的决定。修一个 bug 与从头做出 Windows 的差别还涉及工作范围，一个团队要分工、交换进度。需要记多久、需要多少人协作、能否容忍失败，是分别要回答的问题。

00:48:38 模型能力增长，谁能做出新的产品？

创业者担心基础模型把自己的产品功能做掉。姚顺雨反问，底层模型若完全没有超出既有产品的能力，新公司又靠什么起步？机会要满足两个条件。模型继续变强，创业者还为这种能力找到另一种用法。Cursor 直接在用户正在写的代码上补全、修改，人平时很少像这样与另一个人说话。仿照电影《Her》的助理可以很有价值，他也想象过从 Canvas 再走一步，根据眼前的任务和使用者的习惯生成合适的界面。

已有超级应用给公司带来用户，也牵引下一轮研究。搜索公司很自然会先用新模型改搜索，拥有 ChatGPT 的团队也会围绕聊天产品配置训练和组织。这个惯性给其他交互方式留下机会，窗口能开多久取决于底层进步和产品本身。

00:54:08 用户的每次操作，都能用来把模型训好吗？

编程中的思考轨迹、Canvas 或 Artifacts 上的操作会不会形成数据飞轮，是主持人提出的猜想。姚顺雨的观察更保守。当时许多应用的进步仍来自基础模型升级。要让一轮用户使用改进下一轮服务，公司得能训练模型，能从交互中分清好坏，而且那项改进最好能保留下来。如果大厂也都在主攻同一能力，新一代基模可能抹平优势。

他用 Midjourney 解释，奖励是否合适取决于产品要提供什么。程序写得讨喜却运行错误，喜好分就奖励错了。画图产品恰好要做出人喜欢的图，用户选哪张图就能成为有用的训练信号。假设自己管理 Cursor，他愿意尝试训练模型。是否值得从头预训练，还取决于开闭源模型之间的差距、公司能补多少以及手里的资源。

00:56:46 入职一周以后，系统能多知道些什么？

主持人问，具备推理与行动能力的“数字实习生”往前还能做什么。姚顺雨区分发明新事物和组织许多人做事，前者未必很快得到外界肯定，后者还需要协调分工。主持人顺着问，长期记忆离突破还有多远。姚顺雨从实际工作解释它的价值。入职七天后，人从同事和工作习惯里学到了一批没有写进文档的东西，第二周做事已经不同。即使组织用了 Google Docs 或 Notion，也没有哪份文件能替新人装下这些背景。他怀疑这能解释一部分模型考试很强、产生的经济价值却有限的落差。系统怎样从这七天中改进，可能靠更新权重，也可能靠文字形式或其他形式的记忆。他相信值得做，没给出路线和日期。

01:02:45 没有人给分，为什么还要继续做？

同一段讨论里，他举怀尔斯证明费马大定理为例。证明尚未完成时，外界无法每天告诉研究者今天走对了几步，但人仍能继续。婴儿把玩具放到嘴里，也没有薪水或奖品，好奇、掌控感或安全感都可能促成探索。成人要弄懂一家公司怎么运作，所得反馈往往来自语言和社会关系。怎样在这种开放环境里定义能引导探索的内在奖励，他把它留作研究难题。

01:05:01 人会做而机器还不会的事

姚顺雨在 MIT 接触认知科学，留下的习惯是先看看人会做而机器还不会做什么，例如从很少的经验中学会一件事。把差距观察清楚以后，工程上可以另找办法。海马体和视觉皮层提供了研究线索，究竟要借用多少生理细节，取决于工程问题。主持人问智能体是否应该更像人。他按用途回答，下棋可以超过人，在公司里适应工作却是人做得更好。孤独者可能需要像朋友的交互，做推荐的平台未必需要一张人的脸。

给智能体发身份证，或按智能合约给它分配报酬，都是提问方推进的设想。他自认对加密技术了解不多，转而提出另一个问题。一个社会网络可以既有资源集中的中心，又给边缘的人进入中心的机会。资源集中多少、位置变动有多容易，和后来谈到的行业及交互方式有多丰富，是三件事。他认为历史上可以同时出现集中和流动，对未来的走势留有余地。

01:13:53 GPT 曾经也需要有人愿意下注

主持人把 Gym、World of Bits、Universe 等项目串到 GPT，问 OpenAI 是怎样换方向的。姚顺雨 2024 年才入职，明确说接下来是自己的归纳和推测。他转述导师的经历。导师是 GPT-1 的第二作者，对当时看起来并不突出的成绩是否值得投入那么多算力有疑虑，Ilya Sutskever 却主张继续扩大规模。同一项工作连参与者之间也会有分歧，推进它只需要有一批人愿意押注。在他的理解里，给 GPT 更多资源时，仍有人研究强化学习。他提及的七八成是说明资源可以有侧重的假设比例。到 ChatGPT，人类反馈强化学习又成了把模型做成产品的一个环节。

被问到下一次扩大计算规模会发生在哪里，他想到两种可能。有记忆的系统可以把更多计算花在一段持续的经历中，多智能体也可以扩大协作规模。该把资源花在哪一处，要看应用。谈到为什么觉得强化学习终于能泛化，他把语言视作跨任务交流和推理的工具，把数学或代码训练之后在创意写作上也有进步视为线索。主持人拿 Dota 反问，练好一个游戏会不会自动擅长所有游戏？他没有作这个保证。两项任务的性质会影响迁移，数学和代码也可能只是因为较早有清楚的评分办法，才先被研究。

01:23:26 产品的用处足以付它的账单吗？

主持人转述创业者的估算，单用户的智能体可能比聊天机器人多消耗 500 到 1,000 倍 token。姚顺雨用假设的账来回答。若花 500 美元能创造 1,000 美元的价值，成本就可能站得住脚。简单任务可以专门训练小模型，困难任务也许值得调用大模型。至于创始人是否必须做过研究，他说要看人。技术太熟也可能使人先挑方法、再四处找问题。

谈 Manus 和 Genspark 时，他只试过前者。大厂会借鉴创业公司的交互，创业公司也借助大厂训练的能力。一个通用入口可以靠某个具体应用在一个阶段吸引用户，他以 iPhone、iPad 与早期应用的关系为例。谈 DeepSeek，他认为把较长的思考过程展示出来，可能让普通用户更直观地察觉到产品体验的变化。成功另有工程、组织等因素。做开放模型也需要集中的资金、人才和能维持投入的理由，不能直接套用许多人分别为 Linux 贡献代码的经验。

再被问到“最强的智能体”，他追问在哪种关系里算强。作为朋友，有人甚至希望对方会忘事、偶尔出错。模型可以共享，各人手中的工作经验和信息却不同，有人会愿意让自己的智能体直接与别人的智能体交换信息。与此同时，大平台也有动力把计算和入口收拢。像 Google 一样占据重要位置，和由一家公司包揽所有交互，是两种可能的未来。

01:40:13 反复测“入职第一天”，能测出成长吗？

即便两家的模型很接近，只有一家记得某个用户以前怎么做事，它也可能更好用。主持人顺着这个判断追问 ChatGPT 的记忆更新提示到底改了什么。他说自己最近很少用这个功能，对内部细节了解有限，从过去对话中找回更相关的内容只是他的猜测。主持人又问，MCP 这类把模型连接到外部软件的协议，是否也能触及记忆。他借读冯·诺依曼《The Computer and the Brain》的体会来说明，缓存之外还有内存、硬盘，再往外还可以插上 U 盘。人也会把事情记进笔记本和共享文档。环境保存了系统下次仍能读取的状态。

长上下文是实现长期记忆的一种办法。问到线性、稀疏或混合架构，他把注意力拉回测试本身。往长文中插一句话再要求找回，是“大海捞针”式检索，命中只能说明这条信息找得到。在真正的工作里，即使没人事先写好正确答案，也得弄清什么结果有用。

把 500 道任务分别从头运行再平均，评到的是许多个第一次。姚顺雨打了个比方，把一个人放进 100 个平行世界看入职第一天，仍然看不出他在同一家公司做到第三十天、一年后会怎样。他在文章里用工程师举例。同一个人接着修同一仓库的问题会越来越熟，每道 issue 都重新开局的智能体便失去了这种机会。这里测的是上一件工作有没有帮助下一件，与 τ-bench 重做同一题测可靠性是两个问题。

01:47:27 两条产品路线和两种接口

说到好的产品经理，他关心的是用户的需求，以及从需求反推要用哪种技术。听创业类访谈给过他另一个角度，例如一家公司越成功，早期让出的股权可能越昂贵。对自己创业，他只说愿意考虑，想先找到值得做的问题。

从 2025 年 5 月向后看十二到二十四个月，他预期两条路线可以同时走。一条从聊天入口扩展出能动手的助理，如给 Operator 或 Deep Research 单独的远程工作环境。另一条把协作助手带进用户已有的本地软件。即使创业团队无法训练基模，也能改进两处接口。智能体怎样在软件里行动，人又怎样把意图和上下文交给它。短期他倾向于若干超级应用各建基础设施。两年之后，他认为变化太快，难作具体预测。

01:54:00 预训练与强化学习，什么时候值得自己做？

谈话回到“为什么现在算中场”。姚顺雨想到从前各做翻译、问答、代码的研究者很少有共同方法，如今可以在许多数字任务上采用相近的训练和推理方式。他用牛顿力学作类比，强调统一描述背后有先前一系列积累。他谈的是研究重心的变化。

预训练让模型先懂语言，再去环境里试错。理论上给定清楚的奖励、足够样本且训练测试分布相同，从零开始反复尝试也许能学会。现实里所需样本可能大到用不起。在一个封闭推荐场景，数据多、反馈清楚，直接优化就可能有价值。要适应一家陌生公司的工作，先验知识和继续学习的能力就重要得多。要不要自己预训练，还得算相对现有开源模型和 API 多创造的价值是否值得成本。

02:00:09 五百亿美元的假设，以及微信可以等多久

主持人先让他代入一家没有明确 AI 战略的大公司。姚顺雨会先学到自己能判断技术，再问有哪些现成场景和资源可以为用户创造新价值。接着是假设他执掌伯克希尔，有 500 亿美元可以配置。他看好模型层，也看好能取得特殊环境或持续积累用户上下文的组织。理由有个条件。若模型智能逐渐便宜而普及，独有关系和环境的相对价值才会凸显。他没有分配具体金额。

同样是掌舵者，假设换成微信负责人，他愿意先观察新交互。熟人、顾客和专业服务者已经在这里建立了关系，以相似方式做小改进，早一点晚一点差距可能不大。可当年威胁 QQ 的恰是长得不一样的微信。如果未来职业交往或友谊大量发生在人与智能体之间，而且这些关系在别处建立，原网络究竟值多少就需要重新判断。

主持人把问题从平台责任推到 AGI 的安全，对话中也出现了给 AI 制定宪法的设想。姚顺雨从两种具体责任谈起。一个会误删用户资料的产品很难留住用户，商业上已有动力防这种错误。他对这类有直接利害的安全问题较乐观。公司对整个社会还负有多大责任，访谈时他认为问题本身尚待界定，自己也会担心。问到意识，他把问题留在定义上。一个持续处理复杂上下文、能自主选择行动且选择会产生不同后果的系统，是否就算有意识？他提出这种可能，当时没有定论。

02:09:02 有了方法的直觉，找什么任务来检验？

被问到近一年想通了什么，他说让自己改变看法的是技术的用途比现有产品更广，几种不同的超级应用可能共同决定研究的边界。主持人接着问 Deep Research 是否根据演讲稿写了《The Second Half》。姚顺雨说它给了自己一个可以起笔的草稿。引言改得少，后面的段落删繁就简。他估计自己重写花了约两小时。回看博士工作，他认准两个方向，简单、可跨任务的方法，以及真实数字世界里做了会有用的任务。只在自然语言处理或只在强化学习圈子里找例子，就不容易同时想到用问答和游戏来检验同一套方法。

回到 ReAct，他说难点是手上只有当时的 GPT-3、PaLM 这一代模型，该到哪里找能显示“推理加行动”有用的早期信号。ReAct 团队在知识问答和事实核查中让模型查资料，也在 WebShop 等互动环境中让行动改变下一步观察。做 Tree of Thoughts 时，他又遇到同样的选题困难。翻译天然需要在输入序列里注意不同位置，一个任务可以催生通用方法。他自己的经历常沿另一方向走，先相信一种方法可能通用，再找到既做得动、又真能检验这个想法的任务。他把这种匹配称为 method–task fit。

被问最想设计什么任务，他说在普林斯顿时会想到能否做出一位提出新理论的科学家。到了公司里，他开始同样好奇一个组织怎样持续创造产品和价值，股份制等组织办法甚至能帮助许多不同的公司组织起人和资本。因此创办大公司与提出新理论，很难排谁更难。这也回答了前面的五级问题。在机会特别大的时候，他个人倾向选择上限更高的问题。若没有那样的机会，渐进地积累也可能更合适。

02:19:27 为什么押韵的歌词也是一道好题？

说起成长，他读数学也读历史，参加信息学竞赛拿过全国银牌，仍觉得一个人能懂的只是人类知识的一小部分。主持人从他在清华做说唱社的经历问起。他想起 GPT-3 刚出现时，自己就试过让它写既押韵又有内容的词。押对韵脚容易检查，听起来顺不顺、节奏有没有自己的味道却很难量化。同一种唱法出现太多次，原本的新鲜感还会消失。人的歌词也来自各自真实的生活。

这又带回了语言为什么通用。专门表示可以在围棋这样的单个领域效率更高，语言的长处是让一个任务中的知识能被讲给另一个人、用到别的事上。他猜测机器也能发明语言，但已有知识和人们理解、监督系统的需要，仍会使英语或基于英语的表示有吸引力。

谈个人动力时，他更愿意探索一种即使失败也不同的产品形态。导师曾劝他，既然别人已经能做一件事，也可以让别人去做。他也承认，若有办法做得更好、更快，继续投入同一问题是有理由的。对编码方向，他觉得展示最初的可行信号本身就有价值。对创业者，他仍问能为用户增加什么价值。主持人追问他正在押注什么，他没有透露具体项目。

片尾快问快答里，他提到喜欢椰子和伊斯坦布尔，推荐《智能简史》和传记，拿动物与交通工具的左右对称谈移动。被请挑一篇最重要的 AI 论文时，他依次说到反向传播、Transformer 和 GPT，强调成果靠累积。被问当下最重要的下注，他回到不同的交互方式可能孕育多个超级应用。他对自己是否记对 MBTI 的字母也没把握，随后节目收尾。

本文解读｜怎样衡量智能体在实际工作中的进步

姚顺雨在《The Second Half》把问题从“怎样训练模型解决给定的 X”推到“X 值得解决吗，什么算进步”。文章强调评测设置与现实不一致，访谈又补了一条具体解释。员工能从相处中取得本地知识，模型可能一直处在新人第一天。若只提高考试难度，两种差距都可能被遮住。

上半场

发明方法与模型，围绕 benchmark 迭代，任务常被当作固定容器。

下半场

寻找值得做的现实任务，设计环境和评价，让模型能力转成持续效用。

被忽略的变量

人和组织的上下文、长期记忆、内在奖励、交互形式与责任边界。

从任务说明到验收以退货为例，用户希望退哪件商品，账户与退货规则允许什么，结束后订单和退款状态应该怎样，都要对得上。客服可以说得很礼貌，同时退错订单。这是本文的例子。只按聊天印象打分，会漏掉用户实际承担的损失。

代码为什么能帮助验证。模型把意图写成可执行的修改，测试和执行结果又回到下一轮。在其他领域寻找相似的反馈，需要先查明结果能否观察、与用户目标是否一致。

一个任务里的成功，带到了哪里？

本文把可能的迁移拆成下面三种，第三种尤其容易与前两种混淆。代码写对了，能否弄清新团队的审批条件，仍要另测。

知识迁移

模型把先验事实带到新任务，减少冷启动成本。

策略迁移

模型把“如何分解、试验、检查、恢复”的方法带到新环境。

规格迁移

模型理解新环境的目标、限制和成功定义，而不是只复用旧答案。

从节目里的两个指标，推到实际验收

以一个假设的算例说明。设同一任务每次成功率都是 90%，且三次尝试相互独立。三次至少成功一次的概率是 1 − 0.1³ = 99.9%，三次全成功的概率是 0.9³ = 72.9%。前一个适合能从候选中挑出正确答案的场景，后一个关心反复交付。真实运行中的错误可能相关，不能把这组数直接搬到客服业务。下面的工程指标是本文据此提出的检查项。

任务维度典型目标不应只看更好的指标方向
可靠性客服、支付、合规、重复流程一次成功率或 pass@1pass^k、尾部错误、不可逆损失、人工接管率。
创造性难代码、数学、剧本、研究假设每次都正确pass@k、候选质量、搜索成本和人类筛选价值。
深度长周期研究、长期维护、组织项目短任务 benchmark状态恢复、记忆保真、目标漂移、跨阶段完成率。
广度跨软件、跨团队、跨组织的任务单一环境分数环境迁移、权限适配、上下文获取与责任追踪。

怎么检验一种交互是否能积累优势？

旧界面 + 新模型

容易被平台复制；若只是把通用能力包装成同类助手，差异会迅速消失。

新界面 + 能力溢出

把模型尚未被产品化的能力变成新的工作环境，可能形成短期窗口。

本文将数据反馈拆成四个可以逐项核查的条件。即使四项齐备，若新一代基模很快也能做得一样好，先积累数据的公司仍可能失去优势。

可观测任务

知道用户真正要完成什么。

可信反馈

能分开成功、失败和偶然满意。

可训练模型

产品有能力把反馈写回策略或模型。

价值对齐

模型变好会让用户和公司都受益。

三个仍可检验的问题

本文设想的记忆测试让 Agent 进入一个新团队，给它一周真实任务，再测它能否解释隐性规则、避免过去的错误、在工具更换后恢复工作，并指出哪些结论来自自己的经历、哪些来自文档。这个测试比单纯增加 context length 更接近 utility。

对没有即时外部反馈的探索，本文会先对比两种奖励。一种只计接触了多少新状态，另一种计是否排除了可检验的假设。随后另测任务完成质量，查明它们是否只奖了忙碌。嘉宾没有给出这套实现。

谁拥有和迁移记忆如果平台持有模型、上下文、身份和交易入口，人人拥有 Agent 也可能只是人人租用同一套基础设施。民主化要问的是谁能训练、谁能迁移记忆、谁能获得收益、谁承担错误，而不只是有没有访问按钮。

本文的八个判断

  1. “下半场”首先改变评估方式。 当更多基准都能用相近方法解决，新任务要让人看清哪种进步会改善实际工作。
  2. 上下文缺失是效用差距的一种解释。 比较同一模型初来乍到与熟悉环境后的交付，才有机会把这种收益同推理能力、权限或产品界面的影响区分开。
  3. 可靠性和候选质量要分别测。 能先筛选再交付的研究任务可能从多试几次中受益，每次都要服务真实用户的系统还须记录失败造成的代价。
  4. 交互方式是创业公司的短期护城河。 模型溢出能力只有进入新界面、工作区或社会关系，才会形成新产品；旧界面容易被 Super App 吸收。
  5. 数据飞轮的核心不是数据量，而是 reward 对齐。 没有清晰反馈，更多使用只会生产更多噪声和行为记录。
  6. 环境是记忆层，也是价值层。 外部工具、文档、组织和网络保存了模型没有的上下文；谁控制环境，谁就可能控制长期效用。
  7. 资源集中、流动机会、应用多样性可以分开观察。 基础模型供应者变少时，边缘团队进入市场的成本可能上升也可能下降，还须看用户和组织能否迁移自己的上下文。
  8. 选任务的方向可以相反。 翻译问题启发注意力方法，ReAct 则从方法直觉出发寻找实验。选一个能把它和更简单办法区分开的任务，比找到一个演示成功的故事更有说服力。

如何证伪这套判断

  • 若同一模型在目标、工具权限与训练投入可比时，保留历史和每次重开在后续任务上表现相同，就削弱了“工作上下文是该场景主要瓶颈”的解释。
  • 若单一 benchmark 与真实业务价值长期高度相关，“重新思考评估”的紧迫性会被高估。
  • 若通用 ChatGPT 界面能吸收所有新交互而不牺牲体验，创业公司的 interface moat 会变薄。
  • 若用户使用数据不能改善模型或产品，数据飞轮只是叙事。
  • 若多数看似独立的应用都无法脱离同一平台的用户资料与权限，就需要下调本文对应用之间可持续竞争的判断。
