invoko.ai 创始人梦琪：从垂直 Agent 的误判到重新相信软件

本期背景与内容导览

这期发布于 2026 年 5 月 23 日的对谈，核心不是一套适用于所有 AI 公司的创业定律，而是梦琪对自己创业约一年的复盘。她曾做过 to B 解决方案、TikTok 的 to C 业务，也做过一年 HR；主持人曲凯则以“字节背景、组队融资、追随 Agent 热点并不断 pivot”概括她所代表的一类创业者。这个概括属于主持人的观察，不应替代梦琪对自己经历的叙述。 梦琪先复盘达人营销 Sourcing Agent：为了避开通用 Agent 竞争选择垂直场景，为了沉淀专家经验不断吸收专业用户的需求，结果产品长成传统 SaaS；随后发现找人只占价值链的一部分，转而向增长全链路做深，又遇到客户不亲自使用产品、团队靠服务交付的困境。她由此产生“多数垂直 Agent 不成立”的强判断，但这个结论来自她所在的公司、接触到的同行和赴美调研，不是对全部垂直软件的事实判定。她把停止 to B 还解释为个人选择：这门生意没有给她足够的兴奋感，也未能让她看到客户问题被模型能力提升十倍、二十倍解决的可能。 转向 C 端后，浏览器插件 Clicker 和后续桌面客户端给了她不同的反馈：一个按钮可以减少截图、切换应用、写 prompt、复制结果的步骤；隐私说明漫画、Reddit 用研和大量版本修复则让“体验”变成具体工作。她并未在节目中给出足以证明产品成功的留存、收入或用户规模，因而“跑出曙光”应理解为积极用户反馈与她个人信心的恢复。后来她又在自身增长需求中做出达人营销 skill，并尝试用 multi-agent 流转内部研发问题；前者开始带来收入，后者仍是内部流程探索。 这期最有价值的部分，是她保留了对自我的尖锐批评：早期招聘科学家、讲训练叙事、追逐“数字员工”和新交互概念，都夹杂着想融资、想证明聪明的虚荣心。她最终没有把乐观建立在“AI 不够强”上，而是建立在生成软件之后仍需维护、用户采用程度参差、许多具体问题仍未解决之上。文末她对“创业是玄学”“不要太多左脑”“把 DAU 背后的人当人”的表达，是这一阶段的价值判断与自我解释，不能被改写成心理动机的客观诊断。

真正的低谷发生在她说“今年二三月”的时候，结合发布日期应为 2026 年。她连续提出三个竞争问题：产品与 Claude Code 有何区别？Claude 直接做这件事怎么办？生态里的开发者写个 skill 做同样功能怎么办？当时她找不到足够有说服力的差异化答案，甚至觉得做软件是“脑子进水”。这里记录的是她当时的焦虑，不宜写成所有软件都失去价值。

00:08:45–00:13:20复盘失败决策（一）：从垂直Agent到重走SaaS老路

  • 曲凯打断并评论：如今趋同的也许主要是叙事，Sourcing Agent 已被讲了很多年，但很少有人做出好结果。

梦琪按决策顺序复盘。第一步是在公司成立前选择 Vertical Agent，而不是挤进已有许多 Manus 类产品的 General Agent 市场。她想做 Sourcing，即“找人”：先帮助品牌寻找达人，再设想迁移到找候选人、专家和客户。这个计划把“搜索与筛选”当成可复用能力，但当时的逻辑自洽后来被她视为错误起点。曲凯中途补充自己的判断：趋同的主要是叙事，Sourcing Agent 已被讲了很多年，真正做出好结果的人很少。

产品做了两个月并上线后，反馈者分成两类。创始人这类非专业用户希望直接拿结果，不愿点击和管理中间步骤；负责达人营销的专业用户则要求可审计、逐步确认、自定义指标与筛选条件。团队当时相信“蒸馏专家知识”：先把专业人员的经验沉淀进产品，再服务非专业者。继续做了一两个月后，梦琪发现界面和流程越来越像八年前的 SaaS；公司又没有自有的高质量数据，只能依赖第三方 API，她觉得是在重走旧软件的路。

她用剪辑师作类比解释“专业用户并不自动带来 Agent 形态”：如果不断问专业剪辑师要什么，他会要求控制每个环节，直到产品接近 Adobe 才满意。这里的因果是她对自身产品的复盘，不等于所有专业工具都注定 SaaS 化，也不等于专业用户的审计需求没有价值。真正的问题是，这些需求与他们原先想交付完整结果的目标发生了冲突。

第三个误判是切入点。她估计 Sourcing 只占达人营销工作的约 30%，而后续反复沟通更耗时间；他们把 AI 容易做的部分当成入口，却没有覆盖最重的交付。团队曾想替代 Agency 的全部工作，实际却困在专业用户的过程需求里。到“10 月底”、做了三四个月时，他们已感到困境。按周年时间线，此处大致是 2025 年 10 月，但节目没有报出完整日期，应保留“按语境换算”的边界。

00:13:20–00:18:36复盘失败决策（二）：垂直Agent的结构性困局

  • “单场景喂不饱公司”是融资叙事需要，还是实际赚钱需要？为何不能先把一个点做到足够好？
  • 所谓扩张，是否意味着已经怀疑原方向，只是在延缓对原决策的否定？

团队意识到只找达人价值不够强后，开始考虑扩展到后续 Communication。曲凯追问“单场景喂不饱公司”究竟是融资叙事还是赚钱需求，梦琪回答当时就是想多挣钱；她又承认 Sourcing 的效果有百分之七八十取决于 API 数据质量，团队并不认为它是高价值点。曲凯于是提出一种解释：他们也许是在用扩张延缓否定原方向。梦琪没有完全接受这个心理化概括，而补充当时看到的是价值“强度不够 strong”，不是非 0 即 1 的能否成立。这个细微差别应保留，不能把主持人的推测写成她已确认的动机。

扩张有两条路：横向把“找人”复用到招聘、获客等场景，或纵向把达人营销与增长做深。梦琪认为后者是他们做对的决定。她用“面粉和鸡蛋”说明：大饼加鸡蛋与意大利面原料相同，不代表同一家店的顾客会同时购买；同样，会搜人不意味着找达人、找客户和找候选人的需求能交叉销售。她在测试中还观察到，最可能兼有多类需求的 founder 并不亲自使用产品，于是团队选择沿增长链路做深，开始尝试 GEO、Reddit 等动作，并与她称为“耳熟能详”的大客户合作。具体客户与效果均未在节目中披露。

做到“12 月”时，她形成更强烈的判断：大部分垂直 Agent 面临结构性困局。第一是客户并不亲自使用产品，创业公司为了收入不得不派人服务，逐渐成为 Agency；更极端的情况是，产品用来向投资人展示，真正收入来自服务，连内部服务人员也不用产品。她称之为“景观”。这是她对本公司与所见同行的批评，不应扩写为所有垂直 Agent 都靠人力伪造自动化。

第二是它仍然是一门 to B 生意：周期长，组织形态与她熟悉的年轻团队不同；她认为中国 to B 难做，华人团队在美国做 to B 也有明显天花板。她明确知道这句话可能挨骂，并说它来自一个多月调研。曲凯用“印度人来中国做 to B 也很难”表示理解，把它解释为跨文化销售与关系网络的困难。两人的观点都不是关于整个市场的统计结论；应保留为她的调研感受和创业约束。

00:18:36–00:22:48放弃to B，转向to C：在效率工具中寻找情绪价值

  • 当时大家都在谈专业个人用户等方向，为什么团队仍一直把它理解为 to B？

曲凯问她为何不走当时流行的专业个人用户路线。机器转录在这里出现“to procure”“pro seed”“OPC”等不稳文本，具体术语需要回听；可确定的是，梦琪反思团队把“某种个人化、专业用户趋势”与现实混在一起。他们曾设想：大量 AI 创业者缺流量，向他们销售增长 Agent 就像卖铲子。真正执行后，她发现独立开发者数量与支付能力都没有设想中充足：对方自己还没赚钱，就没有预算买增长服务；最有信息和工具能力的专业个人用户，也可能直接用好 Claude Code，不再需要一个中间产品。
