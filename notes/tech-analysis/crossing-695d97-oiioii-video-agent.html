闹闹：用视频 Agent 帮更多人做动画

访谈脉络：怎样让更多人做出动画

动画愿望先于这次创业

本期嘉宾闹闹创办视频 Agent 产品 OiiOii。她曾在腾讯微信事业群做 QQ 邮箱移动端产品，后来创业做极限运动内容社区，在字节负责过剪映及短视频特效相关工作，也在 B 站从事动画业务。她纠正主持人说法：自己当年做的是 QQ 邮箱，不是微信产品的核心负责人。

她说大学时就喜欢动画，曾在工作间隙学习插画和三维动画软件 Maya，却发现创作工具难用，也对行业收入与个人能力没有把握，最终没有直接成为动画创作者。她记得一位建模师工作多年、环境艰苦但谈到作品时依然很投入；这成为她对动画行业的一段印象，而非行业薪资的统计结论。

2022 年看到图像生成技术后，她开始想能否用 AI 帮普通人做动画；之后工作和项目也是在了解这个领域。录制时 OiiOii 公司成立约四个月、内测约一个月，她说当时尚无收入和利润，团队约十八九人，正在融资。这些是采访时的公司自述。

从首尾帧流水线切到新的模型

主持人问为什么选择 Agent。闹闹认为动画制作包含剧本、角色、分镜、画面、配音等多个步骤，系统可以调用不同能力并协作；同时自然语言界面可能降低操作门槛。这是团队的产品选择，不意味着所有动画任务都适合自主 Agent。

她描述最初的一条路线：如果要做八个镜头，先准备九张相邻首尾画面，再让视频模型按画面之间的变化生成片段，最后拼接。团队还尝试根据镜头需求选择不同模型，例如动作与人物情绪用各自较擅长的模型。她认为这种方式在单镜头稳定性上有优势，但仍要补配音、音乐和音效。

后来她看到 Sora 2 的动画样例，认为它生成多镜头、切换和镜头语言的表现更好，于是团队先暂停旧链路、转向新模型。她同时承认参考图加文本的方案在角色和场景一致性上仍有问题。她对模型训练素材的猜测及「看不出 AI 痕迹」属于个人体验，访谈没有公开模型训练数据或对照评分。

模型是食材，产品怎样「做菜」

被问模型越来越强会不会直接取代应用，闹闹把基础模型比作提供食材的超市，把面向特定用户的视频 Agent 比作餐馆。她认为用户可以自己组合原料，也可能需要产品针对某种内容完成搭配。她声称团队很多工作发生在用户看不见的调试层，但没有公开工时统计或严格比较。

以动画 MV 为例，用户可能只说「让几个人跳一段 K-pop」。团队会整理类似作品的镜头、节奏和音效经验，形成知识资料，再把简单要求扩展为模型可用的描述。她强调关键不是让用户写更长的提示，而是把某种创作经验转成可复用步骤。节目没有公布知识库内容和评测，无法判断这种方法在多大范围内优于直接调用基础模型。

她分享一次调试：早期主要用文字描述场景，跨镜头背景容易变化；后来加入场景参考图，一致性提升，却感觉场景过于固定、人物像贴在背景上。她用放辣椒过少、又加得太多作比喻。更稳定的外观和更自然的变化都可能有价值，需要结合具体作品而不是只优化一个指标。

到底服务谁：视频工作室、漫剧还是家庭

团队曾考虑漫剧，但她认为剧本能力、投流以及人工制作要求与团队当时的条件不完全匹配；也考虑过大规模用户内容社区，却担心社区规模和推理成本。于是初步选择小型内容工作室、动画 IP、音乐视频及用动画做历史科普的人，希望逐个理解他们的制作流程。

内测又出现意外使用者：漫剧团队不一定需要一键成片，先下载分镜再自己剪即可；没有视频经验的人希望用动画表达自己；还有家长给孩子、学生给老师、伴侣或宠物制作私人作品。主持人说自己为女儿做过圣诞歌曲 MV。闹闹由此看到内容不只是争取公共流量，也可以维系私人关系。

她说一些小工作室原本每周更新一集，使用产品后可能一天生成多集；这只是她提供的效率案例，没有给出时长、质量标准、人工修改和样本数，不能当成可推广的生产率倍数。团队希望逐步服务不同垂类，但她承认当时仍未把这些群体服务好。

四次架构调整：流水线如何允许人打断

Koji 问：自然语言很灵活，传统编辑器和固定流程却更可控，两者怎样兼得？闹闹说两个月内曾多次调整架构。第一版由语言模型自主决定任务交给谁，结果有时没有按预期交接；第二版固定所有步骤，又让用户难以中途修改；随后团队尝试在固定流程里设置信号，让系统按需退出、处理修改，再返回原流程；第四版继续处理跨流程切换。

她明确说后两版仍在调试：系统可能离开后忘记回来，也可能没有正确退出而继续执行。访谈并未透露信号格式、状态机或可靠性指标。这个案例的重点是，工作流中的自由修改需要记住当前做到哪一步，以及修改后哪些后续结果必须重新生成。

她还让剧本、角色等 Agent 以群聊式角色呈现，希望用户像导演一样与一个团队协作；表面角色背后可能还有其他助手。角色名称有助于说明分工，但角色多并不自动等于任务完成更好。

与剪映的关系：生成和精修可能连接起来

闹闹曾负责剪映，因此主持人问 OiiOii 会不会替代它。她认为生成动画可能带来新需求，也可能替代部分复杂特效制作，但用户仍可能把生成片段导入成熟工具，完成截断、排序、配音等精修。她特别举「只删掉末尾 0.1 秒」：直接拖动可能比重新用自然语言描述更快。

她说模型内生的镜头和转场能力进步后，某些原来依靠后期完成的工作可能减少；同时，模型生成的内容不一定足够可控，最终仍需编辑。这是对工作流演进的判断，节目没有提供统一基准或成本结果证明两者一定互补。

把「孤独」变成可以生成的镜头

为了让普通用户表达情绪，团队尝试把「孤独」「欢乐」等词连接到镜头、构图与色彩。她举例，孤独可能用长走廊和灰白色调表现；系统可以据此扩写画面描述，再生成候选素材。这样的映射是创作提示，不是孤独唯一正确的视觉表达。用户能否修改、能否保留个人故事，将决定工具是否只会重复刻板风格。

她承认当时高级创作者想加入更细致的个人意图时，产品自由度仍不足；部分用户做出的效果甚至超出团队预期。她希望工具成为让其他人表达的容器，而不是替每个人决定故事应该是什么。

微信与字节：直觉和数据如何结合

闹闹回忆早期在 QQ 邮箱工作时，要大量阅读用户反馈，观察用户真实行为，并练习分辨提出的功能要求背后的需求。她自己记不清是每天一百多条还是一千多条，不能把某个数字写成确定制度。

到了字节做特效，她看到数据策略的作用：观察谁常看特效视频、收藏或打开功能，估计谁可能愿意尝试新特效，先向更可能使用的人展示，帮助内容形成传播。她也提醒，把按钮放大可能改善点击指标，却不一定改善长期体验。她用「右脑、左脑」比喻两段经历的侧重，但并非两家公司只有直觉或只有数据。

她认为产品经理需要能暂时放下专家视角、理解新手，既自信又自省，并持续跟进技术能力。她自己不会写代码，但认为仍要知道技术能做什么、做不到什么，才能把能力连接到用户需求。

冲突、自由与未来产品

谈团队冲突时，她说不同团队围绕业务争论，有时能在共同解决问题后建立合作；她也回忆曾让一位好朋友离开团队，一年后对方换到类似负责人的位置才重新理解她。她称良性冲突可以激发做事，但也承认工作里的冲突常变成攻击；这个个人故事不证明每次冲突都会自然和解。

她回忆自己过去追求外在的自由和反抗，后来逐渐体验到安静也能带来力量。对于 2026 年，她预计视频质量、可编辑性和实时性继续发展，却提醒更多交互不一定吸引更广泛用户：主动互动可能增加操作成本，也可能满足特定创作者。她对多模型差异长期存在的判断仍是预测；产品最终是否能独立生存，要看用户需求和成本。

彩蛋中她没有按惯例凑满十个「我是」，说自己正在减少用身份标签固定自己，并希望 OiiOii 像容器一样让更多人讲述故事。节目以这个未完全确定的愿景结束。

机制拆解：用户中途改剧本时，系统要记住什么

假设用户要一个三镜头动画：①小猫出门，②遇见朋友，③一起回家。系统已经生成前两个镜头，用户突然说「把朋友改成小狗」。一个合理的流程需要先暂停，记录当前完成状态，再更新角色设定；第二个镜头需要重新生成，第三个还未生成的镜头也要使用新角色。第一个镜头如果没有出现朋友，也许可以保留。

如果系统只把新指令塞进对话，却没有更新角色档案和任务状态，重新开始时可能仍调用旧参考图；如果把所有步骤全部重做，则浪费时间和费用。需要保存的不是一句抽象的「记住上下文」，而是当前版本、每个镜头依赖的角色和素材、修改范围以及恢复点。访谈说明了这一类困难，示例不代表 OiiOii 的实际实现。

独立判断：餐馆有没有价值，取决于什么

模型变强不会自动消灭应用，也不会自动保护应用

如果基础模型直接生成更连贯的镜头，应用可能节省后期工作并覆盖更多任务；如果模型厂商同时提供相同的角色管理、编辑、分发和价格，用户也可能直接使用它。餐馆比喻解释了「组合和服务可能有价值」，但没有证明任何一家餐馆一定能生存。应对同一批创作任务比较成片质量、修改便利、费用和所需时间，并观察用户为何留下或迁移。

一致性和创作自由是可调节的，不应只选一头

固定参考图可以帮助保持角色或场景，但可能压缩模型的变化空间。可以在同一剧本上比较不使用参考图、只固定角色、固定角色和场景三种设置，由创作者分别评估角色一致、场景自然、情绪表达和修改成本。若结果显示某类内容需要较大变化，就不应把「越一致越好」写成通用目标。

从使用行为推断价值需要结合创作目的

一位家长做一个孩子愿意反复看的短片，价值可能来自关系和纪念；一位科普创作者则可能关心观点是否准确、每周能否稳定更新。两者都可能发布一个视频，但成功标准不同。用户生成数量、视频播放量和付费意愿应按目的分别解释，不能用单一活跃指标替代。
