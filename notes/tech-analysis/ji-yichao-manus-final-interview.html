季逸超谈 Manus：从下一代 Google 到云端 Agent 的环境、模型与用户

本期背景与内容导览

这次访谈录制于2025年12月1日、Manus 被收购前，是理解团队当时选择的一手材料。季逸超先回顾高中做软件出海、第二次创业追求“下一代 Google”却受通用模型冲击，说明自己为何转向不做 CEO、不急于自研模型、寻找合适合伙人的新起点。随后他解释 Manus 的核心不是再做一个浏览器，而是让 Agent 在云端隔离沙盒中执行真实任务：模型负责规划，环境负责运行工具与代码，用户任务和反馈负责检验结果。团队从 AI 原生浏览器的失败转向这一结构，是为了解决本地运行、长任务与环境不可控的问题。商业部分讨论非零推理成本、prosumer 高价值用户、通用 Agent 的长尾和统一上下文，以及应用公司如何通过真实使用、评测和反馈与上游模型厂商合作。最后涉及发布、定价、团队与“纯血派 Agent”的取舍。本文保留当时观点，不用后来收购结果倒推其必然性，也不把大客户地位或通用 Agent 当作永久护城河。

在节目开场，主持人张小珺介绍了本期节目的特殊性：录制于2025年12月1日，嘉宾为Manus联合创始人兼首席科学家季逸超（Peak），而就在节目录制后不久，Meta宣布全资收购Manus，使得这次访谈成为公司被收购前的最后一次。

在主持人邀请下，季逸超开始回顾自己的成长与创业经历。他将自己定位为“科技创业者”，认为这源于他独特的家庭背景：父亲是北大物理系教授，代表传统科学家；母亲是中关村的连续创业者。他自述从小并非传统意义上的聪明孩子，学习偏科，但很早就找到了自己喜欢做的事——捣鼓软件。

季逸超认为，他人生中一个重要的转折点是2009年苹果App Store的出现。在此之前，个人开发软件很难在全球范围内变现，这种爱好在高中生中显得“离经叛道”。App Store提供了一个平台，让他能通过经济价值向家人和老师证明自己爱好的正当性。他因此成为中国第一代“软件出海”的个人开发者，当时他还在读高中。

他的第一个产品是一款名为“猛犸浏览器”（Manus Web Browser）的第三方iOS浏览器。这款产品采用最朴素的“卖拷贝”（sell copy）商业模式，即每卖出一份软件就获得一份固定收入，维护成本较低。这款浏览器为他带来了总计超过30万美元的收入，这对于一个高中生而言是巨大的成功和正反馈。他提到，这种简单的商业模式在当时移动互联网从PC互联网过渡的“蛮荒期”是可行的，因为即便是大厂也和个人开发者一样在探索新平台，众生平等。他对比指出，如今的AI浪潮虽然是技术突破，但缺乏全新的硬件媒介或平台，导致巨头和创业者反应速度一样快，不存在类似的“蛮荒期”。

这段个人开发经历的结束并不明确，它更像是创业的起点。为了推广软件，他需要在国内外论坛发帖做营销。由于当时国内App Store支付渠道不成熟（仅支持国际信用卡），他甚至会自己破解软件发到国内论坛，以“赚吆喝”的方式积累人气。这一举动吸引了资本界的关注。高二时，他在中关村的一个创业活动上认识了真格基金的徐小平。徐小平问他是否想创业，他最初因拥有稳定的被动收入而犹豫。但在父母的鼓励下，他开始思考机会成本，认为读书的机会一直都在，而创业的机遇稍纵即逝。最终，他接受了真格基金的投资，并获得了“爱干嘛干嘛”的自由度承诺，随后辍学创业。他劝说两位已保送北大的学长加入，组建了团队。

团队成立时，他们已意识到“卖拷贝”模式将失效，市场会走向免费增值模式。为了给付费软件寻找新的功能突破点，结合当时3G网络环境下提升弱网体验的需求，季逸超提出了一个核心问题：能否预测用户的下一次点击，从而提前加载（preloading）内容，加快响应速度。这个需求引导他进入了自然语言处理（NLP）领域，也标志着他对浏览器的兴趣逐渐转移，最终导致“猛犸浏览器”因无人维护、系统不再兼容而“自然死亡”。他总结，这段经历让他幸运地在第一个产品中就集齐了“出海”、“AI”和“变现”三个要素。

卖拷贝 (sell copy)指一种软件销售模式，用户一次性付费购买软件的一个副本（copy）的使用权。这是早期软件行业，尤其是在应用商店初期常见的商业模式，与后来的订阅制、免费增值（Freemium）或应用内购买（In-app purchase）模式相对。
NLP (Natural Language Processing)自然语言处理，是人工智能和语言学领域的分支学科，旨在让计算机能够理解、解释和生成人类语言。在本段中，嘉宾因“预测用户下一次点击”的需求而接触该领域，并经历了其从传统方法到深度学习方法的演进。
Word2Vec2013年由Google团队提出的一个模型，用于从大量文本语料中学习单词的向量表示（词向量）。它的突破在于能高效地将离散的词语映射到一个连续的向量空间中，使得词语之间的语义关系（如相似性）可以通过向量运算来度量，是NLP进入深度学习时代的关键技术之一。
知识图谱 (Knowledge Graph)一种用图结构来表示现实世界实体（如人物、地点）及其之间关系（如出生于、工作于）的语义网络。在本段中，嘉宾的第二次创业试图通过自动构建知识图谱，来为语义搜索提供结构化的知识，以替代传统的网页链接列表。

主持人询问浏览器业务是否有机会做大，季逸超回顾说，当时收到过收购要约，但他认为浏览器产品本质上更适合拥有分发渠道的巨头，创业公司难以颠覆，因此即便以他现在的经验，也无法做出更好的选择。

随后，话题转向他的第二次创业。这次创业始于他对NLP领域的浓厚兴趣。他认为，2013年谷歌发布的Word2Vec论文是一个“石破天惊”的转折点，它能高效地将离散的自然语言文本转化为稠密的向量，使得深度学习方法可以更方便地应用于NLP。这让他意识到自己的真正兴趣在NLP，而非浏览器。在获得投资人真格基金的许可后，他转向了新的创业方向。

当时，受苹果即将发布可穿戴设备（后来的Apple Watch）传闻的启发，季逸超预见到传统“输入问题，返回十个链接”的搜索模式在小屏幕或语音界面上将不再适用。他设想通过一种更结构化、更紧凑的形式革新知识与用户的交互，即“语义搜索”（Semantic Search），并梦想着能像谷歌颠覆雅虎一样，成为“下一代的Google”。

为了实现这一目标，团队的技术路径层层深入。他们认为，要实现紧凑的问答，需要将非结构化的网页文本转化为结构化的知识图谱。然而，当时知识图谱的构建高度依赖人工编辑和专家标注（如Freebase、Wikidata），完备性是巨大瓶颈。于是，团队决定研发自动化构建知识图谱的技术。他们瞄准了“开放式信息提取”（Open Information Extraction, OpenIE）这一前沿方向，旨在让AI在阅读文本时，无需预设实体类型（schema-less），就能自动识别实体、提取关系，并持续构建知识图谱。这个项目被命名为Maggie。

从2014年到2018年，团队经历了NLP技术最剧烈的变革期。他们的技术方案从传统的依存句法分析，演进到基于Word2Vec的向量化方案，再到LSTM、LSTM+Attention。他们很早就遇到了多义词问题（如“孙悟空”在不同语境下的含义），并意识到需要上下文相关的编码方式。幸运的是，学术界相继出现了Transformer和BERT等技术，解决了这个问题；不幸的是，每一次技术迭代都意味着推翻重来。团队甚至从头预训练自己的模型（约两个0.3B模型），并为解决BERT 512个token的长度限制，自主研发了支持16K长文本的模型。他们还自建了从爬虫到搜索引擎的全套基础设施，并与英特尔合作，基于持久化内存（PMEM）技术自研了向量搜索引擎。季逸超称这段经历是自己智力、编程和研究能力的巅峰，花投资人的钱把自己想尝试的技术都做了一遍，人生夙愿得以圆满。

然而，这场技术苦旅在2019年戛然而止。当季逸超拿到GPT-3的早期访问权限时，他感到“天要塌了”。他用一个简单的Prompt，发现GPT-3在信息提取任务上的表现，竟与他们耗费数年、垂直优化的端到端模型“五五开”。他立刻意识到，GPT-3这样的通用大模型将统一NLP的各个垂直任务领域，他们这种“小作坊”式的垂直整合模式走到了尽头。他的第一反应是“赶紧卖掉公司”。

回顾这次创业的失败，季逸超认为有三点原因：

1. 产品层面：低估了搜索引擎的非技术壁垒，如数据源的合作生态，新玩家难以撼动Google的地位。

2. 时机层面：他们所期待的“下一代人机界面”（如可穿戴设备）并未如期成熟落地，“早十步成先烈”。

3. 商业层面：在To C和To B之间摇摆，团队基因与商业模式不匹配。

在第二次创业因GPT-3的出现而终止后，季逸超并未立刻开始第三次创业，而是选择去一家AI to B的独角兽公司工作了一年半。他形容这段经历“非常开心”，因为公司内部有一种独特的激励机制：算法研究员通过内部竞赛“打榜”，赢家可以获得更多的显卡资源。这形成了一种“强者恒强”的局面，他凭借出色的表现囤积了大量算力，可以自由地进行各种实验，长期霸榜第一，这与他学生时代不追求分数的表现形成对比。

这段工作经历之后，季逸超开始思考下一段创业的方向。经历了第二次创业中“垂直整合”的痛苦——每天都感觉被技术浪潮淹没，他明确了几个原则：

1. 不再做垂直整合：他将AI创业分为模型层、基础设施层和应用层，并决定放弃自己不擅长的模型层创业，将目光投向基础设施和应用层。

2. 不做CEO：他深刻反思后认识到自己不适合做CEO。他讨厌管理人，觉得与人打交道比与电脑打交道复杂得多；同时，他有追求“技术正道”的倾向，容易为了一个有趣的技术而牺牲商业目标，需要一个能“管住他”的合伙人。

在2022年底到2023年初，ChatGPT引爆市场后，季逸超与国内外几乎所有大模型公司都进行了交流，但没有一家能说服他加入。他认为当时大家对AI原生应用该是什么样并没有清晰的认知，所有人都是在“基于直觉下注”。他希望自己能更“正规”一点，像字节跳动一样用数据思维来驱动，而不是再次“因为相信，所以去做”。

他寻找的是一个有初步产品市场契合（PMF）但又像“空的画布”一样的产品，可以让他观察真实的用户行为。最终，他将目光锁定在肖弘（现Manus CEO）当时的产品Monica上。Monica是一款浏览器插件，季逸超认为其形态绝妙：

1. 无侵入性：它不改变用户原有的工作流（如使用Gmail、YouTube），因此可以无偏地观察用户行为。

2. 上下文分发：功能根据用户所在的网页上下文（context）出现，如在YouTube上出现视频理解功能，在Google Docs里出现写作辅助功能。这巧妙地解决了功能增加带来的产品复杂度爆炸问题。

他认为浏览器插件是观察用户如何使用AI的“绝妙窗口”和“空的容器”。

除了产品形态，更重要的是他找到了理想的CEO合伙人——肖弘。经过多次长谈，他发现肖弘具备一个在当时AI创始人中“非常稀缺的特质”：正常。他解释说，肖弘“身心健全，没有任何极端思想”，相信常识和团队，是一个能真正带领公司持续发展的领导者。这与许多“得了乔布斯的病，却没有乔布斯的命”的偏执型创始人形成鲜明对比，也包括他反思中的自己。最终，肖弘用一句话打动了他：“你想不想在一个产品里，把浏览器、搜索引擎、语言模型这三件事都重新做一遍？”

季逸超强调，他加入团队并非为了做已有的Monica，而是将Monica视为积累用户洞察和现金流的“学费”，团队的共同目标是利用这些观察去创造一个全新的事物，这便是后来的Manus。

3. 长任务与本地运行的矛盾：AI的价值在于执行人类不愿做的“长任务”（long-horizon task）。但如果AI在本地浏览器中长时间运行，用户就不能合上电脑，否则任务会中断。这使得用户被束缚在电脑前，无法解放注意力。

首先是“环境”的边界。季逸超认为环境是Agent最重要的部分，决定了它与外界交互的边界。Manus选择为每个会话（session）提供一个独立的、一次性的虚拟机沙盒作为最通用的环境。他澄清这并非给每个用户分配一台固定电脑，而是一种可大规模扩展（scale out）的“个人云计算”模式，让非程序员也能操作云计算。为了突破环境限制，Manus团队做了几项关键工作：

2. 跨平台虚拟化：为了不被Linux系统绑定（许多专业软件仅存在于Windows生态），团队选择了基于Firecracker的“全虚拟化”重路线，而非更简单的Docker容器技术，使得Manus现在也能使用Windows虚拟机。

3. 定制化环境：团队在维护一个专为Agent设计的Linux发行版，预装了许多只有Manus才知道如何使用的工具，极大地扩展了Agent的“动作空间”。

其次是“模型”的边界。尽管Manus不自研模型，但通过巨大的Token消耗量（在全球各模型厂商中排名前2到前5）获得了巨大的影响力，从而能作为“无形的大手”干预和影响模型厂商的研发方向。这笔高昂的成本通过产品盈利来覆盖，并且已接近收支平衡。季逸超指出，Agent的Token消耗模式与Chatbot截然不同：Chatbot的输入输出Token比例约为3:1，而Manus中这一比例高达100:1甚至1000:1。团队以“消耗更多token为荣”，因为这代表着更高的质量。

凭借这种影响力，Manus可以直接向Google DeepMind等合作伙伴提需求，帮助构建评估体系（evaluation），甚至主导新功能的开发（例如，Gemini的“可控并行函数调用”功能定义和schema就由季逸超编写）。他深入分析了当前模型存在的几个问题：

1. 为Chatbot对齐：现有模型多为对话场景优化，倾向于一次性回答复杂问题。而Agent需要的是逐步试错、根据观察调整下一步行动的“耐心”。这种不匹配导致模型在执行长链条任务时质量下降，并产生“上下文压力”（context pressure），过早地结束任务。

2. 缺乏压缩意识：他提出一个新观点，超过200K的上下文长度可能不再重要，更关键的是让模型具备“压缩意识”（compaction awareness），即学会将部分不重要的上下文信息外化（如存入文件）或压缩成紧凑表达，并理解这一过程，而不是无限增加上下文长度。

3. 推理模式错配：为数学竞赛等场景设计的“长思维链”（COT）推理模型，直接用于Agent时可能导致遵循指令能力下降和幻觉增加。Agent更需要的是“交错式思考”（interleaf thinking），即在每一步行动前进行短暂的中间推理，而非一次性进行长篇大论的“脑补”。

01:48:11–01:52:22从自动化测试到主观评价：Manus如何迭代模型

在主持人追问核心关注指标时，季逸超列举了几个维度。首先是模型的原子能力，包括三个方面：

1. 编程能力：虽然Manus不是纯粹的编程Agent，但编程是其“灵魂”，因此团队非常关注Sweepbench这类指标。

3. 广义的Tool Call（工具调用）能力：Manus的工具调用复杂度很高，它不仅有模型原生的函数调用，还能通过阅读文档学会使用系统中自定义的命令行工具。

除了这些可量化的原子能力，季逸超还强调了两个难以量化的重要指标：

1. 美学性：即产出物是否美观。

2. 对错误的自我意识：这分为两个层次。低维度的自我意识指模型在用户指出错误后修复bug的能力，而不是像很多AI工具那样，声称修复了却引入新bug。高维度的自我意识则是指模型能意识到产出物“从可用到好用”的差距，并主动优化。例如，Manus在生成网页后，可以自己用浏览器“玩一圈”，检查数据库记录是否正确，从而弥合“可用”与“好用”之间的差距。

Evaluation (评估)在本段中，指衡量AI Agent表现好坏的过程。它分为两种：一种是自动化的、可验证的Benchmark（基准测试），如Sweepbench，通过客观指标（如代码是否通过测试）来评分；另一种是主观评估（subjective evaluation），由人工（如专门的评估团队）根据“易用性”、“美学性”等主观感受进行打分。
Tool Call (工具调用)指AI模型调用外部工具或函数来完成特定任务的能力。在本段中，它是一个广义概念，不仅包括模型原生的函数调用（Function Calling），还包括模型通过阅读文档，学会在一个定制的操作系统环境中（如Manus的Linux发行版）使用命令行工具的能力。
Proactiveness (主动性)指Agent在没有用户明确指令的情况下，主动发起并完成任务的能力。它源于“Agency”（能动性）一词。在本段中，它被视为解决用户输入瓶颈的关键，即Agent通过观察用户的行为和上下文，预测需求并提前完成工作，将结果呈现给用户确认，而不是被动等待用户输入Prompt。
Prefilling & Decoding这是大型语言模型推理过程的两个阶段。Prefilling（预填充）指模型一次性处理全部输入（prompt），计算出初始的键值缓存（KV Cache）。Decoding（解码）指模型在此基础上，逐个生成输出token。在本段中，嘉宾指出，Agent应用的Prefilling与Decoding的token比例（如100:1）远高于聊天应用（如3:1），因为Agent在多轮交互中需要反复处理越来越长的上下文，导致算力消耗模式发生根本改变。

基于云端沙盒的通用Agent执行机制

该机制旨在为AI Agent提供一个安全、隔离、可扩展且功能强大的执行环境，以完成用户下达的复杂任务。

- 输入：用户通过自然语言下达一个复杂任务指令（Prompt），例如“帮我研究一下YC最近一批所有AI营销公司的CEO邮箱，并整理成表格”。

- 过程：

1. 环境创建：Manus系统为该任务动态创建一个或多个一次性的、隔离的云端虚拟机沙盒（VM Sandbox），每个沙盒都是一个完整的操作系统环境（如Linux）。

2. 任务拆解与规划：AI大模型（作为Agent的“大脑”）接收指令，将其拆解成一系列可执行的步骤，如“搜索YC官网”、“识别AI营销公司”、“访问公司网站”、“查找CEO信息”、“记录邮箱”等。

3. 环境内执行：Agent在沙盒环境中，像人类一样通过命令行、调用预置工具或编写执行脚本来完成每一步。它可以上网、读写文件、安装软件、运行代码。

4. 并行化（可选）：对于可并行的子任务（如研究多家公司），系统可以启动上百个沙盒并行处理（“广域研究”），大幅提升效率。

5. 观察与迭代：Agent执行每一步后，会“观察”环境的反馈（如命令输出、文件内容、网页截图），并根据观察结果调整下一步行动，形成“思考-行动-观察”的循环，直到任务完成。

- 输出：Agent将最终结果（如整理好的表格文件）交付给用户。

- 失败条件：1. 底层大模型的推理或规划能力不足，导致任务拆解错误或在某个步骤卡死。2. 目标网站有强大的人机验证（如CAPTCHA），Agent无法通过。3. 任务所需的特定工具在沙盒环境中无法安装或运行。4. 任务本身超出环境能力边界（如需要物理操作）。

“弱到强”的Agent框架评估与优化机制

这是一种用于衡量和改进Agent框架（而非模型本身）有效性的内部评估方法，旨在确保框架能最大化地利用未来更强模型带来的性能提升。

- 输入：一个固定的Agent框架、一个待评估的任务集，以及来自同一个模型家族的两个不同版本：一个“弱模型”（如基础版）和一个“强模型”（如Pro版）。

- 过程：

1. 基线测试：分别使用“弱模型”和“强模型”在固定的Agent框架下运行任务集，得到两组成绩（如任务成功率），计算出两者之间的性能差距（Delta）。

2. 框架调整：Agent团队对框架进行修改，例如优化Prompt结构、改进工具调用方式、调整记忆管理策略等。

3. 重复测试：使用调整后的新框架，再次用同样的“弱模型”和“强模型”运行任务集，得到新的两组成绩和新的性能差距（Delta'）。

4. 比较与决策：比较Delta'和Delta。如果Delta' > Delta，说明新框架更能放大强模型相对于弱模型的优势，即框架的“天花板”更高，这是一个好的改动。团队的目标就是通过不断迭代，找到能使这个性能差距最大化的框架设计。

- 输出：一个经过优化的、能够更好利用模型智能的Agent框架。

- 失败条件：1. 强弱模型之间的真实能力差距过小，导致Delta不明显，无法有效指导框架优化。2. 任务集的难度或类型不合适，无法区分出框架的优劣。3. 框架的改动引入了其他变量，导致性能差距的变化并非由框架本身引起。

Mask 而非删除用状态机限制工具选择，保持历史工具定义稳定。动态增删工具会破坏缓存并让模型混淆旧轨迹。
文件系统作为上下文把网页、计划、结果和长期状态外化为可恢复文件。窗口有上限，不能预先知道哪条观察未来会有用。
保留错误让失败动作、堆栈和环境错误留在轨迹中。错误是模型更新信念、避免重复失败的证据。

这些原则与 Manus 官方的 Context Engineering 文章相互印证，但仍应被看作生产经验而非普适定理。不同模型的缓存、工具调用和上下文退化曲线不同；对某一代理有效的序列化、噪声和复诵方式，可能在另一供应商上失效。

四、评价与数据飞轮：真正的 benchmark 是用户愿不愿意把任务交出去

季逸超介绍 RLI（Remote Labor Index）式思路：评价不是看模型是否生成了像人的答案，而是看它是否完成了用户愿意付费的工作。他把 Coding、浏览器/GUI、工具空间、美学、错误意识和恢复能力列为不同维度，并强调一次性成功与长程恢复应分开计量。

“完成率 2.5%”“未来 20–30%”等数字属于节目中的阶段性口径，不能当作独立基准。更稳妥的评价账本应同时记录：

结果

任务是否满足真实验收，用户是否愿意再次交付。

过程

人工介入、工具调用、失败类型、恢复路径与时间成本。

长期

跨任务迁移、记忆保真、维护成本、权限事故与客户留存。

用户“教”代理并不等于模型自动学习。很多反馈只是 on-policy 的局部修正，可能改善当前框架，却不能改变模型在新分布上的知识。必须区分产品配置、检索记忆、策略更新和参数学习，避免把所有数据都称为“自我进化”。

五、AI 更像制造业：推理成本、供应链与通用入口

Manus 把 AI 与互联网区分开：推理消耗算力和 token，规模越大并不意味着边际成本趋近于零，模型、GPU、缓存、沙盒和网络都像制造业的供应链。于是通用 Agent 的目标不是只做一个漂亮入口，而是把计算、环境、连接器和任务价值组合成可持续的单位经济。

在生态形态上，季逸超更看好“通用协调者连接垂直服务”的星形结构，而不是所有 Agent 彼此完全互联。一个中心节点负责理解用户和拆分任务，专业 Agent 提供能力；但中心化也带来单点故障、平台抽成与权限集中。真正的网络效应必须来自可迁移声誉、任务经验和互操作接口，而不是节点数量。

高价值工作是合理的首个市场专业人士更能定义目标、检查结果并承担责任，容易形成付费；但非专家往往有更强的未满足需求。产品需要在“能发现问题”和“能可靠完成”之间选择，而不能只用职业身份划分用户。

六、纯血 Agent 与小团队：少做功能是一种技术能力

季逸超警惕把 Agent 做成大量硬编码工作流：规则可以提高短期稳定性，却会限制模型发现更好的路径。他倾向于让智能在工具和环境中选择步骤，再通过约束动作空间、上下文设计和错误恢复降低风险。这不是放弃工程，而是把工程重点从“规定每一步”转到“规定边界、观察和可回退性”。

Manus 的组织分成 Sandbox、Agent、评估等小队，并刻意复用外部连接器，不与每个服务竞争。这个取舍很重要：Agent 公司若把所有功能都内建，会失去快速切换模型和环境的优势；若什么都不控制，又无法保证核心任务质量。最小产品边界必须由失败数据和用户愿意支付来决定。

该控制的部分

上下文结构、沙盒安全、任务评价、错误恢复、核心连接器。

该复用的部分

基础模型、通用服务、成熟协议、用户已经拥有的工作系统。

七、如何读“最后访谈”：结果不能替代方法

后续 Manus 加入 Meta 的公开公告显示，产品继续作为通用 Agent 服务并获得更大资源。这个结果可以帮助读者核对时间线，却不能证明所有早期选择都被市场验证。收购可能改变模型访问、分发、合规与资本约束，也可能让“保持模型无关”变成新的组织难题。

因此，本期真正可迁移的不是“最终卖给大厂”的创业故事，而是三种决策纪律：在基模变化快时保持架构可逆；把环境与错误当成一等数据；以高价值任务和可复用反馈，而不是功能数量或 DAU，定义产品进步。

核心判断：Agent 公司的壁垒是可逆的产品—环境—反馈系统

季逸超没有把 Manus 定义成“自己的大模型”，而是定义成一个在真实环境中完成长期任务的系统。它的壁垒由五个相互增强的部分组成：

可逆产品

模型可以替换，产品架构和交互可以在小时级迭代。

行动环境

云端虚拟机、文件系统、浏览器与工具让模型拥有“手”。

任务评价

完成质量、错误恢复与用户愿意支付比一次性 benchmark 更重要。

反馈飞轮

用户教代理、修复失败，系统把轨迹转成框架和模型选择策略。

组织接口

Sandbox、Agent、评估和产品小队共享上下文，同时刻意少做功能。

因此“通用”在这里不是营销词，而是一个架构选择：先把长尾任务交给统一框架，让模型、环境和用户共同发现哪些专业能力值得产品化。

进一步推演：这期访谈留下的九条 Insight

  1. Agent 公司的壁垒是“可逆性”。 能快速切换模型、工具和工作流，才能把基础模型进步变成自己的上升潮。
  2. 环境是模型的手，也是数据的传感器。 没有沙盒、文件、浏览器和错误，模型无法形成长程行动闭环。
  3. 错误恢复比一次成功更接近 Agent 性。 真正的工作世界必然有坏数据、权限拒绝和工具故障。
  4. Context Engineering 本质是状态治理。 缓存、外部文件、工具屏蔽和计划复诵都在回答“下一步保留什么”。
  5. 通用是长尾策略，不是功能清单。 统一框架只有在跨任务复用上下文和反馈时才有经济意义。
  6. AI 的制造业属性会重新定义规模。 推理成本、沙盒数量、延迟、并发与供应链比页面访问更接近真实毛利。
  7. 用户反馈要区分配置学习和参数学习。 “系统变好了”不等于“模型学会了”，更不等于跨分布泛化。
  8. 少做功能是组织能力。 复用连接器、保留边界、把资源集中到失败恢复，往往比堆集成更能提高可靠性。
  9. 收购结果不能抹掉当时的不确定性。 研究创业方法时，必须把事件发生前的选择、证据和风险保存下来。

怎样证伪或修正这套 Agent 公司论

  • 若用户可以无成本把记忆、工具和任务状态迁移到任何模型，产品环境的长期护城河会被削弱。
  • 若更强的模型直接解决错误恢复和长任务状态，Context Engineering 的边际价值可能下降。
  • 若结果型评价无法比 token/时间收费更好地预测续费，制造业式单位经济需要重新定义。
  • 若通用 Agent 的失败率始终高于垂直工作流，长尾策略不一定优于更窄的产品。
  • 若用户反馈无法改善跨任务表现，所谓数据飞轮只是局部个性化而非系统学习。
