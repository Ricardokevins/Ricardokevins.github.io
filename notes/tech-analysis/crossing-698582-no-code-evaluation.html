访谈脉络：无代码应用怎样从创意走到交付

嘉宾档案朱广翔，1993 年生（录制时 32 岁、快 33 岁，开场口误说成 22 岁），双鱼座，ENFP（「快乐小狗」）；清华大学交叉信息研究院强化学习方向博士。
任职与产品百度秒哒产品总经理；在百度 4 年带过 8 个团队，秒哒为第 8 个。一句话定位：「一句话做应用」，专注商业落地的无代码应用平台（海外版名 MeDo）。
收入口径「我们不看自己的 ARR，只看用户的 ARR。」
行业语境2026 年初 Vibe Coding（自然语言开发）进入下半场，赛道分化为服务程序员的 IDE 路线与以意图为中心、面向非程序员的 No Code 路线。

一、写代码二十年，然后「造一个车轮碾过自己」

朱广翔初中起写代码、整整写了二十年到博士毕业，工作没几年却转做产品经理，如今更做出「不让任何人写代码」的秒哒。同事调侃他「造了一个车轮，碾过了自己过去二十年」。他自认本就叛逆：是清华交叉信息研究院（叉院）建院十年第一个换导师的人，当时院里连换导师流程都没有。此前他做计算生物学里的蛋白质三维建模（AlphaFold 前身），成果入选中国年度十大进展，发表论文影响因子已达 20（毕业只需 5）。但看到生命科学距实业成药可能还要五十年到一百年，恰逢 AlphaGo 战胜李世石，他毅然甘冒延期风险转攻强化学习，成为清华最早一批强化学习研究者——「做旧方向越久弯路越长，放到整个人生里晚一年毕业无所谓」。毕业时他是同届唯一不干程序员直接做 PM 的人，随后四年换了八个团队，紧盯行业终局大盘。

在他看来，计算机发展史本就是「用车轮碾死上一代」：第一版简单 C 编译器是用汇编语言写的，再用简单 C 写出复杂 C 编译器，从此没人愿再写「噩梦般的汇编」——汇编造轮子碾死了自己。抽象链条从机器语言（0101）→ 汇编（指挥 CPU 与内存）→ 高级语言（C/Java/Python，表达算法与工程）→ 自然语言（Vibe Coding），一路外推到直接表达意图。如今秒哒内部也在自我革命：据朱介绍，秒哒一半需求由秒哒生成，约 80% 代码由 AI 编写。

二、从「自己都不信」到「楚门的世界」与倒金字塔 ARR

2024 年下半年启动秒哒时，连朱广翔自己都不信：彼时没有 DeepSeek、不知 CoT/Thinking，工具调用只有浅层 Function Call，Coding 模型普遍不行；产品侧没有 Manus，大众认知仍停在 Chatbot。早期内部 Demo 局限少数场景，「智能不行就人工来凑」。扭转他信念的是两个瞬间：一是「用户比我先信了」——对外宣讲「一句话做应用」时，台下起初像看传销，但现场演示后低头玩手机的听众纷纷抬头、眼睛放光并冒出业务场景（他也想起读博时做学术主页的麻烦）；二是「《楚门的世界》时刻」——某天他在百度搜索浏览一个网站半天，同学告知是秒哒做的，回头细看仍看不出 AI 痕迹。联系作者才知是位 50 多岁的医生，用秒哒给医院做了真实上线、百度搜索第一条且带官方 Logo 的官网。这一偶然发现让他确信无代码已进入严肃企业级场景。

解释「不看自己 ARR（年度经常性收入）、只看用户 ARR」时，他引用李彦宏（Robin）在百度世界大会的判断：AI 产业正从正金字塔（底层老黄显卡赚最多、模型次之、应用赔钱）走向倒金字塔（应用层赚最多，再反哺工具、模型与算力）。秒哒据此发起「筑梦计划」扶持一人公司（OPC）与超级个体，举出两类水下标杆：

  • 超级个体「黄啊码」：不会写代码，作品发到秒哒广场直接接单，三个项目赚了十几万——漫剧平台 12 万；门窗店官网 3 万（普通官网只值 3,000 元，但他加上顾客上传家居照片在线试装门窗效果功能，大幅提升转化）；以及汽车喷漆效果预览工具。
  • 12 人传统软件交付公司：原注册 17 家公司接政企项目、周期半年到一年；用秒哒后改为 4 个项目经理操盘，约 1 周交付一单，使用一个多月即落地养老院管理系统 40 万与企业办公平台 30 万，合计 70 万。

他算了一笔次年规模账：目标孵化 1 万个超级个体，每人年入十几万即应用层十几亿 ARR；平台分成 10% 便有 1 亿收入，再拿 1,000 万回流算力，倒金字塔即告闭环。

三、模型延长线风险、「15 度夹角」与 RL 视角的环境内化

谈最大失败风险，朱广翔直指误判模型延长线——以为在做模型外增量，却被下一代基模内化吞噬。由此提出「15 度夹角」理论：产品不能与模型正交（吃不到红利），也不能重合（被吃掉），应保持约 15 度夹角——靠多模型路由吃满顶尖模型进步，同时守住短期难内化的语音、后端、产品设计到部署分发链路。他认为把 15 度夹角拿捏最好的是 Manus，笑称内部招人标准是「PM 招 Manus 这样的，研发招姚顺雨那样的」。

对于中长期产品是否全被大模型吃掉，朱广翔反驳了 Manus 联合创始人季逸超（原转写音误为「毕超」）借「缸中之脑」主张环境永不能内化的观点。强化学习出身的他拆解道：RL 分 Model-Free（如从百度走去清华每个路口问路）与 Model-Based（先画地图将环境建模进大脑规划）；环境本质是 MDP（马尔可夫决策过程），基于状态与动作预测下一状态与奖励的方程理论上可被神经网络学进权重。落到 Coding 上，IDE 只是记事本，真正内核环境是编译器（朱自称写代码只用记事本、命令行或 Vim，早有暴论「Cursor 必被 Claude 干掉」，命令行 Claude Code 确实洗走一批用户）。而编译器与云虚拟机操作系统本质都是代码——若未来模型学进权重自行 replay 执行，中间层都将化作模型级能力。不过他随即加上理性约束：内化编译器至少需 3—5 年，内化 OS 需 5—10 年，且代码越重幻觉越高，只是概率事件、也可能不发生，因此当下最务实仍是守住 15 度夹角。

四、全球「四大天王」、国内跨界与秒哒的六重壁垒

国外「四大天王」核心长板（录制时观察）主要取向
Lovable开发部署轻量化、均衡；模板教程多，推崇「人人都是 CMO」（被调侃像刘德华）轻量原型与大众创作者
Replit偏专业与企业级，数据库配置灵活全面，后端部署做重专业开发者与企业场景
Bolt.new背靠云 IDE 公司，开发环境强、多语言，前端工程环节做重专业前端与全栈开发者
v0前端交互与视觉还原极致，能高保真还原设计师原图前端与设计人群

国内直接专注无代码的产品不多（美团 No Code、马上飞、响指），但三类跨界玩家已全面涌入：IDE 向下渗透（字节 Trae SOLO、腾讯 CodeBuddy、阿里 Qoder）；通用 Agent 增加建站（Manus 1.5、扣子空间）；低代码工作流转型（扣子改名扣子编程）。面对混战，朱广翔亮出秒哒六大差异化：

  1. 「秒哒是活的」（数据飞轮 + 插件）：点赞点踩、是否上线、是否卡壳反复修改，全部回流优化模型与 Agent 调度策略；配合百度地图、百度搜索等插件替小白兜底全链路。
  2. AI 原生后端独一档：前端像脸，后端（数据库、认证、支付、逻辑）像大脑。Supabase 去年下半年官方认证三家领先 AI Builder——欧洲 Lovable、美国 Bolt.new、亚洲 MeDo（秒哒海外版）。AI 时代数据库与传统库三大不同：① 小、多、极致弹性，秒哒 1 周建库量超百度传统 To B 数据库团队 7 年累计总量；② 给 AI 看而非给人看，面向 Agent 深度改造 MCP 与上下文接口；③ 单 Query 原生联通前后端，不像去年底 Lovable 需多轮对话并跳转 Supabase 手填 Token（即便后来 Lovable Cloud 仍有割裂配置）。
  3. 控制权边界澄清：针对 Koji 误以为秒哒锁死代码与数据库，朱纠正：代码可看不可手改（禁止小白破坏结构，可截图或框选代码让秒哒改）；数据库不仅能看表结构，还可像 Excel 一样编辑行列与上传下载——白领办公级操作放开，专业代码藏于 Agent 后。
  4. 私域小程序 + 公域搜索分发：针对微信小程序特殊语法依赖做专门训练与 Agent；发挥百度基因，一键分发至百度搜索、必应与谷歌拿自然流量。
  5. 「产品经理智能体」：一句话不是需求只是创意，距研发听得懂的规格差十万八千里；秒哒先由产品经理 Agent 出需求文档让用户确认修改，再交研发执行。
  6. 「秒哒 Bench」与多模型路由：SWE-bench 只评修 Bug（替程序员），秒哒替完整产研团队，拆解 100 多个任务逐环节建评测（暂未公开，称将发论文）。呼应姚顺雨「评估比训练更重要」，朱补充：「实验室评估不是真评估，用户场景评估才是真评估」；主观审美则结合「用户用脚投票（上线、转发、停留）+ 内部设计师专家团 + 产品运营」三路降偏。路由架构按各任务方格自动匹配最优模型与 Agent——「Benchmark 是菜谱，模型是食材，路由架构是炊具」（Koji 补充 Lovable 创始人也自比开餐馆）。

五、云端沙箱、Claude Skills 暴论与「No Code 必胜」推演

谈及刷屏的 Claude Code，朱广翔认同季逸超的云端优势判断：Claude Code 跑在本地、类似 IDE 赛道，小白给本地无限文件权限极易搞崩主力电脑（以致大家专买 Mac mini 来跑）；秒哒与 Manus 一样用云端虚拟机，每建一应用开一台独立虚拟机，弄坏重开且可并行开 1,000 个 Agent、1,000 台虚拟机同时干活。谈到 Claude Skills，他抛出暴论：「就是把我们去年年中的 Trick 公开标准化了。」 早期秒哒改到约 50 轮就卡死道歉，根源在于上下文爆长与注意力分散；团队去年年中改用说明书式动态加载、渐进式披露（每轮先读目录再按需路由工具、MCP 与代码），一举突破 50 轮僵局、支持持续多轮修改。秒哒将插件设为一级目录，分三类：API 插件、Prompt 插件（兼容市面 Claude Skills）与 Code 类 Skill（交由编译器执行确定性 Python 函数）。

为何坚信 No Code 必胜？朱广翔给出四条依据：① Product Hunt 2025 年 200 多款 AI Coding 产品中，上半年清一色 IDE，下半年 No Code 反超；② 第一性原理上全球仅 3,000 万程序员却有 80 亿普通人，引用 Rich Sutton《苦涩的教训（The Bitter Lesson）》指出真正吃算力的只有 Learning（模型内计算，Model） 与 Search（模型外交互探索，Agent），写死人工节点的 Workflow 并不本质（点评扣子改名扣子编程可能偏晚）；③ 亲历百度内部 Hackathon 获奖队伍从标配多研发演变为纯产品运营无程序员拿奖（Koji 改写为「Idea is cheap, show me the app」），并举一位中石化工程师案例——零代码用秒哒做的矿井设计软件已落地大庆、青海、长庆油田并用于石油大学毕设，彻底胜过此前花 140 万元外采却不懂物理逻辑的废品软件；④ 体验上 IDE 像两人三足（人机绑腿互牵绊很累），No Code 像 99 步 + 1 步接力跑，正如 Photoshop 演进至美图秀秀滤镜、高级语言碾压汇编傲慢，人类天性追逐低门槛。因此他建议若重读大学应去读法律、金融等垂直专业；对孩子则像自己初中学半淘汰教学语言 Pascal 一样，把传统编程作思维「教具」，把 Vibe Coding 作实用工具。

六、大厂助力摩擦、2025 复盘与 300 万美元投资题

谈在百度做产品：助力是技术理想主义、用两年后技术看现在，容忍早期亏损坚持投入；摩擦是人多「对齐」耗时长及 B 站等社区滤镜（「不是百度做的就用一下」），但他自信秒哒「赶的是大集，不是晚集」。团队以「没一个正常人」著称：校招生夸他「不听老板话」，高级工程师同样直接骂他，唯一裁决标准是「上帝指标——用户说了算」，吵不完就丢社区群看反馈；运营有数字游民，深扎用户到收到海南刻字椰子、老师全班应用合集、赚 40 万大哥邀吃年夜饭。产研运营全职闭环只背秒哒一个 OKR，工区排成「十字路口」，四角为产品、运营、工程、策略，所有决策在此碰撞。

复盘 2025：最对是在低代码与无代码间押注无代码、押注 80 亿人；最纠结是给了模型太多自由（像「自负的年轻人」不会也硬干出幻觉，Koji 戏称「自由过了火」），但为模型按月破界留了空间；真正做错是运营晚起步半年、至今无独立预算靠蹭内部流量。出海已推出 MeDo，但他反驳「国内无 PMF」论调，认为中国移动支付、社交与信息流最繁荣，场景与产值独一档。收尾「300 万美元天使投资」题，他先答投给秒哒用户（筑梦计划已真投 300 万美元），排除官方答案后选了 Google / Gemini（原转写音误为 Jenna，按简介还原）——技术基因、最大搜索数据与最大分发渠道，并按简介打趣「百度是中国 Google，就看能否把内部管理好」。

机制拆解：一句话如何跨过「需求—后端—多轮修改」三道关

可跟算示例：为社区诊所生成「在线挂号预约系统」 初始一句话 Query：「帮我给诊所做一个在线预约网站。」
  1. 阶段一：创意转规格（产品经理智能体）。原始一句话至少缺 5 项硬约束：出诊科室与排班、每 30 分钟号源上限、是否需手机验证码防占号、提前几小时可取消、前台如何导出名单。产品经理 Agent 先生成结构化需求文档供老板确认，避免研发 Agent 盲猜返工。
  2. 阶段二：多任务路由与 AI 原生后端联动。系统把交付拆进 100 多个子任务方格并行路由（UI 交审美最强模型，并发防超卖交推理最强模型）；云端秒级拉起独立小数据库与沙箱虚拟机，经面向 Agent 的接口建表（doctors、slots、bookings 并加 (doctor_id, slot_time) 名额约束），将表单提交、鉴权 Token 与后端 API 原生打通，免去跳转第三方拷密钥。
  3. 阶段三：长周期迭代防崩溃（动态上下文加载 / Skills）。设想上线后老板连续改了 60 轮（第 18 轮加微信提醒、第 42 轮改周六停诊、第 58 轮调按钮色）。全量塞入 60 轮历史必触发上下文膨胀与注意力稀释（复现早期 50 轮卡死）；改用说明书式渐进加载后，第 58 轮仅加载前端样式规范与目标组件，屏蔽数据库迁移代码，稳住修改成功率与推理成本。

隐蔽失效点：若第 58 轮改为「允许同手机号替家人约两个号」，前置路由误判为纯前端表单校验而漏载后端唯一索引说明，前端放开、后端依然报错拒单——按需加载一旦漏召回跨层约束，仍会制造隐蔽 Bug。

独立判断：夹角、内化假说与无代码评估的真实边界

一、「预测执行结果」与「改变外部真实状态」不能混为一谈

用 RL 的 Model-Based 思想推演模型内化编译器与 OS 很有启发性，但忽略了一道根本断层：脑内模拟（Simulation）不等于真实执行（Execution）。一方面，编译器与财务/医疗账务要求确定性零幻觉，模型即便 99.5% 模拟正确，剩余 0.5% 概率误差在生产环境仍不可接受，真实沙箱恰恰提供零幻觉验证器；另一方面，模型就算完美预测数据库写入和支付返回「成功」，外部银行账户与诊所排班表不会凭空改变——只要软件与真实世界交互，带权限隔离的运行时与 API 就不会被完全消灭，最多只是减少试错调用。

二、《苦涩的教训》推不出「所有固定工作流都该消失」

算力驱动的 Learning 与 Search 是强战略视角，但工程上开放搜索与确定性硬约束本应互补。诊所网站的排版和需求澄清适合开放搜索，但「同一号源不能并发双卖」「退款必须幂等留痕」写进确定性数据库事务和代码插件远比靠模型自由发挥可靠。划界标准应是固定任务集上的故障率、单位成本与纠错耗时，而非哲学教条。

三、「用户用脚投票」离「真实业务成功」仍有噪声距离

把上线率、转发率与反复修改频次接进数据飞轮很务实，但隐式行为天然带噪：点「上线」可能只是发链接给同事看半成品；连续改 40 轮既可能是卡壳，也可能是产品真的好用、老板不断加新功能。若 100 人生成页面、60 人发布、30 人分享、仅 10 人一月后仍有真实订单，直接拿发布率训练模型易过拟合「首屏炫酷诱导发布」而非后台稳定。更扎实评测需结合自动化功能/并发回归测试、30 天真实调用留存与分行业盲评。

四、「15 度夹角」的动态考题：模型再强一代，什么留得下来？

「15 度夹角」是本期最锐利的创业框架，但今天的多模型路由或上下文诀窍都会随基模升级与行业标准化迅速贬值（正如 Claude Skills 一夜间拉平起跑线）。秒哒能否沉淀持久壁垒，取决于三项非模型资产：高黏性托管数据与运维账户、「筑梦计划」里真正靠平台稳定接单赚钱的超级个体供给网络，以及从海量真实失败案例中沉淀的跨行业验收基准。
