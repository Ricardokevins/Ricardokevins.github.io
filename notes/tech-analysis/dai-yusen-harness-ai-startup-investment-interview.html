戴雨森谈 Harness 与投资回报：模型之外，任务、数据与结果怎样形成闭环

本期背景与内容导览

戴雨森从半年前预测失误复盘起，承认自己看对了 C 端变现困难，却低估了 Anthropic 在 Coding 场景的商业爆发。这个误差把话题带到“投入—产出—结果”的链条：客户为模型与算力付费，得到代码或其他产出，最终还要证明利润或战略能力真的提高，不能把供应商收入直接当成客户回报。随后他拆解 Harness：模型负责生成与判断，Context 提供任务相关信息，Harness 组织工具、记忆和 Agent 循环，Runtime 管理实际执行、权限与结果。模型与 Harness 可以相互增强，也可能因模型厂商整合而冲突，CPU/OS 类比只能帮助理解，不能预设开放生态一定形成。节目还讨论 Agent 任务轨迹的数据价值、通用与垂直创业、Agent 市场，以及人在 AI 时代的 Agency。本文保留其投资视角与公开承认错误的部分，不把估值、市场结果或 Agent 网络效应当成已经验证的事实。

本期节目开篇，主持人张小珺直接向嘉宾戴雨森提问，关于他在半年前节目中预测2026年将是“现实与回调之年”（The Year of R）并清空二级市场股票的观点，如今是否感觉“被打脸”。

戴雨森坦诚回应，承认“打脸是常态”，尤其是在AI这样快速变化的领域。他回顾了过去半年市场对顶尖AI模型的看法快速轮换：从去年11、12月市场热捧OpenAI，到今年1月Google的Gemini被看好，再到3月因编程能力出色而市值一度超越OpenAI的Anthropic，及至5月OpenAI凭借Codex和GPT-5似乎又卷土重来。他认为，这种快速变化本身就意味着机会，而害怕被打脸则会妨碍做出判断。他透露，正是因为在播客中公开表达了看空观点，这种公开的立场在一定程度上限制了自己后续的操作，使其在市场上涨时不敢像朋友们那样激进地加仓。

在主持人追问下，戴雨森引用了“Strong Opinions, Weakly Held”（观点要强，但不必固守）的原则，解释了聪明人应如何根据核心原因的变化来调整自己的看法。他承认，自己当初预测回调的一个重要依据是认为OpenAI的C端订阅和广告电商收入增长会低于预期，这一点事后看基本正确。但他完全没预料到Anthropic在企业服务（特别是编程）领域的收入会因其模型能力的“量变到质变”而大幅增长。这个新变量的出现，让他修正了对市场回调时间线的判断，并相应调整了自己的投资仓位。

Strong Opinions, Weakly Held一种决策原则，意为“观点要强，但不必固守”。它鼓励决策者基于现有信息形成一个明确、有力的观点（Strong Opinion），并清楚支撑该观点的理由。同时，决策者也必须保持开放心态，当出现新的、能挑战原有理由的关键信息时，要愿意且能够迅速放弃或修正自己的观点（Weakly Held），而不是出于维护自尊或路径依赖而固执己见。
Agentic Coding / AI Coding指利用具备自主规划、执行、反思能力的AI智能体（Agent）来进行编程工作。输入是用户的编程任务需求（通常是自然语言描述），输出是可执行的代码、软件或完成的开发任务。其核心机制是AI在一个循环（Agentic Loop）中自主地分解任务、编写代码、测试、调试并修正错误，直到完成目标，从而能处理比简单代码补全更复杂的、需要长时间执行的开发工作。
Harness (模型编排)在本语境中，Harness指位于底层大模型API之上、用户直接交互的应用层或框架。它将一个或多个大模型的能力封装起来，通过特定的工作流、用户界面和工具集，来引导、约束和增强模型，使其能稳定、高效地完成特定领域的复杂任务（如编程）。输入是用户的任务指令，输出是经过Harness编排后由模型生成的高度结构化、任务导向的结果。它区别于直接调用模型API的“套壳”，更强调对模型能力的深度整合与工程化编排。
Return (回报)在这里特指AI领域的投资回报。它不仅指模型公司自身的收入，更关注整个价值链的最终闭环：硬件投入（CAPEX）-> 模型公司收入 -> 客户（企业或个人）购买Token的投入 -> 客户利用AI实现利润增长（增效或降本）。嘉宾的核心观点是，只有当最终端的客户能够获得实实在在的利润回报时，整个AI产业的高投入才能被证明是可持续的。

主持人邀请戴雨森系统总结他之前预测的对错之处。戴雨森回应，他看对的部分主要在于对C端用户变现的担忧。他当时判断，以OpenAI为代表的普通用户订阅模式（每月20美元）难以提价，且付费用户规模在达到5000万后增长会放缓。同时，他认为在ChatGPT这样的创新产品中嫁接广告和电商的商业模式，其难度远超外界想象，需要长时间探索，无法迅速贡献收入。他认为，过去半年的发展验证了这两点。

看错的部分，则是完全没有预料到Anthropic在编程（Coding）领域会如此迅速地取得突破。他将AI的智力发展比作烧水，必须突破某个阈值（如100度）才会产生质变价值，而这个阈值何时达到很难预测。他指出，Anthropic的Claude 4.5版本（从版本号看官方可能也未预料到其巨大影响）就实现了这样的突变，让原本无法有效运行的Agentic Loop（智能体循环）跑了起来，使AI能完成更高价值的编程工作。他认为，这种突破背后主要是高质量用户交互数据和Agentic RL（智能体强化学习）的功劳。

当被问及何时开始理解Anthropic时，戴雨森谦虚地表示不能说完全理解，但他通过在硅谷的交流，认识到Anthropic的组织能力和组织形态是其关键优势。他对比了OpenAI和Anthropic：OpenAI在探索期采用的是松散、自下而上、鼓励个人英雄主义的组织模式，适合多方向探索，但也导致一些项目（如GPTs、Sora）后续维护不足，有“管杀不管埋”之嫌。而Anthropic则在选定企业服务和编程这个主攻方向后，展现出一种从上到下、高度对齐的组织能力。具体体现为：有严格的价值观面试、创始人Dario每两周同步内部思考备忘录、产品迭代迅速且“管杀管埋”。

戴雨森进一步分析，编程能力已从一个垂直领域（如医疗、金融）转变为一个水平的、通用的基础能力，能赋能各行各业。Anthropic的成功还在于它没有仅仅停留在卖API，而是推出了Claude Code这个Harness（模型编排应用）。这个产品不仅为Anthropic带来了大量高质量的用户使用数据，形成了数据飞轮反哺模型训练，也证明了Harness本身的重要性，打破了之前“API好就够了”的观念。

主持人首先提问，好的Harness是否必须由模型公司自己来做。戴雨森认为不一定。他指出，Claude Code本身可以接入其他模型，说明其与底层模型的耦合不强。更重要的是，像OpenClaw这样的热门Harness是由个人开发者做出来的，证明了创新可以来自任何地方，而不仅限于模型公司内部。他总结，过去被轻视为“套壳”的应用，现在被正名为“Harness”，其重要性得到了重新认识。

接着，主持人询问戴雨森对OpenAI和Anthropic当前估值的看法。戴雨森从三个时间维度给出了复杂的判断：

1. 短期（如3个月）：他认为两家公司可能都被低估了。以它们目前约9000亿美元的估值，若在当前市场情绪下上市，很可能翻倍甚至更高，达到2-3万亿美元。考虑到年底1000亿美元的ARR（年度经常性收入）预期，当前的估值倍数并不算特别高。

2. 中期（1-2年）：他认为可能被高估了。核心原因在于“Return”（回报）问题并未真正解决，当前的收入增长可能无法持续，估值或将面临大幅回调。

3. 长期（10年）：他认为最终的赢家（可能两家都是）有机会成为5万亿甚至10万亿美元市值的公司。

他补充说，目前头部模型公司之间并未拉开决定性差距，往往是“谁最后发模型，谁就显得最厉害”，用短期领先去推断长期格局存在风险。

在谈到Claude Code与OpenAI的Codex之间的竞争时，戴雨森认为，先发优势带来的品牌锁定和用户粘性非常重要。用户一旦习惯了某个工具（如在Claude Code中配置了大量个人化的Skill），迁移成本就会变高。因此，后发的Codex采取了价格战策略，成本大约比Claude Code便宜50%。同时，得益于GPT-5.5的发布，Codex在推理等方面的能力也得到了提升。因此，竞争的关键已经从单纯的模型能力比拼，扩展到了品牌、渠道、价格等多个维度。两个月前Claude Code优势明显，但现在两者的差距已经大大缩小。

00:23:19–00:37:28回报问题转移而非解决：AI投入、产出与结果的三步链条

  • 你也刚才说到，Return的问题没有真正解决。

戴雨森详细阐述了他认为“回报（Return）问题”并未解决的逻辑。他提出了一个“投入-产出-结果”的三步链条。目前，Anthropic等公司的收入大涨，本质上是其客户的“投入”，而非最终的“结果”。客户投入资金购买Token，是为了获得“产出”（如开发出新软件），并最终实现“结果”，即增加利润（通过增效或降本）。

戴雨森对这个链条能否顺利闭环持保留态度：

1. 增效（增加收入）的挑战：他认为，企业收入增长的瓶颈通常不在于缺少程序员写代码，而在于缺少好的产品方向和创新。即使AI让工程师效率提升10倍，如果公司不知道该做什么新产品，这些多出来的生产力很可能被用于进入他人领地、互相“卷”，导致同质化竞争加剧，而非创造新的市场和收入。新产品的发现和成功是一个缓慢过程，与当前Token消耗的速度存在时间错配。

2. 降本（裁员）的局限：虽然AI Coding让硅谷程序员普遍感到焦虑，但戴雨森认为大规模裁员并不容易。首先，程序员的工作不仅是编程，还包括沟通、协调、建立信任等难以被AI替代的部分。其次，这类似于自动驾驶，即使解决了90%的路况，剩下的10% corner case仍需要人类介入，导致无法完全去掉驾驶员。最后，裁员是一次性动作，无法持续产生增量效益。

对于“现在谈回报是否为时过早”的追问，戴雨森强调，之所以现在必须关注，是因为投入的规模“太大而不能忽视”（too big to ignore）。他提到，今年AI硬件利润高达7000亿美元，存储厂商的利润甚至超过了云厂商，而Anthropic年底预期的千亿美金ARR意味着每月有百亿美金的Token被消耗。如此巨大的投入，叠加数据中心建设已开始使用资金杠杆，都要求回报问题必须在较短时间内得到解答。

他将当前市场比作一个水槽：涌入尝试AI Coding的用户（进水）远多于因未获价值而离开的用户（漏水），所以整体水位（如LangChain、模型公司的ARR）在快速上涨。但长期来看，必须“堵住漏水”，即让用户能实实在在地从AI投入中赚到钱，否则这个循环不可持续。他认为，AI Coding目前对个人和小型创业公司机会更大，因为他们原本就受限于开发资源；而大公司的问题更多是组织效率和创新方向不明。

最后，戴雨森回顾了自己从2023年以来对AI发展主线的看法，始终聚焦于Agent（智能体）对生产力的提升。他认为Agent是解放人类注意力的关键，让人类可以成为“AI的老板”。过去被认为是“套壳”的应用，现在被正名为Harness，其价值终于被认可。他总结，2026年的AI世界，就是模型能力提升带来了Agent的真正落地，而Harness正是Agent落地的关键产品形态。

戴雨森将这个“壳”的架构拆解为几个层次：

1. 模型 (Model)：最基础的核心，提供根本能力。

2. 上下文 (Context)：模型本身不知道很多实时或组织内部的专有信息，需要外部输入。这是模型外的第一层。

3. Harness：在Context之外，为模型提供可使用的工具、设定Agentic的循环机制。一个好的Harness能解锁模型的潜力，完成更复杂的任务。

4. 运行时 (Runtime)：Harness之外的一层，通常指一个隔离的执行环境（Sandbox），让模型可以在其中安全地使用复杂应用，如上网、操作软件。现在趋势是为AI配备一个“持久的电脑”，让其能在其中持续运行任务。

戴雨森认为，这些层次中，有些由模型厂商自己构建，有些则由第三方创业公司提供，但价值正越来越多地体现在模型外面的这些“壳”里。主持人张小珺追问这是否与“模型即产品”的观点冲突。戴雨森解释两者并不矛盾：产品的核心能力确实源于模型，但用户交互的始终是产品，而非裸露的模型API。他以ChatGPT为例，指出它本身就是将InstructGPT模型封装成对话形式的产品，这种产品化引爆了浪潮。因此，即使是Claude这样的“模型级产品”，也离不开其外层的Harness。

针对“模型将吞噬一切”的观点，戴雨森认为“模型很重要”和“壳很重要”可以同时成立。一方面，没有足够强的模型，很多任务无法完成。但从早期投资角度看，模型领域的格局已趋于稳定，新玩家进入门槛极高。另一方面，好的Harness能通过收集高质量的用户交互数据，反哺模型训练，形成数据飞轮。他指出，传统的Chatbot没有数据飞轮，因为普通聊天内容对已训练大量文本的模型提升有限。但Agentic模型（如编程助手）在解决真实问题的过程中，用户的使用轨迹本身就是高质量的反馈信号。因此，拥有自己的Harness（壳）变得比以往更重要。

Harness在本对话中，Harness指在AI模型之外，用于控制、引导和增强模型能力的一整套工具、机制和框架。它源于马具（harness），意为驾驭强大的力量（模型）。其输入是用户的指令和底座模型的能力，输出是经过Harness优化和约束后，模型完成的更复杂、更可靠的任务结果。它包括提供上下文（Context）、调用工具、执行Agentic循环、管理记忆（Memory）等功能，可以看作是模型与最终应用之间的“操作系统”层。
Context在这里指为AI模型提供的、其自身知识库中不包含的背景信息。输入是实时的、私有的、特定领域的数据（如组织内部文档、当前对话历史），输出是让模型能够在特定情境下生成更准确、更相关回答的“知识补充包”。它是Harness架构中的一个重要层次。
Runtime指为AI模型或Agent提供的安全、隔离的执行环境，通常是“沙盒”（Sandbox）。输入是AI生成的代码或指令，输出是这些指令在受控环境中的执行结果（如访问网站、运行程序）。它确保了AI在执行任务时不会对用户的真实系统造成破坏，是实现复杂Agent功能的基础设施。
Agentic Loop指AI智能体（Agent）的工作循环机制，即“思考-行动-观察-再思考”的闭环。输入是用户的任务目标，中间过程是Agent不断地分解任务、调用工具、执行操作、评估结果并调整下一步计划，输出是最终完成的任务结果。Harness的一个核心功能就是为模型设计和管理这种循环。

2. 第二阶段：技术渗透到一定程度后，出现原生新机会。

* 互联网时代：当上网人口足够多，诞生了连接人的社交网络（Social Network）和即时通讯（IM）；当信息足够多，诞生了组织信息的搜索引擎；当买卖双方都上网，诞生了平台电商。

* 新的商业模式：当广告的受众从人变成AI，广告业态和商业模式将发生根本变化。

* 新的软件形态：当AI间通信不再需要Excel这种为人设计的“界面”，而是直接通过API交换数据，微软Office的护城河可能会受到冲击。

其次是“世界模型”（World Model）成为热点。戴雨森指出，这个概念在中美都非常热门。从实用主义角度看，中国市场关注硬件如何能真正做事，而非仅作摆设，这需要机器人具备操控能力。从模型角度看，硅谷的研究者们希望将语言模型成功的范式平移到机器人领域：即通过收集海量数据，遵循某种Scaling Law进行训练，让机器人模型也具备Zero-shot或Few-shot的泛化能力和更高的稳定性。他提到，目前存在几条不同的技术路线，例如以EgoScale为代表的，通过学习第一人称视角（EgoCentric）下人类操作视频来训练模型；以及类似谷歌DeepMind的RT系列（嘉宾可能指其前身或相关项目），使用人类遥操作数据进行训练。尽管“世界模型”概念本身仍在争议中，大家对具体路线有分歧，但普遍共识是其目标在于像语言模型预测下一个词（token）一样，预测世界的下一个状态（state）。

第三个方向是“Auto Research”，即AI的自我迭代和自我提升。戴雨森提到，大家希望AI能提升AI自身，无论是在科学研究还是AI研究领域。他举了田渊栋新近官宣的创业公司Cursive为例，该公司就在探索自我改进的AI。他认为这是一个未来非常重要的方向，在中国也有一些科研性质的公司在考虑。

世界模型 (World Model)在本段中，指一种AI模型，其目标是理解并预测物理世界的动态变化。与语言模型预测下一个文本“token”类似，世界模型旨在预测世界的下一个“state”（状态）。其输入通常是多模态数据，如视频、传感器读数、遥操作数据等，输出是对未来世界状态的模拟或预测，常用于机器人领域，以提升机器人的泛化能力和操控稳定性。
Auto Research指利用AI来加速或自动化科学研究与AI自身研究的过程。其核心是实现AI的自我迭代和自我提升。输入是研究问题、数据或现有模型，输出是新的科学发现、更优化的算法或性能更强的AI模型。
Agency在本段中，指人类的主动性、自主性和驱动力。它不是指AI Agent，而是强调人类作为主体的核心价值，即“要做什么”、“要问什么问题”、“想解决什么问题”的意愿和能力。在AI能完成大部分执行任务的背景下，这种发起行动和设定目标的能力被认为是人类不易被替代的核心特质。
Out of Distribution (OOD)字面意思为“分布之外”。在本段中，指代那些超越现有数据和知识范围的、具有原创性的内容或想法。AI目前擅长处理已有数据分布内（Within Distribution）的任务，但难以创造出真正新颖、从未见过（OOD）的事物，例如一个原创的笑话或一个全新的科学理论。

Harness的四层架构

戴雨森将模型之上的“壳”解构为一个四层系统，用于驾驭和增强模型能力。

- 输入: 用户的自然语言任务指令。

- 过程:

1. 模型 (Model): 最底层的能力引擎，接收指令并生成初步响应。

2. 上下文 (Context): 第二层，为模型注入其知识库之外的实时、私有信息（如内部文档、历史对话），使其响应更具相关性。

3. Harness: 第三层，核心编排层。它为模型提供可调用的工具（Tools）、设定Agentic Loop（规划-执行-反思循环）、管理长期记忆（Memory），将模型的原始能力转化为完成复杂任务的结构化流程。

4. 运行时 (Runtime): 最外层，一个安全的沙盒环境（Sandbox），供Harness调度模型在其中执行代码、访问网络或操作软件，确保安全可控。

- 输出: 经过层层编排和约束后，由模型完成的、可靠且符合用户复杂需求的任务结果（如一个可运行的软件、一份深度研究报告）。

- 失败条件: 如果底层模型能力过弱，Agentic Loop无法有效运转；如果Runtime环境限制过多，Agent能执行的任务范围将非常有限；如果Context提供的信息不准确，会导致模型产生错误的输出。

一、从“被打脸”看高速行业里的理性更新

戴雨森把上一期的谨慎分成“看对”和“看错”：他对 C 端订阅、广告和电商变现的速度判断并非全错，但低估了 Anthropic、Coding Agent、企业预算和模型能力出现阈值跃迁的速度。这里的关键不是某个具体价格或收入，而是 AI 与互联网产品的增长形态不同。

互联网常表现为连续的渗透率、留存和 ARPU 变化；大模型在数据、推理能力和 Agentic RL 同时跨过阈值时，会突然把一批原本“能回答”的任务变成“能交付”的任务。市场因此会在短时间内重估。用过去的线性经验去外推，会把技术的相变误判成普通产品迭代。

二、Model—Context—Harness—Runtime：厚“壳”其实是完整系统

节目把产品层拆成四层：模型负责推理与生成；Context 保存用户、任务与历史状态；Harness 编排工具、子任务、记忆、权限和失败恢复；Runtime 提供浏览器、终端、沙盒、文件系统、身份和支付等行动空间。这个分层比“模型 vs 套壳”更准确，因为每一层都在改变下层能力的可用范围。

Model

决定可表达的策略上限，但不自动知道用户的目标和责任边界。

Context

把一次性问答变成有历史、有偏好、有项目状态的连续工作。

Harness

把工具选择、循环、重试、审批、技能与观察写成可执行流程。

Runtime

让代理真正读写文件、调用服务、浏览网页并承担行动后果。

因此，用户的黏性可能来自 Harness 中积累的记忆与工作方式，而不是某个底层模型的品牌。更换模型有时只需要切换处理器；迁移所有上下文、权限、连接器和失败经验，成本高得多。反过来，模型厂商也可以向下吸收成熟 Harness 的设计，把优秀的运行时变成自己的产品默认值。

三、为什么 Coding Agent 先跑出来：高质量任务比聊天数量更有价值

普通聊天产生了大量语言，却未必产生能改善模型的清晰标签：用户是否满意、答案是否真的解决问题、错误会造成什么后果，常常不可见。Agent 任务则把目标、工具调用、环境观察、失败、修复和最终结果串在一起，形成更接近生产数据的轨迹。

这解释了节目中“高质量任务胜过大 DAU”的判断。一个用户每天只发起一次，但让代理连续运行数小时完成研究、代码、采购或运营，可能比高频短问答更有商业价值。指标应至少拆成 任务价值 × 完成率 × 复用反馈 ÷ 单位成本，而不是把 token 或打开次数当作产出。

正向飞轮

真实任务 → 可观察失败 → Harness 改进 → 更高完成率 → 更高价值任务。

反向飞轮

只追求调用量 → 低质量轨迹泛滥 → 训练噪声、成本和权限风险上升 → 信任下降。

“Agent 间网络效应”仍是早期假设。私人上下文、技能和声誉可能让一个代理更会雇佣另一个代理，但这要求身份、权限、报价、结算与责任都可计算。没有这些基础设施，网络效应只是“大家都在用同一模型”的换名。

四、三阶段外星人：AI-native 的难点最后落在组织

戴雨森把 AI 进入社会分成三个阶段：先让人类拥有更多、更强的代理；再让代理适应人的数字世界，包括图形界面、支付、验证码、身份和浏览器；最后建设原生的代理世界，让 API、命令行、微支付和代理间协作成为默认接口。每一步都不是模型升级就能自动完成的。

组织也有同样的滞后。电动机刚进入工厂时，人们只是把蒸汽机替换成电动机，生产线和部门结构没有变；只有工厂重画布局，生产率才真正释放。AI 现在也常被塞进旧的审批、产品、研发和销售链条。若仍以部门交接为基本单位，代理只会加快信息传递，不能减少翻译成本。

五、创业框架：做大厂暂时看不上的横向创新

节目对创业机会的判断并不是“再做一个垂直 SaaS”，而是寻找大公司暂时不愿承担的横向实验：新的 Agent 交互、开放源码、跨应用工作环境、代理通信或原生代理世界。大厂的优势是资源和分发，但它们也受既有用户、品牌安全和组织流程约束；创业公司的优势是可以把低概率、低共识的方向做成可观察产品。

“横向”不等于没有边界。一个好方向必须同时满足三件事：用户在乎、模型/运行时已足够可用、反馈能在短周期内改善产品。只追求“通用”而没有任务闭环，会变成漂亮的演示；只追求“垂直”而没有可迁移的系统能力，则容易被平台复制。

中美差异的合理读法访谈把美国的 Coding Agent 热度与中国的硬件、机器人和世界模型倾向并置。它更像资本与产业反馈的差异，而不是能力高低排名。判断机会时，应看当地能否提供计算、数据、分发、制造和长期付费的组合，而非只看叙事热度。

六、教育与人的余地：执行力会被外包，能否保持 agency 才是问题

节目最后把讨论从公司拉回个人。AI 可以外化记忆、搜索、整理和执行，但不能替用户自动获得理解、价值判断和好奇心。若学生把所有思考都外包给代理，短期效率可能上升，长期却可能失去“思考肌肉”。因此“思考需要刻意练习”不是反技术口号，而是 AI 时代的基础设施投资。

更准确的分工是：把信息压缩、草稿和可逆执行交给 AI，把问题选择、价值冲突、关系建立和不可逆责任留给人。人的稀缺性不在于永远比模型算得快，而在于知道什么值得算、谁会受到影响、什么时候应该停下来。

核心判断：AI 的竞争单位正在从注意力迁移到可完成的任务

戴雨森从上一期“Year of R”的谨慎预测被市场部分反驳讲起。他没有把复盘写成“谁预测得更准”，而是提出一种更适合高速变化行业的工作方式：观点可以强，但必须知道自己为什么强；原因变了，观点就应该变。这个姿态连接了整期节目的三条线：

模型是处理器

模型提供通用智能与生成能力，像 CPU 一样可被不同产品调用。

Harness 是操作系统

它管理上下文、工具、权限、运行时、记忆与失败恢复，决定能力如何落地。

任务是价值单位

高质量任务、agentic hours 与可复用反馈，比单纯 DAU 更接近真实效用。

最值得带走的翻译“模型会不会吞掉 Harness”不是二选一。模型能力越强，越需要一个能接住权限、环境、记忆和责任的运行层；但运行层若不能形成持续反馈、用户迁移成本和信任，也会被模型厂商快速吸收。

证据边界“阈值跃迁”“某模型收入增长”是访谈中的解释与观察，不是独立审计结论。更稳妥的做法是把它改写成可观察指标：端到端任务完成率、人工接管率、单位任务成本、续费与企业部署规模是否同步改善。
Insight：真正的护城河是“状态迁移成本 × 反馈速度”只有状态值得保留、反馈能持续改进，Harness 才会从界面变成基础设施。没有长期状态的编排只是一次性工作流，不能自动获得操作系统式的地位。

进一步推演：这期访谈留下的八条 Insight

  1. AI 时代的估值单位从注意力转向任务。 DAU 仍可描述分发，但不能描述高后果任务的真实价值。
  2. Harness 是机器可执行的管理学。 工具、权限、流程、复盘和停止权被写进运行时，组织设计因此进入产品核心。
  3. 状态比模型品牌更可能形成黏性。 用户真正迁移困难的是记忆、连接器、习惯和责任边界，而不是 API 名称。
  4. 高质量反馈是 AI 公司的稀缺资本。 任务完成、错误恢复和用户愿意支付，比更多低信息聊天更能推动下一代模型。
  5. 技术相变会先制造组织错配。 模型变强不代表企业生产率同步变强；只有重做流程、团队和指标，收益才会出现。
  6. 大厂看不上的方向可能是最好的实验场。 但“被忽视”本身不是护城河，必须用可重复反馈把新交互变成基础设施。
  7. 通用与垂直不是产品二选一。 通用模型负责能力覆盖，专业环境负责上下文、权限与责任，两者组合才接近真实工作。
  8. 人的优势从执行转向 agency。 未来教育和职业训练要增加问题定义、反事实思考、审美与责任训练，而不是只增加信息记忆。

怎样证伪或修正这套判断

  • 若用户可以无损迁移完整记忆、权限与任务状态，Harness 的状态护城河会明显变薄。
  • 若 DAU 与长期付费、任务完成和毛利稳定高度相关，单独强调 agentic hours 就是过度修正。
  • 若模型厂商能在不牺牲开放性的情况下持续复制所有优秀运行时，应用层的独立价值需要收缩。
  • 若跨部门旧流程只需接入代理就能获得同等生产率，组织重构的成本被节目高估。
  • 若代理市场无法建立身份、结算、声誉与追责，Agent-to-agent 网络效应只能停留在概念。
