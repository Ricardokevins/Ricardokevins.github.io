孟繁青谈模型竞争：从后训练、合成数据到RSI的演进与非共识判断

本期背景与内容导览

本期主持人曲凯对话 Evolvent AI 联合创始人、NUS 博士生孟繁青。官方 shownotes 补充称，孟繁青为 2001 年出生，曾在 Kimi 实习一年多，做 Agent 与 RL Infra，并参与 Kimi K2.5、Kimi Linear 等模型发版。访谈时的 Evolvent AI 成立约半年，一方面承接合成数据合作，另一方面探索 RSI；RSIBench-Data 是团队已经发布的项目，但本期没有给出足以独立复现其结论的实验表格或消融结果。 对话先从模型厂与创业公司的分工差异展开。嘉宾认为，模型厂内部训练服务已经成熟，普通后训练研究员的大量工作转向数据、环境和评测；创业团队则不从零训练基础模型，而要寻找与基础模型训练相区别的切口。他把新式 Agent Bench 解释为“环境＋任务＋检查”：模型不再只回答一道题，而是在模拟软件环境中连续操作，再由细分得分点验收。由此，数据质量的事前指标与训练后的实际效果被分开：正确性、轨迹是否作弊和难度可用于初筛，最终仍要看目标 Bench 提升以及其他能力是否退化。 随后嘉宾提出本期的主要行业判断：国内模型的特色更多来自资源限制下的大模型架构与预训练创新，海外厂商则在后训练数据积累上起步更早；蒸馏是补充数据和加速竞争的手段，不是国内模型变强的决定性因素。他同时强调，榜单交替领先不等于实际体验完全相同，算力之外还有数据、Infra 和组织协作。关于国内外差距、具体公司表现、算力比例和架构名称，节目提供的是嘉宾及其朋友圈的观察，不是经过本期独立核验的行业统计。 RSI 部分需要区分三个层次：在推理时反复修改一个答案，改变外部 Harness 或搜索过程，以及用产生的新数据重新训练模型参数。嘉宾用“更聪明的 DFS”概括第一类探索，用 world model 与 value model 解释模型如何选择后续动作，并把更强的基础模型和更长上下文视为 RSI 进步来源。这是他的统一解释框架，不证明所有 Self-Evolving、Auto-Research 与 RSI 系统在严格定义上等价，也不证明搜索成功会自动带来参数层面的持续自我提升。 数据部分把合成数据写成“给定环境与目标，让模型探索并保存轨迹”，把本期语境中的蒸馏写成“使用外部强模型充当探索者”。环境、题目和评分器因此成为数据生产的资产；外部教师、内部模型和真人轨迹只是不同来源，仍要经过质量筛选、训练和其他任务验收。嘉宾进一步把“一个模型后训练另一个小模型”的长过程称为潜在的 RSI 数据，并判断普通 Agent 数据订单可能减少、这类高门槛轨迹更有价值。该方向是团队正在探索的路线与市场预测，不能写成已经验证的商业或训练结论。节目最后回到 Evolvent AI 的实际业务、RSIBench-Data 的初步定位和招聘偏好。

主持人曲凯先请孟繁青介绍自己。嘉宾自述为 NUS 博士生、Evolvent AI 联合创始人，当前主要研究 RSI；此前在 Kimi 有较长实习经历，做 Agent 与 RL，偏 Infra，并参与 Kimi Linear、K2.5 等模型发版。官方 shownotes 另给出“01 年出生、在 Kimi 实习一年多、前 Kimi RL 实习生”的介绍。这里的“参与发版”不等于本期证明他独立负责这些模型的全部研发。

曲凯把“年轻、博士在读或刚毕业、具有模型厂后训练经历”概括为当下常见创业者画像，并询问创业约半年的实际感受。孟繁青认为，在 Kimi 后期，基础模型训练对普通研究员而言已较工程化，内部训练与推理流程稳定，他也会做合成数据。创业后，团队不从零训练基础模型，而要寻找与模型厂基础模型工作相区别的切入点，并从零搭建内部使用的平台与 Infra。

原转录在此段出现“训技术模型”“不训鸡模”“模型治理”等明显识别噪声。结合后文“不做 RSI 专用基模”以及团队会后训练小模型的表述，本稿按“不从零训练基础模型、寻找区别于基础模型研发的工作”还原语境；这不等于 Evolvent AI 完全不训练任何模型。嘉宾对大厂与创业公司的概括来自其个人岗位经历，也不能外推为所有模型厂研究员的工作状态。

Pre-training（预训练）用大规模数据训练基础模型，使其学习语言、知识与一般模式的阶段。本期把架构、优化器、训练计算等归入这一层；嘉宾将国内模型的部分竞争力归因于此。预训练提供能力基础，不等于已经确定所有下游任务表现。
Post-training（后训练）在预训练模型之后，通过监督微调、强化学习或其他数据与反馈过程改变模型行为。输入可包括问题、示范、模型轨迹、环境反馈与训练配置，输出是新的模型参数或版本；验收不限于单一答案，还包括目标能力、其他能力和成本。
SFT（Supervised Fine-Tuning，监督微调）用给定的输入与目标输出训练模型。模型厂内部服务化后，研究员主要提交数据与请求，由平台执行训练并返回模型结果；操作简化不代表数据设计、配置和效果诊断没有技术门槛。
Bench / Benchmark（基准测试）用于比较模型或 Agent 的任务与评分体系。本期的新式 Agent Bench 还包含可交互环境：输入是初始状态和任务，模型连续操作工具，评分器按多个得分点检查过程或结果。环境真实性、评分点设计与防泄漏共同影响结论。

话题推进：从个人岗位差异出发，主持人继续追问：为什么后训练背景的人似乎比预训练背景的人更容易创业，他们又能提供什么产品？

00:02:36–00:04:37为何Post-training背景的人更易创业：从数据到平台

  • 我发现做Post-training的人现在创业的是比较多的，Pre-training的好像很少。
  • 那Post-training的人出来创业，你觉得他是比较擅长和适合的是做什么呀？

曲凯先给出观察：做 Post-training 的人创业较多，Pre-training 背景者较少。孟繁青解释，预训练研究员更多处理模型架构、优化器等问题，这些工作需要大量计算资源，初创公司较难覆盖成本；他也认为预训练数据已相对饱和，研究员日常直接接触数据的机会较少。后半句是他的行业感受，不是对预训练数据研究已经终结的判断。

他给出的后训练创业入口主要有两类。第一类是合成数据：相较预训练阶段更大的数据用量，后训练数据更强调精细设计。第二类是平台，他将其白话化为 Bench。早期 Bench 更像一组难题，新式 Agent Bench 则提供可持续交互的环境，让模型长时间探索并完成任务。

嘉宾进一步把 Agent Bench 与商业落地连接起来：环境本身需要较好的工程实现，任务和验收又接近真实工作，因此他认为优秀的 Bench 更容易转成商业产品。这是“为什么后训练背景创业者更多”的机制解释与市场判断，节目没有给出创业者数量、公司收入或 Bench 转化率的统计证据。

孟繁青 · 00:03:15

嘉宾把两类切入口概括为合成数据与 Bench：前者重在后训练数据的精细设计，后者为 Agent 提供可探索、可验收的任务环境。

孟繁青 · 00:04:07

他认为 Agent Bench 的工程实现接近真实工作，因而更容易形成商业模式；这是嘉宾的创业判断，并非本期验证过的营收结论。

话题推进：“平台就是 Bench”仍然抽象，主持人要求嘉宾具体解释新旧 Bench 的差别，以及模拟环境中的结果怎样判定。

00:04:37–00:07:12基准测试（Bench）的演变：从“做题”到“模拟环境”

  • 哎，我觉得你说这个Bench的白话还不够白啊，就是所以到底今天的Bench你觉得跟之前的区别是什么？
  • 但你看之前的那个就是做题这件事情，包括Coding这件事情，它的可验证性其实我理解是更强更简单的，对吧？……那你说的我建一个环境，最终怎么评判这个结果的好坏呢？
  • 所以最后还是需要人来做这个检查嘛，对吧？

孟繁青用“做数学题”类比传统 Bench：输入一道难题，模型直接给答案，主要考察推理。现实中的白领工作还依赖飞书、Notion 等软件，因此新式 Bench 会模拟这些工具，让 Agent 通过连续操作完成任务。评测对象从单次答案扩展为环境状态、工具调用和最终交付。

曲凯随即指出，数学题和部分 Coding 任务容易对答案，模拟环境怎样保证评测可信？嘉宾把问题拆成两层。第一层是环境是否接近真实：例如同一个输入分别作用于模拟 Notion 与真实 Notion，比较输出是否一致。第二层是任务与检查是否设计正确：不再只判断最终答案是否相等，而是拆成多个小得分点；这些得分点目前依赖人的精细设计，检查时可由人和 Agent 共同完成。

这里的“相同输入得到相同输出”是环境行为一致性的检查例子，不能单独证明模拟环境在所有操作、异常和长期状态上等同真实环境；人工或 Agent 参与检查也不自动保证评分准确。嘉宾在 00:06:43 附近举到的两个 Bench 名称转录为“Crawlmark”和“Automation Bench”，本稿不替其猜补正式名称。

孟繁青 · 00:04:44

过去像让模型解一道数学题；现在可以模拟包含飞书、Notion 的白领工作环境，让 Agent 操作工具完成任务，同时考察推理和工具使用。

孟繁青 · 00:06:04

环境检查可对同一输入比较模拟 Notion 与真实 Notion 的输出；任务验收则拆成多个小得分点。前者检查工具行为，后者检查任务完成度，两者不能互相替代。

话题推进：环境和得分点都需要设计，话题由此回到后训练研究员的日常：他们的核心工作是否主要已经变成做数据？

00:07:12–00:10:35后训练的核心：门槛降低但“做数据”并非枯燥

  • 我最近听了一个说法，就是有人会讲说Post-training的人其实每天主要就是在做数据。
  • 所以会有人讲说那Post-training是不是其实相对是比较枯燥无聊的工作，以及说那是不是现在所谓的这个训模型这件事其实门槛没有大家想的那么高。

对于“Post-training 研究员每天主要做数据”的说法，孟繁青基本认可，并以模型厂内部 SFT 服务解释原因。外部训练者可能要自行找代码仓库、GPU、配置环境和整理数据；内部研究员则提交请求与数据，由远程服务执行训练并返回结果。他所说的“即使不懂 SFT 也能走完流程”强调操作门槛降低，并不表示数据设计、训练配置和结果诊断都不再需要知识，搭建服务的 Infra 人员也仍面临大量工程问题。

曲凯追问：这是否意味着后训练既枯燥又低门槛？嘉宾将二者分开。他认可普通算法研究员的执行门槛下降，但认为关注更直接、更本质的输入是技术演进的一部分，不等于工作没有研究含量。他把架构发展到 Transformer、RL 采用可验证规则奖励等作为“方法走向简单和结果导向”的例子；这是他个人的历史归纳，不是“所有复杂算法都失去价值”的证明。

团队 RSI Bench 的观察提供了反例：Agent 能处理较机械的修复，例如某批数据使模型回答格式出错后，Agent 可以修改；但嘉宾认为它还不能主动提出造数据的 insight。因此，研究员知道该造什么数据、为什么这样造，仍是核心 know-how。该段只报告团队观察，没有披露任务数、对照方法或成功率，不能扩大为 Agent 永远无法提出新数据策略。

孟繁青 · 00:07:44

模型厂内部把 SFT 做成服务：研究员提交数据和请求，后台执行训练并返回结果。节目没有进一步给出训练参数、模型地址或自动评测报告等实现细节。

孟繁青 · 00:09:50

团队的 RSI Bench 中，Agent 能修复数据造成的格式问题，但嘉宾认为它尚不能提出新的造数据洞见。机械修复与开放策略提出是两种不同能力。

话题推进：既然关键差异落在研究员的数据 know-how，主持人继续追问：数据好坏究竟怎样衡量，能否在训练前就知道？

00:10:35–00:12:48数据质量的评判：结果导向与过程中的不确定性

  • 所以你看同样的人，他做出来的数据的结果不同，好坏大概体现在什么地方？有没有一个某一个具体的例子？
  • 但你说的这个是结果上的评判吧？对，我就说是什造成了不同的这个结果呢？
  • 所以我能不能换个角度理解，就是现在数据的质量它仍然是一个比较难评判的事情。
  • 所以对于一个模型来讲，就是我们只说后训练部分，它的Infra的好坏跟数据的好坏，你觉得这个重要性占比大概是怎么样的？

孟繁青先给出训练后的结果标准。其一，数据用于训练后，能否在没有作弊或 hacking 的情况下提升目标 Bench；其二，目标能力提升是否以其他能力退化为代价，例如代码数据训练后，写作等能力是否下降。曲凯指出，这仍是在看结果，并追问造成差异的原因。

嘉宾随后把一条数据描述为“问题＋模型轨迹＋最终答案”。训练前可以检查答案与轨迹的正确性、轨迹有没有作弊，以及任务难度是否适中：太简单可能没有新增学习信号，太难也可能学不到东西。这些指标主要用于初筛，不能替代真正训练后的验收。原稿把“正确性”几乎等同于“是否作弊”，本次将二者拆开；是否 hacking 与答案是否正确是不同检查维度。

因此，本段形成的闭环是：先用正确性、轨迹和难度过滤候选数据，再训练模型，最后同时观察目标 Bench 与其他能力，失败后再改数据。嘉宾没有给出各项指标的阈值，也没有给数据和 Infra 一个数值权重；他只判断当前数据更重要，理由是 Infra 已相对稳定。这一排序是他的经验判断，且后文也说明长轨迹仍会反过来推动 Infra 改造。

结果验收至少看两项：目标 Bench 是否在不 hacking 的情况下提升，以及代码训练是否损害写作等其他能力。目标提分不能掩盖能力退化。

一条数据可包含问题、模型轨迹和最终答案。正确性、轨迹作弊与难度可做初筛，但真正是否有效仍需训练和评测。

话题推进：在数据、训练服务与评测的关系厘清后，对话转向更宏观的问题：国内模型与海外模型分别在哪些环节积累优势？

00:12:48–00:17:09反直觉的观点：国内模型优势在Pre-training创新

  • 在你你的视角看来，今天尤其是国内的这些模型，大概是发展到一个什么阶段？大家在拼的是什么东西？
  • 你说的这个其实跟我本来预想的还蛮不一样的。……我本来会觉得说……pre-training部分海外的可能它算法的人才密度会更高一点，它的卡肯定也远多于国内，然后post-training的反而是更偏工程上的东西。理论来说是国内更应该有优势的部分。
  • 所以你觉得这个观点是就是AI lab内部大家公认的一个点吗？还是是你个比较个人的一个看法？

本期最重要的技术分界，是“搜索得到一个更好产物”与“训练得到一个更强模型”。嘉宾的宽口径有助于统一讨论，也容易让两者的证据混在一起。

推理：GPU kernel 的持续修改只需固定模型、可执行环境和评分器，就能改善当前代码；即使成功，也没有证明模型下次面对新任务更强。参数更新则需要将轨迹用于训练，并在未参与搜索的新任务上复测。若进一步主张 RSI，还需多轮固定预算比较，排除只靠更长搜索时间或更多人工评分换来的单次收益。

竞争解释与边界：可用同一基础模型比较一次性生成、多样采样选优、LLM 引导搜索、搜索后训练四组，统一总调用与 GPU 预算，在保留环境和新任务上同时测量产物质量、后续成功率、人工干预和成本。这样能判断增益来自搜索、训练还是额外资源，而不是只展示一条成功长轨迹。

待解问题：复杂环境与高质量评分能否让外部教师或自生成轨迹稳定提升学生，而不是只对评分器过拟合？

待解问题：记录一个模型训练另一个模型的 RSI 轨迹，作为后续训练数据是否有超出其生成成本的增量？

下一步信息或小实验：用同一研究 Agent 分别学习普通问答、成功结果和完整 RSI 轨迹，在未见的小模型与任务上比较数据修改质量、最终学生效果、干预次数、泛化和总 GPU 小时。

怎样的结果会改变判断：若完整轨迹不能提高新任务表现，或其收益可由更便宜的过程数据获得，则“下一波高价值数据”应降为小众需求；若它能稳定减少人工诊断并提升学生效果，才支持更高价值判断。
