当软件容易被创作：Albert 谈个人工具、体验型产品、maker 社区与微型组织

本期背景与内容导览

本期主持人曲凯与连续创业者 Albert 讨论的起点，不是“AI 能否写出软件”，而是“写出软件之后，价值还在哪里”。官方简介与对话均指向 Albert 团队：过去两个月，团队五六名实际 coding 的成员在其所称 Opus 4.6 之后高频做了几十个实验，多数只达到自己可用的程度，没有正式发布；Albert 自述这一阶段收益为零。内部基建把部署、数据库和公司后端环境串起来后，一个简单想法可以从晚上九点多做到次日凌晨三点。但同事的文档工具未必适合他的工作流，说明代码供给变便宜以后，个性化反而更显眼，外部发布所需的增长、运营与需求验证也并未随之消失。 Albert 由此推演出两层软件格局：通用生产力入口可能向少数模型公司集中，个人和两三人、三五人的小团队则能以低成本服务极小众需求。他把后者称作不限于“一人”的 OPC，并用“哑铃型”描述模型巨头与长尾创作者并存、部分中型软件公司受挤压的可能未来。这是他的行业判断，不是已经发生的市场统计。长尾产品也不只承担工具功能：古文爱好者的笔记、街景地图、限定内容陪聊助眠的设想，以及 Dazz 的设计与调色，被用来说明体验、审美和情绪价值。曲凯持续追问另一面：旧平台能否承接，优质供给是否已经过剩，长尾是否最终仍向头部集中。Albert 同意头部分布必然存在，但认为新生产工具也会改变谁能创作、创作什么以及人与人的连接方式。 这条思路最后落到官方简介所述 merging.live。Albert 将其定义为面向新 maker 的社区，希望提供“回应—回响—回报”中的第二层：不仅获得曝光数字，也得到自己重视的同类创作者认可，乃至设计和调试上的协作。他自述约八人参与、做了约一个月并改了很多版，当时仍不满意媒介与网络结构，因此不能把这版理念写成已验证的社区机制。组织层面，他区分低成本个人创作与负有股东、员工责任的公司，设想微型团队、低功耗生活和按现金流分成的投资；也提出“影响力模式”和交易市场中“从 token 到经济价值”的更短计价路径。以上均为访谈时点的设想、个人观察或转述，尤其是稳定数倍收益和一人基金，不构成实盘、合规或可持续盈利的证据。 【说话人归属校正】机器转录在约 00:00:50—00:44:16 大段反置“曲凯／Albert”标签，44:16 之后恢复。审读依据官方简介中“Albert 团队几十个产品”“Albert 找到 merging.live 方向”，以及主持人问“你们公司”、受访者答“我们公司”的连续性恢复归属；因此内部实验、哑铃型结构、回响社区和 token 路径主要归于 Albert，连续质疑主要归于曲凯。这是文本与官方简介交叉校正，不冒充独立声纹识别。原逐字稿、shownotes 与两份初稿均原样保留。

曲凯先问 Albert 最近做了多少产品。Albert 自述过去两个月、在其所称 Opus 4.6 之后，团队五六名实际 coding 的成员人均每周做一两个；双方最后采用“几十个”这个约数，并非经审计的项目清单。这里的“产品”标准很低：能给自己用就算，和正式对外发布不是同一件事。Albert 明确说没有按公司经营的标准把产品发出去，并自述这一阶段收益为零。其提到的“11 月 24 日 4.5、2 月 4.6”是本人对模型迭代节奏的回忆，本期没有进一步核验版本与日期。

曲凯随后补充自己接触到的创业者：一个月前还觉得方向很好，一个月后又因模型能力变强而怀疑产品价值，只能不断 pivot。Albert 说自己也感到疲惫，对前一个热点及所谓下一代项目都提不起兴致，因为难以判断创业公司的必要性。曲凯把这种情绪推进一步：不仅创业者，成熟公司也担心要么 all in coding 模型，要么在下个时代出局。他用“压路机前捡钢镚”概括依附于模型能力的短期机会——动作快可以捡到一点，但价值有限且可能很快被碾压。这是两位对行业处境的比喻和判断，不是“所有应用创业都没有价值”的实证结论。Albert 同时看到另一面：小团队可能获得很高的生产力杠杆，OPC 因而成为值得讨论的组织形态。

为什么不发布？Albert 把答案拆成两部分。服务外部用户仍要解决运营、增长等难题；服务内部的小问题则容易得多。比如一位同事按自己的功能迭代和版本管理习惯做了文档工具，而 Albert 做事前喜欢先与 coding agent 长时间讨论，两人的工作流不同，所以同事的工具并不适合他。团队不发布的第二个原因，是认为这些工具“价值厚度”不足：其他人也可以围绕自己的问题和工作方式重新做一个。可见本期开场并没有证明“软件已经没有价值”，而是证明“可运行的软件原型”与“能服务外部用户、形成经营回报的产品”之间仍有距离。

他解释，自己从零做简单工具已经很快，前提是团队先把重复工作沉进基建。原先需要分别处理 Vercel、Supabase、后端部署和数据库，现在把这些环节一体化并接入公司后端环境，给一个命令即可完成相关准备。他举的实例是：半个月前晚上九点多想到一个 idea，到凌晨三点 coding 完并能自己使用。这个案例说明的是在其现有基建、简单功能和自用标准下，从想法到可用原型约数小时；它没有覆盖公开产品的测试、合规、客服、增长和长期维护，也不能外推为复杂软件都只需数小时。

曲凯进一步比较“拿别人的成果改”和“从零重写”。Albert 说是否修改要看品类，自己公司目前还没有发生过拿别人产品再改的情况。曲凯将其概括为个人端 fork 需求是否不多，转录此处写作 folk；Albert 没有接受这个结论，而是明确说下结论太早，取决于产品类型、发现方式和目的。如果只是让生产力工具更适合自己，改造未必普遍；如果改造本身是娱乐或非生产力体验，情况可能不同。这个保留意见很重要：它说明本期支持的是“新建成本下降”，尚不足以判断“复用、分叉和再创作”的未来比例。

面对“公司现在到底积累什么”的追问，Albert 先自嘲“没有任何积累”，随即修正为两类实际沉淀：把基建做好，以及让团队成员都能熟练使用 coding agent，在自己的生产环境中快速实现想法、提高提效能力。这里积累的是生产条件和团队能力，并不是几十个实验自然转化成的收入或护城河。

曲凯提到此前一个已发布的小产品：用户上传与 coding agent 的聊天记录，系统评分并生成个人页面；他将它类比为“新一代 GitHub”，这是主持人的类比，不是官方定位。Albert 称发布后看到市场上约十个同类项目，但团队没有继续沿这条线深入。他复盘当时的推理：如果模型提供的底层能力趋同，人的差异可能体现在怎样提需求、怎样与 agent 交流；这些对话或许能显露稀缺性，连接这种稀缺性便可能有价值。

产品中最具体的观察点叫“你拒绝什么”。Albert 认为自己这样的非工程师在多数情况下难以评价 agent 给出的方案，往往直接接受建议，因此拒绝反而可能暴露真正关心的东西。他称由此看到不同画像：有人紧盯技术架构，有人关注 UI，有人关注产品定义。这为“对话记录可能承载个人品味”提供了一个小实验，但没有证明对话能完整代表能力、品味或长期身份，也没有展开本地记录扫描、评分和隐私处理的实现。

当曲凯问起面向 OPC 的“产品基建”时，Albert 先纠正说也不能这么叫，再解释更宏观的推演：数字化的信息、数据和流程已大量进入计算设备，如果未来人主要通过 coding agent 操作这些设备，而 agent 又持续变强，模型公司便可能创造大部分价值。这是后面所有行业格局判断的前提之一，不等于所有知识工作、客户关系或线下履约都可以被 coding 一并替代。

00:10:43–00:15:12哑铃型软件格局：模型巨头与长尾创作者并存

  • （转述观点）未来的软件有没有可能发展成跟现在的硬件一样，非常垄断？

曲凯转述当天听到的观点：未来软件也许像电脑硬件，只剩少数模型或产品品牌，人们主要通过几个 coding agent 使用计算能力，不再分别打开大量 SaaS。所谓“十个牌子”只是类比中的约数。Albert 赞同这一方向，理由包括模型创造的智能价值大、模型训练是重投入且只有少数主体能做，而 Codex、Claude Code 等也可被理解为模型公司的工具容器。

他进一步预测，许多独立生产力工具可能被模型公司提供的不同 agent 入口吸收：创作任务可以采用画布，非创作任务可以采用 terminal。这里谈及 PS、IDE 等，是在描绘可能的入口整合，不是宣布这些产品已经消失。与此同时，低成本又允许创作者服务非常 niche 的需求；他举“只有一万人有共鸣”作说明，意在表达受众小也可能值得做，并非市场规模测算。

于是形成他所说的“哑铃型”：一端是占据大量价值的模型公司，另一端是充分分散的微型创作者。OPC 不一定是 one person，也可能是两三人、三五人达到过去三五十人团队的效率；中间一些过去靠软件工程积累和开发成本建立壁垒的公司会被挤压。效率倍数和中型公司消失都属于他的判断。代码实现成本下降确实削弱一类壁垒，但客户信任、领域知识、合规与履约是否也被削弱，原文没有论证。

哑铃的另一侧并不只有功能替代品。Albert 认为日常小产品可能更分散，过去较难出现品牌溢价的软件，在多样化体验与情绪影响增强后，可能出现新的溢价。他举团队里偏好古文的同事自制笔记软件：旁人觉得需求奇怪，本人却真心喜欢。曲凯由此联想到行为艺术，Albert 又以 meme coin 作情绪价值类比。三者共同表达的是“外人眼中的低实用价值不等于当事人眼中的低价值”，而不是笔记、艺术或加密资产已有相同商业模式。

推理：Albert 认为新内容需要能被原生消费的容器，又担心固定容器限制创作范围。这其实是在选择先确定交互标准，还是先让关系与作品形态自由生长。若作品运行和展示没有基本约束，消费与分发可能困难；若过早规定格式，又可能把新创作压回旧类别。可将‘最小可消费单元’作为折中实验，而不是一开始定义完整平台。

竞争解释与边界：也可能最终由模型入口直接承担运行和分发，新社区只负责人与人之间的关系层；这取决于模型平台开放程度及用户是否愿意迁移。

【本文推断】哑铃型预测把代码壁垒削弱外推为中型公司整体衰弱，论证跨度过大。

推理：客户关系、合规、行业知识、服务履约、数据接入和采购信任并不随代码生成成本同比下降。中型公司也可能用相同工具压缩成本并加深场景服务。因此更合理的检验不是数中型公司是否消失，而是看哪些价值来自可复制的实现、哪些来自难以复制的领域与关系资产。

竞争解释与边界：若模型公司的通用入口直接接管客户交互、数据与履约，或用户只需临时生成解决方案，传统中间层的确可能遭受比效率提升更深的替代。

【本文推断】‘token 到金钱’适合做成本收益核算，不足以作为策略质量的单一 eval。

推理：净收益混合了信号、决策、执行、杠杆、风险和市场环境。单看收益会奖励侥幸与承担隐藏风险，也无法分辨 AI 的信息处理贡献。若要验证 AI 的增量，应先固定策略与风险预算，比较无 AI 和 AI 辅助的信息处理，再观察成本后收益、回撤与跨期稳定性。

竞争解释与边界：在规则极清晰、可自动结算且成本低的封闭任务里，净回报可以是更直接的最终指标；它仍需包含失败样本和风险约束。

尚未解决的问题与可检验的下一步

待解问题：几十个内部实验中，有多少在一个月后仍被本人或同事持续使用？持续使用主要来自功能、习惯匹配还是创作本身的情绪价值？

下一步信息或小实验：为实验建立匿名清单，记录功能、创建时间、基建成本、首用与30天后的使用、是否经他人改造及停止原因；分开自用、同事用和外部用户用。

怎样的结果会改变判断：若大量工具持续使用且跨工作流复用，个人软件积累的价值更强；若多数很快弃用，则应把高创作量主要视为探索与情绪价值，而非稳定产品供给。

待解问题：merging.live 的‘回响’能否形成可重复的协作，而不是更窄圈层的曝光？

下一步信息或小实验：在一小组创作者中记录谁得到回应、谁被具体求助、是否发生共同修改、30天后是否继续互动，并与只提供作品展示的对照比较。

怎样的结果会改变判断：若实际协作和持续创作增加，回响机制得到支持；若只有点赞和浏览增加，或少数熟人垄断互动，则需重做匹配与网络结构。

待解问题：哪类中型软件公司的价值主要来自代码实现，哪类来自客户、合规、数据或履约？

下一步信息或小实验：按行业选取可比较产品，拆解替换成本并用同一 AI 工具重做核心流程，记录达到原有可靠性、集成与服务要求所需的额外投入。

怎样的结果会改变判断：若大量场景可低成本完整替换，哑铃预测增强；若主要节省编码时间而领域与交付成本仍高，中型公司更可能转型而非消失。

待解问题：AI 在预测或交易市场中的增量，能否在扣除成本和控制风险后跨期保留？

下一步信息或小实验：固定策略、资金与风险预算，比较无AI和AI辅助的信息处理；披露样本外区间、交易费用、滑点、回撤、容量和所有失败试验，并区分研究、信号、执行与市场环境贡献。

怎样的结果会改变判断：若增量只来自单边行情、杠杆或少数试验，‘稳定收益’不成立；若多种市场环境下仍有可重复的成本后增量，才支持更直接的AI交易价值。
