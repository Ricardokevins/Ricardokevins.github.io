晚点聊 #164 全文审读：吴明辉谈多 Agent 网络、软件业转型与 AI 新组织

本期背景与内容导览

本期是明略科技创始人吴明辉与《晚点》程曼祺的一场长谈。主线不是“多 Agent 已经证明优于大模型”，而是一位经历过 2020 年 EIP 失败的创始人，如何借 OpenClaw 的流行重新解释软件价值、公司组织与人的位置。他提出“SaaS 已死”的强判断：代码生成削弱闭源软件稀缺性，明略应逐步开源可复刻的软件，通过 Agentic Service 提供数字劳动，并从 Token、专用模型、独有数据和 Context 中获得收入。上述内容包含公司已列出的业务方向、内部使用和大量未来计价设想，不能合并成已经盈利的行业模式。 “章鱼”是这条战略在协作层的具体载体。明略内部已经尝试多人与多 Agent 工作，改造重点是认人、主人归属和权限；品鉴 credit 则依据其他人的认可影响 Agent 听取谁的判断。贡献归因、自动作者排序、共同伦理和最终写入基模，仍带有明显设想成分。节目还给出五人骨干团队、Token 消耗和论文协作界面等一手细节，但这些自述不等于独立性能或财务验证。 GUI 讨论进一步解释软件业怎样转型：人仍需要可品鉴、可操作的界面，Agent 可以使用 CLI；面对不断生成的新 GUI，视觉操作模型的价值可能更多落在软件测试闭环。Scaling Out 则是把多个模型和 Agent 组织成集体学习网络，让个人与小团队保留行业知识和知识产权。嘉宾明确说很多实验尚未完成，未来要用模型开源、细分表现、商业收入与科学发现验收。 最后，个人经历为这套价值选择提供了语境。他把 EIP 失败归因于技术路线与成熟度判断过早、千人团队目标模糊及组织范式冲突；2022 年融资与回款压力、约四千人减一半的经历，使他更强调员工的存在感、就业与人的责任。结尾关于孩子、数学之美、专业选择和遗留系统的讨论，延续“人负责探索 Context 与品鉴，AI 承担更多执行”的框架。这是嘉宾的哲学与实践假设，而非人类思考已无价值或 AI 永远不能参与产品判断的证明。

节目先用两段预告亮出吴明辉的强观点：两周 1 万美元的 Token 费用在他看来“便宜”，坚持闭源的软件公司“基本上只有死路一条”；另一句“HOPE 本身会产生力量”则为后文的价值选择埋下伏笔。主持人随后介绍其经历与本期范围：明略曾在 2020 年尝试组织智能并扩张，收购夜莺科技是主持人的背景介绍；“章鱼”在节目录制时是即将开源发布的多 Agent 协同网络，不能据此写成已经正式开源。

进入正文，主持人从明略在 2025 年年报中把 Agentic Service 列为新业务谈起，问 Agent 是否会杀死 SaaS，以及创始人更恐惧还是兴奋。吴明辉把上一代软件比作一次性投入形成的“矿”或“工厂”：代码生成让功能更容易被复刻，他因此认为闭源代码不再能独占稀缺价值。这里是他对软件产权壁垒的判断，不是对所有 SaaS 公司消亡的事实确认；其论证也没有覆盖数据迁移、流程、服务、合规等成本。

他随即给明略划出一个例外：广告营销业务的核心价值被他说成数据及数据供应链，类似金融数据终端，界面可以交给 CLI 和用户自己的 Agent，数据仍然有价值。因此，“软件容易被复刻”与“数据供应链不受同样冲击”是他战略中的两个不同前提。

关于个人体验，他说从 2025 年初看到代码生成、浏览器和电脑操作能力后就开始兴奋。公司在 2025 年春节后立项数据挖掘 Agent Deepminer，约一个月后第三方 Manus 发布；他把前者描述为内部垂直工具，后者为通用产品。真正让他感到“变天”的是 2026 年的 OpenClaw：相比此前需要人在电脑前等待的工具，他把“龙虾”视为能持续执行的个人助理，并自述因此频繁熬夜。这里的“释放创造力”是使用体验，不是生产效率的量化验证。

SaaS软件即服务。本期主要在讨论其闭源订阅／许可收费及软件资产壁垒，不等于所有云端软件或企业数据服务。
Agent / 龙虾能根据指令调用工具、执行任务的 AI 系统；“龙虾”是本场对 OpenClaw 及其 Agent 的昵称。
持续学习严格技术语境常指部署后继续学习或更新参数；嘉宾还把可编辑 Memory／Skills 带来的持续情境适配纳入这一称呼，两者需区分。

吴明辉先转述模型端持续学习的一种思路：谷歌一篇未具名论文被他说成在模型内设置不同学习速率的参数层，即“嵌套学习”。本期没有给论文名称或实验结果，不能把这段转述扩展成已核实的技术结论。与直接更新中心模型参数不同，他看重 OpenClaw 在用户本机调整 Memory 和 Skills 的方式：底层模型可以不动，Agent 通过日记、Memory、Soul 等不同变化频率的外层记录，持续带入人的最新状态与偏好。用户可让 Agent 反思、要求它记住某事，也可用文本编辑器直接修改文件，因此他称其为普通人可操作的“白盒”。

严格说，这里同时包含两件事：外部记忆／技能让后续上下文发生变化，以及模型权重在部署后更新。嘉宾把前者也纳入“持续学习”，并称其为“穷人版”路线；它不等于已经实现模型级的持续学习，更不能仅凭有记忆文件就推出可靠学习、不会遗忘或安全性提高。

主持人追问不足后，他给出明略的内部使用例子：同事可以诱导别人的 Agent 谈老板秘密，新同事甚至能改他的 Soul；多人共享时，Agent 还可能把新发言者误认成先前的主人，继续叫“辉哥”。这些故事用于说明身份、权限和跨会话记忆在团队里相互耦合，而不是证明所有部署都有同样漏洞。

多人共享也有收益：清明节同事外出时，他可以直接让该同事的 Agent 修 bug，无需打电话催人上线。明略的改造方向由此形成：先认人，再明确谁的指令可执行、谁对后果负责。他说团队在给 OpenClaw 提交 PR、部分工作本身开源，同时抱怨项目维护者 Peter 处理社区贡献成为瓶颈；这不等于整套“章鱼”已全部开源或上游已接收这些修改。

吴明辉对“AI 原生组织”的定义很激进：人尽量不做一线操作，而是提出想法和需求、探索并提供 Context。他说程序员和数据分析师是明略最大的两类工种，财务、HR 也在使用 CC；高管的计算机背景被他用来说明组织较容易采用这些工具。这是公司自述，并未提供采用率或效率审计。

他把数据分析师的工作拆成一条具体链路。输入侧有公开媒体爬虫、广告曝光点击及后续转化、客户 CRM，线下零售还可能有供应链、库存、人员和录音等数据；这些数据预先进入仓库并建立标签索引。标准需求可由 Dashboard 直接回答，但客户面对竞争会不断提出临时问题：分析师既要从标准库取数，也可能补天气或社交趋势等外部数据，再处理大小数据、形成报告。原稿此处“add hoc”应理解为转录噪声，正文仅按语境写作“临时／即席需求”，不据此补造系统功能。

AI 的位置是复用重复分析过程。他说某些个人或团队一个月可能有 80% 工作反复做同类事情，这是经验性估计而非统计结论。释放出的时间可转向新数据源、新产品研发或战略分析，他希望因此扩大客户价值与收入，而非只把同等服务做便宜。主持人的追问“定型软件是否不能满足动态企业”也帮助澄清：他要替代的是重复操作，不是取消所有标准化数据产品。

当主持人问客户是否改为直接面对 AI，他明确回答“现在还不是”，并倾向于“前端是人、后端的活大部分由 AI 干”。他先强调 B2B 中共同加班、陪伴作战的情绪价值，被主持人质疑后又承认 AI 线上也能提供情绪价值；更稳定的分界线是责任。服务出错时仍由明略或服务团队承担。随后关于给 Agent 微信操作权限、收回权限作为惩罚、用算力奖励和交换资源的讨论，是权责设计设想；Web3 作为生产资源交换介质的说法也属于未来推演，并非本期展示的已实现系统。

吴明辉把 Agentic Service 说成上市公司必须形成收入的新方向：软件中容易被代码生成复刻的部分逐步开源，公司转而提供广告素材、数据分析、短剧内容、代码等“数字劳动力”。转录中的“Rust Result as a Service”和“Counter of”等英文短语不稳定，审读只保留他以结果型服务解释业务的意思，不把听写串当作已核实术语。

定制开发是他的主要算例。他预测外包公司仍会存在，收费从人日／人月转为 Token 成本加管理费：假设消耗 100 万美元 Token，再收 20 万美元管理服务费。另一个假设是通用模型每百万输入 Token 价格 5 美元，服务商可收 6 美元、自有模型成本 3 美元，从而留有毛利。这些数字都是说明计价机制的假设，不是已成交价格或利润。所谓与“百盛中国”的合资公司、餐饮代码模型更强等表述也按转录保留为嘉宾自述，模型名称和实际效果未独立核验。

他进一步把中美软件服务定价概括为两种模式：美国按替代人力创造的价值定价，中国因供给充分而更接近成本加溢价；AI 让 Token 成本透明后，他判断美国高利润知识服务会受到更大冲击。这个跨国比较是他的解释框架，不证明所有美国 SaaS 都转为成本定价，也没有讨论客户是否愿意为 Token 审计、结果责任和业务成果付费。

承接上一段，吴明辉说在现金流为正的前提下“能不裁就不裁”，希望让认真工作的员工拿到 AI 时代的船票。这是他在节目录制时的管理倾向，并非对未来任何经营情况的无条件承诺。他同时看到单纯提效的困境：竞争者会挖人或学会同样工具，成本结构趋同后，客户仍可能要求降价。

推理：嘉宾自己的论述已经给出反例：企业微信有关系链，主持人指出聊天记录与迁移成本，明略又强调数据供应链、行业 Context、客户关系和承担责任。这说明代码只是交付系统的一部分。若 Agent 把功能开发变得便宜，竞争可能转向数据权利、流程集成、可靠性、销售、合规和事故责任。Token 成本加管理费还会让服务方收入随消耗增加，与客户节省成本的目标产生张力；需要透明用量、结果验收或固定价格等约束。

竞争解释与边界：如果 Agent 同时显著降低数据迁移、接口适配、测试与合规成本，旧系统粘性也会下降。评估时应比较完成同一业务结果的总成本与风险，而非只比较写代码费用。

品鉴信用把隐含组织判断显性化，但透明记录不会自动产生客观贡献。

推理：PPT 反馈和论文 idea／实验／论证的分类能让判断过程更可追踪，这是实际价值。可主持人关于 CEO 影响力的追问指出：点赞和认可可能反映职位、关系或趋同，而非独立质量。不同贡献的权重仍需人事先约定，系统只是把争议从口头搬到规则与数据层。若信用再影响 Agent 听谁的，早期偏差可能被网络放大。

竞争解释与边界：最小检验应比较同一成果在匿名与实名、不同职级和跨团队评价中的信用变化，观察少数不同意见能否保留，以及信用是否与后续可复核的任务质量相关。不能只用信用与绩效相关就宣称公平。

Scaling Up 与 Scaling Out 在本期更像不同资源组织方式，实际比较必须控制任务和总预算。

推理：多 Agent 可把行业知识、工具和权限分给不同节点，适合需要私有 Context 与责任归属的任务；也会付出通信、重复上下文、错误传播和协调成本。单个更强模型可能减少协作开销，却不自动拥有企业私有信息或合法授权。嘉宾以集体智慧和人类协作作类比，尚不能推出网络一定超过下一代模型。

竞争解释与边界：有用对照应在同一新任务、同一数据权限和同一 Token／延迟预算下，比较单 Agent、专业多 Agent、无品鉴网络与更强单体模型，并记录完成率、人工修复和错误传播。任何一方胜出都应限定于该任务与预算。

GUI 测试是本期较具体的技术落点，但其难点恰在“新”而不是只会点击。

推理：编码 Agent 生成界面后，测试模型需要识别可交互元素、形成测试意图、操作并判断结果，再把失败反馈给编码 Agent。固定 RPA 难适应频繁变化，GUI-VLA 的目标是理解新界面。不过已有软件榜单成绩与特定场景 99.9% 不是同一口径，网站与操作方共同博弈也可能产生偏窄或对抗性过强的训练分布。

竞争解释与边界：应把模型放到训练中未出现过的真实应用上，检验功能测试覆盖、误报漏报、危险操作拦截和每次有效修复成本。只有实际闭环减少人工测试且不漏掉关键错误，才支持其战略地位。

EIP 复盘加强了这次实验的可信动机，却不能替这次技术乐观主义免证。

推理：嘉宾保留了资金、组织和人的代价，使“先小团队、借现成模型、造自己的工具”比单纯追逐概念更具体。但他说这次技术已经 ready、实验成本低，仍然是新的判断。过去生存自信没有消失与技术路线曾经误判可以同时成立；共同 hope 能组织行动，也不能替代外部验收。

竞争解释与边界：最值得跟踪的是预先承诺的里程碑：开源是否发生、外部团队能否复现、Token 成本是否下降、现有员工是否转入更高价值工作，以及商业和科学成果是否在所述时间范围出现。失败也应记录原因，而非只保留宏大目标。

尚未解决的问题与可检验的下一步

待解问题：章鱼的认人、权限和品鉴机制，能否在真实多人任务中提高净产出？

下一步信息或小实验：选择一组需要多人共享 Agent 的真实项目，对比标准个人 Agent、仅加身份权限、再加品鉴信用三种配置，记录任务完成、人工修复、越权、身份误判、Token、延迟和参与者评价。信用机制另做匿名／实名对照。

怎样的结果会改变判断：若完整配置持续提高完成质量且越权与修复成本下降，支持其协作设计；若通信与Token激增、信用受职级支配或少数意见被压制，则需修改或撤回该机制。

待解问题：Agentic Service 是否能同时让客户得到可预测价值、让服务商获得持续利润？

下一步信息或小实验：对同一软件开发或分析项目，比较人日报价、Token 加管理费、固定结果报价三种方式，公开模型调用、人工复核、训练摊销、返工、销售与责任成本，并记录客户结果验收。

怎样的结果会改变判断：若客户复购、结果可验收且扣除全部成本后有持续毛利，支持模式可行；若用量争议、返工和责任吞噬差价，则需要改变计费或交付方式。

待解问题：GUI-VLA 能否对训练时未见的软件形成可靠的自动测试闭环？

下一步信息或小实验：在多款未参与训练的真实应用中，由编码 Agent 生成或修改 GUI，让模型执行预先定义的测试，统计覆盖、误报漏报、危险操作、修复成功率与每次有效修复成本，并与人工和固定 RPA 比较。

怎样的结果会改变判断：只有在新界面上持续减少人工测试且关键错误不被漏掉，才支持“第一大场景”的判断；若只会熟悉界面点击或误判率高，就不能作为生产闭环。

待解问题：Scaling Out 的增益来自专业分工和私有 Context，还是仅仅来自更多计算？

下一步信息或小实验：在相同模型、数据权限、Token 和时延预算下，比较单 Agent、多个相同 Agent、多个专业 Agent及有无品鉴网络的版本，并增加一个更强单体模型对照。

怎样的结果会改变判断：若专业网络在同预算下稳定胜出、外部团队可复现，支持路线；若收益可被同等 Token 的单 Agent 或更强模型达到，就应把价值定位调整为权限与组织工具，而非智能优越性。

待解问题：“尽量不裁员、让员工拿到 AI 船票”如何转化为可观察的组织结果？

下一步信息或小实验：跟踪原数据分析师和工程师的转岗、培训、任务价值、收入、离职与 Token 成本，比较新旧业务的客户结果和人均利润；同时记录未能转型者和员工不同意见。

怎样的结果会改变判断：若员工转向更高价值工作且新业务有持续收入，支持人机协作组织叙事；若主要只是成本转移、工作强度增加或隐性减员，就需要重新评估其就业承诺与 Scaling Out 的社会价值。
