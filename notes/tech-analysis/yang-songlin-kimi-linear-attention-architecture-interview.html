杨松琳访谈深读：注意力的下一场竞争是状态、硬件与评测的共同设计

一道题如果要生成几万个 token 才能解出来，模型到了最后几步，还能怎样找回开头的线索？Kimi Linear 发布后，《张小珺商业访谈录》请来论文作者、当时在 MIT 读博的杨松琳。她和张小珺从 Kimi、DeepSeek 和 MiniMax 的不同选择谈起，最后回到她自己的研究经历，以及年轻研究者怎样获得验证架构的机会。

#119 · 张小珺访谈杨松琳 · 1 小时 43 分 25 秒

访谈原文讲解

片头约一分半是后文的剪辑。正式开场后，张小珺把这次谈话放在 2025 年的模型研发背景中。当继续增加数据和算力越来越难，提高同一份计算的利用率还有哪些办法？杨松琳从她亲手做过的序列模型和公开的架构说起。

04:00–20:20　从加速 RetNet 到 Kimi 的规模筛选

杨松琳最初读斯坦福 Hazy Research 写序列建模的博客。读博之初，她想提高微软 RetNet 的运行效率和模型效果，随后发现，把递归计算改写成 GPU 可并行执行的形式，同样能用在别的模型上。她和 Yu Zhang 合作开发了开源库 flash-linear-attention（FLA），让研究者可以直接调用这些实现。后来也是 Yu Zhang 邀她参与 Kimi 的工作。

主持人请她解释“线性”指什么。设序列有 L 个 token，每个位置产生查询 Q、键 K 和要读出的值 V。全局因果注意力用当前查询和此前各位置的键打分，经 softmax 得到权重，再加权读取值。整段序列要处理的配对数随 L 的平方增长。她先用去掉 softmax 的简化情形解释另一种做法。先把历史各个键和值的外积累加成固定形状的矩阵，再拿当前查询乘这个矩阵，就能读出按查询与键的匹配程度加权的值。后来的变种改变了写入规则，仍然可以逐步更新固定形状的状态。宽度固定时，每来一个 token，更新和读取这份状态的工作量都不随已见长度增加，走完 L 步的工作量随 L 线性增长。Transformer 每层还有处理各位置表示的前馈网络（FFN）。混合专家（MoE）改的是前馈部分，这场访谈讨论的几种注意力则是预训练前就要选定的另一部分。

为什么在那时重新选注意力？她举 DeepSeek-R1、Kimi k1.5 为例。强化学习和推理时增加计算，让模型一次可以生成几万个 token。全注意力会缓存每个历史位置的键和值（KV cache），后面的每一步都要再读越来越长的历史。单条序列占用的显存上升后，同时能跑的序列也变少。Kimi 想保住原有任务表现，同时让这种长生成跑得起。

Kimi Delta Attention（KDA）的具体改动落在遗忘门上。此前的 Gated DeltaNet 已经能用 delta rule 更新某个键对应的值，但为了便于 GPU 并行，每来一个 token，同一注意力头内的各个维度共用这次输入算出的一个衰减率。KDA 让同一头里的不同维度根据当前输入分别决定保留多少旧状态。早先的 Gated Linear Attention（GLA）已经试过细粒度门控。新的并行算法和算子让它能够与 delta 更新放在同一个模块里。

约 19 分钟，杨松琳解释团队怎样判断一个改动值得继续投入。先在小规模比较多种混合方案，表现好的进入下一档，再和全注意力基线比较。有些小规模看好的候选到下一档仍会落后。这也是团队继续尝试更细粒度衰减门控的原因。

20:20–28:05　几家公司各自省下了什么

张小珺问 Kimi 和 DeepSeek 各适合什么任务。杨松琳先解释二者为何都瞄准长文本解码。Kimi 和千问用许多递归层替代全局层，递归层省下逐位置增长的缓存，同一张卡便可能容纳更大的批次。DeepSeek-V3.2-Exp 的稀疏注意力（DSA）则用一个索引器给历史位置打分，只让得分最高的 k 个位置参与本次主注意力计算。下一次查询仍可能选中今天没选的位置，因此各位置的表示还得留着。DSA 这里省的是一次查询要做的主注意力计算。每个位置的 KV 如何用 MLA 压缩，是另一项设计。

MiniMax 的变化说明指标会影响选择。M1 在七层 Lightning Attention 后接一层全注意力。按杨松琳对团队经验的转述，早期监控的 MMLU 等指标表现不错，随后才发现长文本里一环接一环找证据的多跳题掉点明显。M2 这一版回到全注意力。她猜代码和 Agent 任务更加依赖多跳关系，可能促成了这次取舍，也提到团队仍在探索混合方案。这是她在团队之外的解释。谈到硅谷时，她只举有公开说明的例子，GPT-3 曾交替使用全局与局部带状注意力，gpt-oss 也搭配了滑窗与全局层。

28:05–38:16　记忆怎样遗忘，怎样改写

主持人请她把近几年的进展串起来。第一条线是改遗忘。以 RetNet 为例，假设旧状态每一步都乘 0.99，同样多走一步，留下的比例总是一样。改成输入相关的门后，有用的线索经过许多步也可以继续保留，遇到新话题则可以迅速淡出。第二条线是改写入。早期规则把新键和值的外积加进状态（Hebbian 更新），同一个键先后对应的内容会叠加。delta rule 先拿当前键读出旧值，再用学出的、介于 0 和 1 之间的系数 β 决定向新值移动多少，把差额沿这个键写回。这样就能有针对性地修正一条关联。

她把研究热度的两次变化放在不同环节解释。早期卡在训练，当时 BERT 常见的长度只有 512，2K 或 8K 就已经很长。普通实现把巨大的注意力得分矩阵写到显存再读回，既慢又可能放不下。FlashAttention 分块计算，省掉来回搬整张矩阵的开销，全注意力仍然计算这些位置配对，训练却可以快很多。后来卡在逐词解码，生成到几万步，每一步都要读更长的缓存。这个成本让递归状态重新有了吸引力，此时 FLA 已让团队有现成算子可以试。

38:16–47:55　三层 KDA 后为什么还要一层全局注意力

长度持续增加而状态的容量固定，早先的细节会在更新中丢失。杨松琳因此看重混合模型中的全局层，当前查询在这些层仍可以直接与很早的位置匹配。Kimi Linear 论文第 4 节和公开模型采用每三层 KDA 后接一层全局 MLA（多头潜在注意力）。Qwen3-Next 也采用每四层一层全局注意力。她把 3:1 称作几支混合架构团队逐渐接近的选择，同时指出 DeepSeek 还在走另一条路。

张小珺接着问，表达能力和计算效率是否是设计中最重要的两项取舍。杨松琳举 RULER 等评测说明混合模型也能处理长文。但短题分数持平，仍可能掩盖跨段多跳的损失。这类任务先要找到一处关系，再顺着它到另一处取证，往往更依赖全局层。反过来，训练好的网络有些层功能冗余，并非每一层都需要遍历全部历史。她转述 Yu Zhang 的实验观察，说细粒度衰减对多跳、代码和数学任务有改善。若能做出既可高效并行、又能更好更新状态的循环网络，差距也许还会缩小，这是她对后续工作的预期。

问到个人贡献，她把分工说得很具体。Yu Zhang 在 Kimi 做了主要的架构比较与消融。她从一项减少求逆次数的已有算法得到启发，推导出适合 KDA 的分块并行算法，把一串有前后依赖的更新改写为块内可并行的矩阵运算，再在块之间传递状态。Yu Zhang 据此写出 GPU 算子并验证放大后的表现。

47:55–57:05　研究员问注意力怎样设计，为什么还要和滑窗比

张小珺代一位研究员问，还有哪些值得做的设计。杨松琳把混合线性和动态稀疏看作两条主线，也提到有人保留甚至增加运算量以换取表达能力，或把 delta 更新引入 softmax 注意力。她自己最想试的是保留多数递归层，把少数全局层换成动态稀疏层。理由是长度足够大时，混合模型里剩下的全局层仍会拖慢解码。层层都用 DSA 又要管理所有位置的缓存。搭配起来，多数层可以节省缓存，少数层仍有机会检索远处的原始位置，每步只对选中的位置细算。

这个设想依赖索引器选得准。若问题需要三段前提，索引漏掉一段，该层主注意力就读不到那段。她担心从零学习这种离散选择时，梯度只能经过少数已选位置，索引器很难学好。她举 DSA 为例，用稠密注意力的分布给索引器提供学习目标。在录制时，她见过学界尝试把两种层放进一个模型，工业界有没有团队同时采用，她只谈自己见过的范围。再比较 Kimi 和 M1 时，她看重这几年陆续验证过的门控和 delta 更新，也提醒两者的其他模块有所不同。

55:36，怎样才算和滑窗公平比较？ 她认为线性层更直接的对手是滑窗层，两者都能替掉一部分全局层，而且状态容量都有上限。窗口宽度为 W 时，最近 W 个 token 的键和值可以逐个取回，更早的位置退出该层窗口。递归层则始终保留一份固定状态，远处的信息可以留在里面，也可能被后来的写入覆盖。

她具体展开的比较办法，是把滑窗存满时的 KV 缓存与递归层的状态放到同一容量预算下，例如按各自实际占用的字节数对齐，再比较模型保住了哪些信息。她判断，当逐词解码的瓶颈在显存带宽时，每步需要搬动的状态量相近，速度也有可能接近。这个判断有带宽瓶颈的前提。两种状态占用相同，回答多跳题的能力仍可能差很多。

57:05–1:07:43　同样的计算预算，还能扩什么

从 Transformer 到 MoE，再到新的注意力，杨松琳认为训练端追求的是用同样多的浮点运算取得更低的损失。MoE 让一个 token 只激活部分前馈专家，于是可以在相近计算量下容纳更多总参数。注意力这边，她更想扩的是上下文长度，例如多个 Agent 执行一项工作时，要反复读取已累积的步骤和结果。DeepSeek 等团队使 MoE 在她看来成为近几年最大的架构进展，注意力可能是下一个。被请来打大脑的比方时，她把处理当前上下文的注意力比作工作记忆，把前馈网络在训练中习得的知识当作参照。

如果数据不再能任意加，怎样从相同数据学到更多、怎样节省算力，就更值得研究。张小珺问架构还有什么上限，杨松琳先想到仍在限制上下文长度的全局层。若处理长上下文足够便宜，有些现在靠外部检索增强生成（RAG）解决的问题，可以把材料直接放进上下文。接着她才提到让模型持续学习，乃至从零以强化学习获得经验。这些是她想看的后续方向。

1:04:30，另一道由主持人转达的研究员提问是，怎么把线性注意力模型继续做大？ 杨松琳答的是工具配套。FLA 的 Triton 算子让人能动手试，性能还有优化空间。半年前参加圆桌时，她就把基础设施列为瓶颈。Qwen、Kimi 发布采用新层的公开权重后，SGLang 等推理框架有动力支持，下一家尝试时便不用从头实现训练和部署。她期待使用者增多后，又能带来新的优化。

1:07:43–1:15:16　国内团队的选择能比较到哪一步

主持人问中国和硅谷谁的算法创新更强。杨松琳明确把自己的判断限在基础架构上。她更看好国内团队在这方面的尝试，理由是卡少，对效率的要求更迫切。在她的观察中，美国团队在优化器上投入更多，国内团队也在跟进，Kimi 是较早大规模使用 Muon 的例子。

具体追问 Kimi 的线性方案和 DeepSeek 的稀疏方案谁更好，她回答无法判断。不同厂商一起改了训练架构、数据配方和优化方法。Kimi 报告有同配方的全注意力对照，却没有把 DSA 放在同样条件下再跑一遍。为什么不两路都跑？卡有限时要先验证一路，是她提出的一种可能解释。

位置编码也还没有统一做法。Kimi 的全局 MLA 层采用 NoPE，不额外加显式位置编码，递归层的更新顺序仍携带位置信息。Qwen3-Next 的全注意力选择部分旋转位置编码（RoPE），25% 指查询和键的每个头中参与旋转的维度比例。她猜测，在这类混合模型中少加一点旋转约束，可能更容易处理超过训练长度的输入。聊到 DeepSeek-OCR，她看得清的一项用途是把书籍和 PDF 转成训练文本。将上下文转成图像来压缩是否划算，她还拿不准。

杨松琳也划清了参与范围。她给 Qwen3-Next 团队做过学术讨论、回答问题，没有参加模型训练，也没有参与 MiniMax M2。她说“雕架构”可以是把一个有用的模块逐步打磨好，MoE 就经历过这样的过程。这个判断也有适用条件，她拿机器人举例，如果增加数据仍有明显收益，先去收集数据可能更值。

1:15:16–1:29:50　为什么选择架构研究，为什么回去读旧论文

主持人后来问到研究兴趣从哪里来。杨松琳本科时就对机器学习感兴趣，硕士阶段在上海科技大学做自然语言处理。她回忆，从过去分任务研究转到语言模型后，可以集中讨论一批通用问题。博士申请结束、入学前的空档里，她花约半年读架构旧论文，记住了 2021 年的一项 DeltaNet 工作。后来大家关心从前文找回信息，她想起这条路线已有记忆更新办法，但高效并行的问题还留着。这解释了她为什么会把旧想法和新的实现工作联系起来。

转折发生在做完 GLA 之后。她已经知道 DeltaNet 怎样修正旧记忆，当时缺少能大规模训练它的算法，这就给了她一个可做的问题。再往后，DeltaNet 在一些任务上落后于 Mamba2，她借来后者的门控，与 delta 更新结合。她说自己读博总体顺利，既得益于事前熟悉领域，也有运气。对她而言，清楚什么问题值得解，遇到技术障碍便比较容易接着走。她喜欢算法，也喜欢看到不同任务的研究者实际用上自己写的代码。论文里公式多，常常是因为要证明逐步递归和分块并行给出相同的状态，最难的是找到能并行的写法。

1:23:12 起，两人把“考古”落到几个实例上。从 Transformer 的绝对位置编码，到后来常用的相对位置表示。从 MoE 一度受冷落，到 DeepSeek 等团队把它做成可用模型，技术会被重新拿出来试。在注意力上，她回看早期用核方法逼近 softmax 的工作，个人并不看好这条路线。相反，2021 年 DeltaNet 的定向写入令她一直惦记。细粒度遗忘很早就有人做，后来的实现却曾为效率退回粗粒度。稀疏路线也从 Longformer、BigBird 等预设连接，经过常用的滑窗，发展到按当前输入动态选择历史。她觉得有些想法沉下去，只因当时的代码别人很难接手。另一种情况则是小模型有效，放大后经不起验证。前一种情况值得回去把算法实现好，后一种则需要新的规模实验才能判断。

1:29:50–1:43:25　硬件怎样影响下一种算法，年轻人怎样入场

张小珺追问 delta rule 给她的灵感。杨松琳把采用这条更新规则的早期工作归给 2021 年的作者，把自己的工作比作 FlashAttention 对 softmax 注意力的贡献，即找到能让已有规则在硬件上高效执行的算法。她看一个老想法，会同时问它在学习上解决什么问题，以及更新能否并行。Transformer 就是一个例子。LSTM 得沿时间逐步传状态，Transformer 的全局注意力虽要处理更多配对，却能把大部分工作交给并行矩阵乘，也给远隔的位置建立了直接联系。

她选题时看重矩阵乘、内存层级和数据搬运这些不同芯片共有的特性，没必要一开始就把算法绑在 H100 这个型号上。研究原型可以先用 Triton 快速迭代，验证想法后再花时间打磨 CUDA 算子。她没有确认 Kimi 后来会怎样选。她也看到反方向的影响。Transformer 大量做矩阵乘，GPU 就围绕这种运算演进。Tensor Core 加速矩阵乘，TMA 在显存和片上存储之间搬运数据，Blackwell 又为矩阵运算提供专用存储。替代算法面对的，是一个也在随硬件不断提速的全注意力实现。她举 FlashAttention-4 为例，矩阵乘快到一定程度，softmax 中求指数的开销便显出来，近似算指数也值得优化。

谈执行速度时，杨松琳区分训练、处理输入提示的预填充（prefill）和逐词生成（decode）。只要前两步耗时能接受，最后一步足够快，长输出场景就可能愿意采用新架构。前面提到的多跳题则检验模型在生成过程中能否用对远处的证据。她还举 DeepSeek 的索引器说明怎样利用芯片特性，用 FP8 运算给候选位置打分，取前 k 名只需比较分数大小，省去了 softmax 中的求指数。这个简化发生在选位置的阶段。她由此推测 DeepSeek 的基础设施团队对架构选择影响较大，对 Kimi 内部怎样权衡、下一代模型会采用什么，她都没有把握。

1:42:23，主持人问想做注意力或架构的年轻研究者应该从哪里入手。杨松琳的回答很具体，先找一家能做这类实验的公司实习。她给的理由是，架构需要算力验证，小规模成立的变体常常放大就失效。读老论文和写开源库是她自己的研究路径。结尾这条建议针对的是怎样碰到真正能做规模验证的条件。

笔记分析｜在相同状态预算下，能读回什么

线性层可能因少存历史而省显存，稀疏层可能因少算位置而缩短每步时间。判断谁更适合一个任务，我会先问它能留下哪些信息，再问下一次查询能花多少计算去读它们。

一层中的做法生成下一步之前保存什么本次查询怎么读最值得检验的情形
全局注意力每个已见位置的 KV 或相应的压缩表示，随长度增长。可直接与每个已见位置匹配。精确回看有收益时，长序列带来的带宽和显存开销有多大？
滑窗注意力最近 W 个位置的 KV，窗口满后容量封顶。窗口内逐个匹配，窗口外的信息需借其他层传来。若把关键证据挪到窗口外，正确率怎样变化？
线性递归层定形状态，旧信息在更新中压缩。用查询从状态取值，留下的关联可能跨越很长距离。较旧的关联和相似的新关联会不会互相干扰？
动态稀疏注意力（以 DSA 为例）留有供未来检索的逐位置表示，还需保存索引用的键。先打分，再在选中的位置上做主注意力。关键证据的入选率有多高，选 k 个位置本身花了多少时间？
分层混合各层自行保存状态，总开销取决于层比。大部分层以较低成本更新，另一些层有机会直接读到远处位置。减少一次全局访问后，跨段组合需要的中间信息还能传到下一层吗？

一个等容量的算例。 假设只有一条序列、一层、一个 KV 头，键和值各有 64 个数，每个数用 BF16，占 2 字节。窗口存 32 个位置，KV 共占 32 × (64 + 64) × 2 = 8192 字节。一块 64 行、64 列、同为 BF16 的递归状态也占 64 × 64 × 2 = 8192 字节。两边都是 8 KiB。若问 40 步前出现的名字，滑窗层已移出那个位置，递归层却可能仍保留相关信息。若问窗口内刚被反复修改的一条记录，显式保存各次记录也可能有优势。算例只计这两块持久状态，实际实现还要计其他缓存、状态精度，以及每步的读写和计算时间。

再看一次定向写入。假设只有一个单位键，忽略其他键和遗忘。它原来读出 2，新的目标值为 6，写入系数 β 为 0.25。用 delta rule 修正后，读出变为 2 + 0.25 × (6 − 2) = 3。新值纠正了同一键的旧答案。多条关联共享一块矩阵时，还要检验写入一条是否干扰另一条。

怎样测到被短题均分掩盖的损失

我会用四类问题检验这些差异。先问单个事实，再给相互冲突的版本，让模型找到指定时点的证据。第三类让答案必须串起分散在多段里的事实。例如，一段记着谁接收了包裹，另一段记录这个人的地址，问题问包裹最后去了哪个城市。第四类再让工具返回改址通知，观察模型能否修正刚刚给出的城市。这样，一个会找名字却常接错关系、或得到纠正仍坚持旧答案的模型，不会只留下一个模糊的均分。这是本文提出的评测设计。

分别计时

记录预填充耗时、每步解码耗时和同卡总吞吐，同时标明输入长度、生成长度、批大小、硬件与精度。省缓存后能放进更多序列，这项收益可另测。

控制会改变结论的条件

对照注意力机制时，应报告训练数据、激活参数、层比、位置编码和优化配方。比较滑窗与递归层时，还要列出每层每序列的状态字节数。

定位失败发生在哪一步

分别检查该保留的事实是否仍可读、索引是否选中证据、拿到证据后是否能完成多跳，以及给出反馈后能否纠错。

笔记作者的进一步判断

  1. 不同任务可能需要不同层保留细节。 照抄最近一段和沿多段证据找关系，即使输入长度一样，对直接回看的要求也会不同。调层比时可以看是哪一类题先受影响。
  2. 报告模型规模时值得给出状态的两项成本。 每条序列的固定状态，以及每多一个 token 要增加的缓存，决定服务长短请求时能同时接住多少条。参数量本身给不出这个答案。
  3. 选择错误是否会传到最终答案，可以单独测。 稀疏层漏选证据时，该层读不到它，后续层却可能把它找回来。给索引器指定正确证据再测一次，可以区分漏检和拿到证据仍推不出答案。工具反馈后的纠错也可以作类似的对照。
  4. 社区能否接手一项研究，会改变下一轮能获得什么证据。 易用的算子、公开权重和框架支持让别的团队也有条件试到失败。相反，单凭几家公司的发布结果，很难判断算力约束是否促成了某种架构选择，也推不出哪条路线在相同资源下占优。

哪些结果会改变这些判断

  • 如果纯递归模型在相近的训练和推理预算下，稳定追平混合模型在多跳推理与精确检索上的表现，就应重新估计保留全局层的必要性。
  • 如果 DSA 类索引器选位置的时间抵消了主注意力省下的时间，或关键前提屡被漏选且后续层难以找回，就应下调对该配置的效率或能力预期。
  • 如果 KDA 在一种硬件或一种任务长度下的收益换个条件就消失，应把结论限于能重现该收益的配置。
  • 如果仅扩大窗口就能让模型在工具任务中读回证据、纠正旧结论，为这些任务专设摘要或回退机制的必要性就会降低。
