完整对谈重建：MiniMax Dev Meetup 现场的五场交锋

本期《十字路口》录制于 MiniMax 首届核心开发者聚会（MiniMax Dev Meetup）现场，由 Koji 主持圆桌。难得公开露面的 MiniMax 创始人兼 CEO 闫俊杰（IO），与三位来自开源框架、工程实践与上市金融公司的技术一线同台，集中回应了 2026 年中 AI 研发最尖锐的几个问题：一代模型好不好究竟看什么、10T 参数为何差整整两代、Vibe Coding 为何让人“不敢上线”、为什么大模型公司开始聘请核物理学家，以及在 AI 逼近人类智能的背景下人该守住什么。

一、为何亲自下场办开发者聚会：从“两年前问梁文锋”说起

Koji 开场直言颇感意外——原本以为创始人只做简短致辞，没想到闫俊杰不仅全程参加，还做了大段深度分享。闫俊杰解释，核心目的是当面感谢社区：包括打造出 7 万星开源项目的何涛，以及很早就给 MiniMax 提过大量建议的张佳圆。

他借此回忆起两年前的一段行业往事：当时他曾问另一家公司创始人梁文锋“你们要不要做 AI coding”，对方回答不做，理由是全中国会写代码的人可能只有一两百万，看起来不是一个大市场。仅仅两年后，整个前提已被颠覆——AI 编程与生成式 AI 不会让从业者变少，反而让更多人拥有了原本属于程序员的生产力。但哪怕面向普惠，新范式的扩散仍需要最初一批真正热爱编程的核心开发者去点燃与传播。因此 MiniMax 打算把开发者聚会变成持续机制。

二、从 M1“后背发凉”到 M2.7 日耗十万亿 Token：克制取舍与 M3 定位

面对 Koji 提问“从 M1 到 M3 哪些突破符合预期、哪些尚未达到”，闫俊杰首先给出了一个区别于榜单跑分的硬标尺：Token 消耗量（Token 是模型处理文本等内容的基本计费与计算单位）。他坦承 M1 最终产品效果不算好、消耗量也很低，但团队其实早在 M1 时期就亲历过震撼时刻——去年五一假期，团队第一次在 M1 上跑通编程刷题时，全员都有一种“瘫坐在椅子上、后背发凉”的感觉。

真正的路线抉择发生在去年下半年做 M2 时。彼时整个行业发布模型几乎都紧盯 LMArena 对话评测榜单，MiniMax 却顶着内部大量质疑做出极端聚焦：只做 coding 和 editing（编程与编辑），主动放弃不相关的通用对话场景。模型刚上线时（发言泛称 M2，官方简介记作 M2.5），团队觉得如果每天消耗 1 万亿 Token 就非常满意；结果到 M2.7 阶段，日消耗量一路冲到约 10 万亿 Token，超原定目标整整 10 倍。对于 M3，团队定下了更大目标，当时尚未完全达成。

在具体能力上，他同样毫不讳言偏差：做 M2 时原计划实现多模态，也希望 M2 直接成为编程里的主力模型，这两项当时都没做到；反而是后来 Claude Code 与各类 Agent 工具爆发，让专注 coding 与 editing 的模型切中了真实大市场。到了 M3 这一代，团队设定了两大轻量模型目标——让大家无需顾虑费用、几乎无限制地使用（口述提及 30B 和 20B 档位模型），再叠加整个行业的大盘增长，总量正逼近非常可观的量级。

三、一线实操样本：多模型编排、七万星开源社区与金融决策

多模型协同压降成本（张佳圆）：紧接前序关于 Loop Engineering 的分享，张佳圆谈到用 M3 跑真实工程的体感：处理 GitHub issue、客户支持等流水线场景不必每步都用最贵模型。团队每人手握多个 Claude Code 账号再加 Codex、Cursor，月耗数千美元。他们的解法是用系统聚合弥补单模型短板——M3 有时偏啰嗦、思考耗时偏长或偶有疏漏，就让 M3 承担主力编码，再让 Opus（转写音译作 ops）或 GPT 做审查（reviewer）或导师（mentor），平衡 Token 成本与产出质量。

七万星开源项目的双重身份（何涛）：首次公开解释 DeerFlow 为何斩获 7 万星时，何涛坦言团队也没找到必然公式，走红往往像“上帝握着你的手写代码或说话，交给 Claude Code 或 Cursor 写出，X 上一转发就火了”。但 DeerFlow 有两个清晰身份：

  • 用国产模型打样的桌面全能工具：2025 年因不满 OpenAI Deep Research 需 200 美元 ChatGPT Pro 订阅才给用几次（戏称“奸商”），团队立志用中国模型（连生图都用国产）做出桌面工作者的完整多模态闭环——写报告、画图表、生成像 Koji 那样的播客、给家里小孩做动画片，甚至听音乐。因此发布首日（Day 0）即接入 MiniMax Open Platform 并点赞其 Token Plan，初期残缺被喷也愿直面社区。
  • 全球千人开源社区的治理难题：目前已有超过 1,000 位贡献者，遍布除南北极外几乎所有大陆，常收到看不懂语言的 issue。如何用 Agent 管理社区、清理被吐槽成“屎山”的历史代码，成了最头疼的新课题。Koji 补称多家热门开源项目（转写记作 Open Cloud、Nano Boat）近来也都公开喊苦。

金融场景的门槛与实时应对（虞扬）：虞扬点出金融用户两大痛点：一是不会表达需求（打开行情软件只知想赚钱，最高频提问是“帮我选几只个股”，谁都答不了）；二是同类产品只罗列一堆信息“没有然后”。AI 要先筛选信息，再解释术语（如 PE 市盈率高低的原因及对用户的直接影响）来降门槛。被 Koji 追问是否用 AI 炒股、赚超工资会不会辞职 all in，虞扬答合规原因对外不给投资建议，内部有回测机制看胜率，个人凭真实数据支撑很有信心；但他强调炒股远非纯文字推理——信息、个人画像与分析状态必须全对，更致命的是市场实时突变（如“OpenAI 突然 IPO”），比预测走势重要得多的是事情发生后立刻怎么应对。

四、基模与 Harness 共舞，以及 10T 大模型为何差“整整两代”

针对“未来还会不会有独立 Agent，还是只剩基模”，闫俊杰坦言去年此时还在做 M1，市面上几乎没有 Claude Code，根本想不到今天模型的形态，因此也无法预测明年（AI 一年顶其他行业好几年）。模型与 Harness（围绕模型编排上下文、工具调用与执行循环的系统外壳）并非互斥，而是共同进化：没有 Claude Code，Anthropic 的模型未必如此破圈；没有 GPT-5.5，Codex 也起不来。两者最终都是服务人类的手段。Koji 顺势援引 Alan Kay 名言：“预测未来最好的办法是去创造未来。”

谈及“10T（十万亿参数）大模型必须做成”的最大卡点，闫俊杰认为 AI 已如半导体一样是大产业，不存在跨不过去的神秘障碍，拼的是时间、实验与脚踏实地积累，但也面临三道硬工程约束：

  • Scaling Law（缩放定律）无法跨越十倍外推：规模放大 3 倍或 5 倍尚可外推，一步放大 10 倍公式即失效，训模型变成“开盲盒”。美国模型目前大体比中国大 10 倍，恰好是整整两代差距——国内每家都必须先扎实做好 3T，再借经验冲击 10T。
  • 推理架构与 KV Cache 瓶颈：规模每次跃迁都要重调算力、训练效率与网络结构。例如 M3 计算量控制较低，但推理时保存历史上下文的 KV Cache（键值缓存）仍偏大，下一代将重点压缩 KV Cache。
  • 200T 数据荒与噪声放大：按“数据量 ≈ 参数量 × 20”粗略估算，10T 参数需要 200T 数据，“全世界都没有这么多”；且模型越大越易拟合噪声，对数据质量要求倍增。

尽管坦言“比较忐忑”，闫俊杰仍相信有机会跑通——论及“进步速度最快”的口径，他定义为拿国内任意模型当下的智能水平除以 3 个月或 6 个月前的水平，无论看哪套标准，MiniMax 的提升倍率都位居前列。

五、AI Coding 拐点：Vibe Coding、工程品味与“没人敢上线”

张佳圆（人人都成了产品经理）：AI coding 已商品化，第一代 Vibe Coding 用户本就是产品经理，只是过去驱动程序员；如今人人都能 Vibe Coding，人人都站在了产品经理位置上。好产品经理的核心不是提 100 个需求，而是决定“做什么、不做什么”。他重提经典《Code Complete》（《代码大全》），指出复杂软件本质是组织工程；面对 Multica、DeerFlow 每天涌入的海量外部 PR，核心维护者必须钉死路线图与品味，并帮外部贡献者对齐上下文。

何涛（绝不能甩锅给 Agent）：何涛抛出全场金句：“从来没人说 Vibe Engineering，但写代码从来都是 Engineering 工作，而不只是 Coding。”他反感被叫“码农”，软件工程追求的是长期交付与持续生命力。他向闫俊杰提要求：现有 SWE-bench、SWE-bench Pro 都考一次性修完单题，模型看似“使命必达”，后人却没法接着维护——模型需要长期维护代码库的 taste（工程品味）。同时提醒人别把模型当魔法棒：模型擅长讨巧道歉“对不起我可以改正”，有时其实是人有偏见而模型原本没错，人类不能丢掉判断力。他推荐《Clean Code》（《代码整洁之道》），把工程先哲规范与 Google、Amazon 最佳实践蒸馏成 Skill 和上下文喂给 Agent，并痛批推诿：“最讨厌有人说‘这是 Agent 做的别怪我’——拿你的账号提交、花你的 credit，背后就是你的责任心。”如同当年通电一样，必须从 mindset 上把 AI 当工具而非魔法棒。

闫俊杰（生产狂飙，验证断层）：他举了近期去阿里交流的亲见：大厂几百个微服务，过去一人改一个仓库，如今一人借 AI 跨十几个仓库提巨大 PR，功能看似对，却没人敢上线，因为手动 QA 远跟不上生产。回忆早年自己逐行 code review、后来做架构 review，如今 Vibe Coding 里 review 几乎缺失——模型与 Harness 全奔着“生产”去，忽略了验证、交付与评审。去年 Claude 4、GPT-4.5 之前几千行就崩，今天撑到十几万行终究还是会崩，因上下文有限且人类直觉难完全替代。他主张在验证上投入接近研发生产的能力；MiniMax 内部也用类似 Multica 的流水线开发训练与后训练系统（从 base model 提 issue 逐阶段走完），靠 E2E 测试、benchmark 以及拉红线的项目 principles 兜底。

六、数据观转向：10X 专家合作，与 Anthropic 为何养核物理学家

一年前行业把数据理解为标注，如今 MiniMax 推出 10X 专家合作项目，请领域专家带路。闫俊杰归纳了两重触发：一是内部推演——AI 如同汽车加速赶路，但解决真问题单靠研究员不够；去年做 coding 时就发现开发工程师比算法研究员更懂“好代码”，更能做好评测、归类与强化学习环境构造。跑通“研究员 + 工程师”双角色后，拓展到网络安全、金融、法律自然升级为“算法 + 工程 + 领域专家”三角色。二是拆解 Anthropic 招聘版图——他们雇了大批经济学家、心理学家、哲学家乃至核物理学家，因为每次安全对齐都要实测越狱后能否用来制造核武器。半年前他还未理解，如今已彻底看透。

七、下半年押注什么：陪伴、工程里的温暖、留住思考与“用 AI 理解 AI”

尾声 Koji 笑称本想让每人荐一只个股，随即转为问 2026 年下半年最想 all in 的事：

  • 虞扬：不荐股，押注两件事——一是陪伴（金融市场多数时候亏比赚多，情绪陪伴难替代）；二是 Agent 从初期处处“限制模型别乱来”升级为“引领模型主动思考创造”。
  • 张佳圆：常写专栏《How AI Shapes Our Society》，认为 2026 年国产模型（MiniMax M 系列、DeepSeek 等）跨过拐点、多模态给模型装上眼睛，却也让普通人焦虑内耗。他讲了亲身故事：妻子因脱发焦虑看中医，问国内 DAU 最大的某 chatbot 照做反而掉得更多，抱怨“你们行业害人害己害到老婆身上”。他用 Codex 导入妻子全部体检报告、检查单、用药史和原聊天记录，接入飞书做成专属个人 Agent，帮她列好就诊提问清单，甚至录下医患对话反问医生，沟通大为顺畅。借此点题：Vibe Coding 不是为了让人失业，而是在冰冷软件工程里找回人类社会的温暖。
  • 何涛：只投资自己和公司；自称“AI 降临派”，认定 AI 终将比人更强，未来是与 Agent 竞争。警惕人类思维惰性把思考外包给 AI，自己会与 AI 共同探索，但把最核心的“思考”留给自己。
  • 闫俊杰：压轴直面 AI 黑盒——从业者至今不懂为何有 Scaling Law，十年前读博看过论文称超三层神经网络现有数学工具就难分析收敛性。他最关心“什么时候 AI 能帮助人类理解 AI”，这决定了安全与上限。他读过不少生命科学论文，发现人脑与神经网络高度相关：大脑虽不算矩阵乘法，却有类似矩阵的模块和近乎等价于梯度反向传播的机制，海马体记忆也和 DeepSeek 近期记忆机制很像。一年前还不懂安全为何重要，如今对可解释性也在经历同样觉醒，而 AI coding 将在帮助 AI 理解 AI 上发挥大作用。

机制：从生成补丁到安全交付的验证闭环

本文自拟工程示例（对应“跨十几个仓库提 PR 却没人敢上线”）：假设一家支付平台要上线阶梯退款新规，工程师借助 Agent 同时改写了订单核心服务、数据库表迁移脚本和前端退款页面。如果只跑一条“点击退款按钮返回 200 成功”的常规单测，完全暴露不出三类致命线上隐患：网络重试触发重复请求时是否会多退钱、尚未升级的旧版客户端调用接口是否报错、数据库迁移中途回滚后账务流水是否对平。

要把“生成速度”转化为“交付速度”，验证闭环必须前置为可执行约束，而非依赖事后人眼通读数万行代码：

验证阶段核心动作拦截的典型 AI 编码风险
1. 业务不变量声明先写死不可违背的红线（如“单笔订单累计退款金额 ≤ 已实付金额”），把规则写进测试与架构原则防止 Agent 为“跑通当前用例”悄悄绕开核心业务约束
2. 多维自动回归在沙箱内自动跑通正常、重复提交、高并发竞争、契约兼容性及失败恢复测试弥补 SWE-bench 式“单次修补即过关”忽视长程演进与边界条件的盲区
3. 跨模型与人工分级评审由独立上下文模型检查接口破坏与安全隐患，高风险变更仍由有权限的工程师依据变更面与回滚预案拍板防止同源模型共享错误假设，同时落实“代码提交归责于人”的工程责任制

需要强调的是，张佳圆提到的“让第二个模型审查第一个模型”确实能抓出大量表层遗漏，但若两个模型依赖相同的错误业务前提，仍会默契放行。只有把业务不变量、真实环境端到端测试、灰度监控与一键回滚接进闭环，外部世界返回的客观失败信号才能构成真正独立的验证。

独立判断：领域知识怎样变成可持续的训练信号

一、领域专家真正稀缺的不是“标答案”，而是定义“什么值得检验”

闫俊杰把数据观转向拆成“研究员 + 工程师 + 领域专家”三角色，切中了后训练时代的核心瓶颈：强化学习效果的上限，很大程度上取决于奖励环境（verifiable environment）是否贴合真实世界。在编程领域，资深工程师之所以比纯算法研究员更关键，是因为他们知道哪些线上故障真实发生、哪些架构债务会让三个月后的迭代瘫痪，并能把这些经验编码为自动测试套件。推广到金融、法律与核安全时，难点也在于把隐性专业判断转译成可复现的评分标准——例如金融策略必须严控数据时点（防止未来函数泄露）、滑点与交易成本约束，绝非“请来专家坐镇”就自动产出高质量训练信号。

由此延伸出一个更开放的评测命题：即便未来编程模型把所有既有 issue 都修得漂漂亮亮，它能否在没人报障之前，主动从线上日志、调用链和长期业务目标中揪出尚未写成 issue 的架构隐患？衡量这种能力时，不能只看模型“提出了多少条改进意见”，而要对照真实后续故障记录，同时统计漏报率、误报率以及修改后的可维护性成本。

二、Token 消耗量、参数规模与端到端质量，各回答不同问题

圆桌里高频出现三组数字：日均 10 万亿 Token 消耗、3T 到 10T 参数规模、多模型编排后的任务完成度。这三者彼此关联，却绝不能互相替代。Token 消耗量确实比单一刷榜分数更能反映真实调用活跃度，但它同时受定价策略、Agent 循环重试次数、上下文膨胀程度以及客户结构影响——单次推理啰嗦十倍，Token 账单也会暴涨，却不代表用户更满意。同样，参数规模只是模型容量的一个维度，真正决定工程体验的，是在给定延迟、内存（含 KV Cache）与预算约束下，端到端任务的一次交付成功率。跨模型对比时，把用量、成本、耗时与一次上线成功率并列披露，才能避开单一指标幻觉。

三、生产狂飙会把组织瓶颈从“写得快”推向“验得准”

当一个开发者借助多 Agent 并发，半天产出过去一个团队两周的代码量，软件工程的稀缺资源就彻底从代码产出转移到了理解带宽与验收吞吐。如果团队不按比例重投自动化测试、契约检查与可观测性，未验证的逻辑债务会迅速堆垮整个代码库——这恰恰呼应了何涛“Vibe Coding 不是 Vibe Engineering”的警示。至于每个团队究竟该把多少研发比例投入验证，取决于业务容错率（支付清算与内部一次性脚本截然不同）和现有测试底座，不宜把访谈中的经验呼吁当作固定配比。

四、大脑类比与个人健康 Agent 的现实边界

圆桌尾声两个极有感染力的段落也值得留出冷静界线。一方面，闫俊杰借人脑矩阵式模块、类反向传播机制与海马体记忆来表达对“用 AI 理解 AI”的期待，这是富有启发性的跨学科类比，但神经科学至今对大脑局部学习规则与人工神经网络反向传播的等价性仍存广泛争论，不能据此认为现有模型记忆机制已经复现了人类海马体。另一方面，张佳圆为家人搭建个人就医沟通 Agent，出色示范了“汇总零散病历 + 准备高质量就医提问”的合法、高价值用法，但它本质上是沟通整理工具，既不能替代临床诊断，也提示个人敏感医疗数据的本地加密与授权边界必须格外谨慎。
