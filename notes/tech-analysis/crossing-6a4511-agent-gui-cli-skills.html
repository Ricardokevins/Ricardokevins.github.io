钟天杰与归藏：Agent 时代的界面、工具与工作流

从一篇关于 GUI 思维的文章出发，讨论机器如何调用工具、人如何保留判断，以及 Skill 能否成为新的产品。

对话脉络 · 工具与工作流 · 独立判断 · 证据边界

先把对话讲清楚

Koji 与真格基金投资总监钟天杰（Jack）、开发者归藏回看近一年多 Agent 的变化。三人围绕图形界面、命令行、Skill、Agent 经济、OpenClaw 和开发者资助展开。钟天杰觉得模型能力超出预期，但产品还没有充分减少人的注意力投入；归藏则说，自己维护大型代码项目和自动化内容工作流的能力都超出当初想象。这是他们各自的使用体验，不是统一测量的生产力结果。

1. “不投资 GUI 思维”究竟是什么意思

钟天杰解释，文章针对的是一种产品设计前提：默认人必须逐步打开界面、操作每个按钮，才能完成工作。如果 Agent 能承担一部分执行，产品不应只围绕让人长时间点击来设计。但他同时强调，只要人还要理解、确认或欣赏结果，图形界面（GUI）仍然有价值；大众使用 Agent 的入口本身也需要易用的界面。

归藏说，他会用 FFmpeg 处理视频，让 AI 根据需求调用命令完成裁剪等操作。他认为用户通常只想得到可用的视频、日程或文章总结，而不是关心文件在哪个文件夹、按钮在哪一层。讨论 Notion 等现有产品时，他担心频繁变动界面会影响老用户，希望保留熟悉入口，同时探索面向 AI 的新路径。这是对具体产品体验的评价，并不证明某一种界面已经成为最终答案。

2. 邮箱为什么让人感到疲惫

钟天杰回忆，自己订阅了很多邮件，曾通过关键词、标签和规则分类；来源越来越多后，维护规则的工作反而超过了阅读信息的价值。他还遇到一次过滤器设置错误，邮件被意外归类。后来他授权 Agent 按自己的需求总结过去一天的邮件，认为这减少了手动整理。

他由此提出，邮件服务可以成为 Agent 背后的执行和信息来源：用户未必每次打开原来的界面，但底层邮件账户和数据依然重要。归藏接着举反例说明可视化并未消失：视频需要在对话中直接预览，图片与文字需要一起查看，文件需要能被人打开。界面的价值从逐步操作，部分转向理解、审查和呈现结果。

3. CLI：开放能力为何也会引发商业顾虑

命令行接口（CLI）通过符合规定格式的文本命令调用程序。归藏说，过去人难以记住大量参数，Agent 可以把“降低码率”等意图转换成程序可执行的命令；前提仍是命令正确、程序存在且有权限。他们提到飞书、邮件及消费服务向 Agent 开放能力，并讨论哪些平台可能不愿开放。

钟天杰认为，开放接口可能让外部 Agent 带来用户，却也可能削弱原有入口和客户关系，因此企业需要权衡。归藏希望常用通讯软件能更方便地被自己的 Agent 使用；钟天杰则猜测，部分服务可能选择向有限的合作渠道开放。两人还讨论内容分享如何带动聊天迁移：当朋友讨论的内容在另一个平台时，部分对话也可能跟随过去。节目中的具体平台状态、用户数字与未来合作方式属于当时的观察和推测。

4. Skill 保存了什么

归藏最推荐自己的演示文稿 Skill：他回忆初版从个人记忆和旧项目中提取了一些风格，随后由自己调整。钟天杰则使用不同会议类型对应的总结流程，以及通过连续追问帮助澄清想法的工具。两人所说的 Skill，大体是 Agent 可复用的一组任务说明、规则和可能配套的工具或资源。

他们认为系统可以从重复活动里提出流程草稿，但归藏强调，人仍需检查和修改，因为系统可能猜错真正想要的效果。关于 Skill 的寿命，他预计模型增强会吸收一部分简单技巧，但专门的流程和生态仍可能持续一段时间。钟天杰则认为，普通用户最终更可能信任能完成任务的产品，而不是比较其背后安装了哪个 Skill。

归藏提到作品展示、用户反馈、安装和更新仍不完善；GitHub 星标或讨论热度也不是准确的安装量。他看好 Skill 的商业价值，但承认让用户在已经支付模型费用后再为它付费并不容易。是否存在可持续收入，需要看任务质量、复用频率和付费意愿，而不能从安装量直接推出。

5. Agent 经济、入口和部署

谈到给 Agent 提供沙箱、记忆和支付等基础设施，钟天杰说，创业者应先考虑利用现有框架；他觉得模型和计算仍处于重要建设期，并设想未来 Agent 可能在一定范围内帮助需求方和供给方匹配。他也承认自己没有尝试节目中提到的一些基础设施，时间判断高度不确定。

谈到 OpenClaw，两人认为它帮助大众理解新的 Agent 使用方式，尤其是把交互放进熟悉的即时通讯界面。但归藏也指出安装、宕机和重启的负担：用户第一次觉得新鲜，并不代表它会稳定留在日常工作里。工具能否持续服务，取决于连接、故障恢复和用户是否仍愿意使用。

6. Token Grant 和下一个阶段

节目介绍一项面向早期开发者的 Token Grant：为入选项目提供五万元人民币的模型调用费用支持，称不占股份。归藏介绍自己的 CodePilot，愿景是让 Skill、记忆和工具配置能够保留，并适配不同模型或框架；钟天杰介绍一个持续生成代码的实验，关注它后续会怎样变化。代码行数只能说明代码规模，不能单独证明任务能力或真正的自主改进。

最后，钟天杰强调技术变化快，需要有调整的能力；归藏认为未来产品未必呈现全新界面，可能仍是视频等熟悉形态，但生产方式和供给数量发生变化。两人也承认今天的预测可能出错。节目开场的“Agent 元年”日期在官方简介与机器转写中不一致，本文不把其近似时间线当作精确发布史。

机制：一个需求怎样穿过几层工具

本文自拟例子：用户说“整理今天的会议，并标出需要我决定的事”。Agent 先识别需要读取哪些会议记录；通过已授权的接口取得内容；再按约定模板提取议题、决定和待确认事项；最后把带来源的结果展示给用户。若还要修改日程或通知他人，这是额外的动作，需要相应权限和清楚的用户意图。

几层工具在这里承担不同职责：CLI 是调用程序的一种方式；API 允许程序按定义的接口交换数据；MCP 是让应用向模型系统提供工具和上下文的一种协议；Skill 可以告诉 Agent 某类任务应遵循什么步骤、模板和边界。它们可以组合：Skill 指导先做什么，Agent 再通过 CLI 或 MCP 调用具体工具；没有某一层并不意味着任务无法完成。

实际自动化还要处理错误：记录可能不完整，人物名称可能识别错，接口可能失败，权限可能过期。一个好的结果应能回到原始记录核对；执行写操作时应明确对象、预期变化与失败状态。把按钮换成自然语言并不会自动消除这些问题。

独立判断：减少操作，仍要让结果可检查

界面与机器接口解决的是不同瓶颈

批量读取和重复操作适合程序接口；比较视频、审阅财务数据、决定是否采用方案则常需要图表和可视化。强产品的分界不在有没有 GUI，而在何处让机器执行、何处让人看到足够的信息作判断。如果只隐藏操作过程，却不显示来源、失败和待决事项，节省点击可能变成增加核对成本。

Skill 的价值在可复用的判断，而不只是提示词长度

一份会议总结规则如果只是要求“总结重点”，较强模型也许无需专门流程；如果它能区分不同会议、保留决策的原话与归属、识别缺失证据，并且经过真实使用修订，就为模型提供了具体工作标准。可以用相同材料比较有无该流程的遗漏、归属错误和用户修改量；如果表现没有稳定改善，流程的存在本身不是优势。

开放接口的价值取决于交易关系

如果外部 Agent 带来的新增客户和完成交易的收益，大于平台失去入口、客服与治理的成本，开放可能划算；如果原业务主要依赖展示广告或控制用户体验，激励就不同。企业也可以开放部分只读能力、限制写操作，或与少数渠道合作。因此“有接口”与“完全失去入口”之间存在许多选择。
