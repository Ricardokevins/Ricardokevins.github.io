Token在大型语言模型中，Token是处理文本的基本单位。它可以是一个词、一个字符、或一个词的一部分（subword）。模型的输入（prompt）和输出（generation）都是以Token序列的形式进行处理和计量的。模型公司通常根据处理的Token数量向用户收费。
Tokenmaxxing指在当前AI发展的早期阶段，一些公司或用户过度消耗Token的现象。这可能是因为模型效率低下、追求表面上的高使用率，或是对Token经济学理解不足，导致了大量不必要的计算资源浪费。
SOTA (State-of-the-art)指在特定时间点上，某个领域（如此处的AI模型能力）最先进、性能最好的技术或模型。
Coding Agent指专门用于辅助或自主完成编程任务的AI智能体。它能理解自然语言需求，生成、修改、调试代码，并与开发环境交互，极大地提升软件开发效率。

主持人张小珺首先提问如何理解AI时代的计量单位“Token”。嘉宾Freda认为，未来衡量一家公司的标准会是“dollar per token”（每美元可购买的token数），类似于工业时代的“dollar per kilowatt-hour”（每美元可购买的电量），衡量的是能耗产出比。但她立刻指出，Token是一个极易误导人的单位，核心在于“token per task”（每任务消耗的token数）在不同模型间差异巨大，可能相差几十甚至上百倍。

Freda解释了差异的几个原因：

1. 输出长度不同：高效模型用精简代码完成任务，而低效模型可能需要数千行冗长代码，表面都完成了任务，但Token消耗量级完全不同。

2. 隐藏的推理消耗：模型在给出最终答案前，会进行大量用户不可见的中间推理（Reasoning Tokens），这部分消耗因模型而异。

3. Agentic Workflow的放大效应：基于Agent的工作流会进一步放大Token的消耗。

因此，Freda明确表示，Token消耗并非越多越好，恰恰相反，最终追求的是效果和效率。她以编程模型Cursor为例，指出其完成同样任务时消耗更多Token，说明其“能效”更低。但在行业早期，不了解情况的公司CFO可能会因为看到使用量暴增而错误地追加投入，这是一种普遍存在的误解。

对于“Token大爆炸”是否会因模型效率提升而停止，Freda认为答案复杂。她将AI总投入拆解为四个变量的乘积：用户数 × 每用户任务数 × 每任务Token数 × 每Token价格。前两项（用户和任务量）随着AI从程序员向普通白领破圈，必将大幅增长。后两项则有优化空间。她预测，行业会逐渐从“按Token收费”转向“按效果收费”。她举了AI客服公司Sierra的例子，该公司按AI成功解决问题的比例收费，若转接人工则不收费，这种模式将客户与公司的利益绑定，共同追求效率。Freda认为，这种模式会首先在客服、销售转化、催收等结果易于量化的领域普及，而创意写作等领域可能长期维持按Token收费。

主持人询问嘉宾Freda如何看待Anthropic的领先优势和壁垒。Freda认为，过去两年“SOTA模型轮流坐庄”的假设可能正在被打破。核心原因是Coding Agent的成熟催生了一个关键循环：“更好的AI创造出更好的AI”（better AI makes better AI）。一旦这个“递归式自我改进”（recursive self-improvement）的循环越过某个临界点，领先者的曲线将变得极其陡峭，后来者可能再也无法追赶。她将此比作汽车取代马车的历史进程：早期汽车频繁抛锚，快马尚能追赶；一旦汽车性能稳定，没有引擎的马车便再无机会。

Freda指出，这个转折点始于2024年1月左右，标志是Coding Agent的成熟，它将工程师的生产力提升从几个月前的5%提升至显著水平，使得模型迭代速度从数月缩短至一个月。这解释了为何Meta这样的大公司愿意花费数十亿美金使用外部模型，因为不这样做，迭代速度就会落后一个档次。各大公司都已将Coding能力置于战略核心：OpenAI按GPT和Coding两条主线重组；Google由Sergey Brin亲自负责Coding；Meta和xAI也都在该领域积极布局。

关于模型公司的商业模式，Freda反思道，模型层并非传统的SaaS（按人头订阅），而是基于用量（usage-based）的模式。这鼓励了企业客户同时使用多个供应商，并根据每个查询（query）的性价比进行动态选择。因此，OpenAI和Anthropic之间更像是共同做大市场，而非零和竞争。

Freda还回顾了投资界对Coding市场规模（TAM）的认知演变。最初，投资人仅以美国约四五百万开发者为基数，估算出百亿美金的市场，但Anthropic一家的收入就远超此数。她认为，正确的理解应如Anthropic创始人Dario所言，目标是全球数千万亿规模的“白领市场”，因为任何可被计算机自动化的任务都属于Coding的范畴。当她看到Coding产品收入迅速飙升至10亿美元时，便意识到自己最初的投资框架是错误的，并及时修正了判断。

最后，Freda讨论了模型公司的盈利模型。她曾转述Dario提出的“负向滚雪球”理论：模型训练成本的增长速度快于收入增长，导致持续亏损。但最近几个月的情况证明，如果收入增长的斜率远超训练成本的增加，公司也能突然盈利，这是因为市场需求（尤其是对Coding能力的需求）远超预期。当需求爆发时，公司被迫将更多算力（Compute）从训练转向推理，从而意外实现了盈利。

主持人询问AI对软件公司的冲击。Freda认为，AI带来的最大反思是关于软件公司本身的组织和商业模式。传统软件公司如ServiceNow、Adobe、Salesforce等，拥有数万名员工，其中销售和营销人员占比极高，相关开支可达收入的40-50%。相比之下，同样是To B业务的Anthropic，80%是企业用户，员工仅3000人，人均创收可达千万美元级别，比传统软件公司高出一个数量级，且几乎没有正式的销售团队。这让Freda反思，过去是否过于强调了销售的重要性，以及用户对“智能”本身的需求是否是无限的。

基于此，主持人追问投资人是否在抛弃软件公司。Freda给出了肯定的回答。她解释，从投资的DCF（现金流折现）模型看，当未来的不确定性上升时，折现率（discount rate）会提高，从而压低公司当前的估值。AI的出现极大地增加了软件公司未来的不确定性。她观察到，二级市场的软件公司股价已大幅下跌，而一级市场许多公司仍维持着AI时代前的估值，造成了一二级市场的估值倒挂。

在讨论哪些软件更脆弱时，Freda提出了两个判断维度：

1. UI占比：核心价值在于精美UI的“点解决方案”（point solutions），如电子签名、项目管理工具，受冲击最大。

2. 数据结构化程度：数据结构越规整的软件（如项目管理工具Monday），越容易被Agent替代。反而是像Excel这样内部数据混乱、每个单元格语义都不同的软件，更难被直接替代。

对于Office套件的未来，Freda认为虽然AI能快速生成网页版PPT，但只要工作流中有一个人需要手动微调，PowerPoint这种所见即所得的工具就有其价值。她认为，只要“流水线”上还存在手动修改的环节，Office套件就会继续存在。

关于AI时代新的软件机会，Freda认为，仅仅在现有CRM、ERP前加上“AI”前缀并不能带来本质改变。真正的机会在于处理和记录过去无法被结构化的“决策过程信息”。例如，CRM记录了给客户25%的折扣，但没有记录为什么是25%而不是30%，以及决策过程中各方的意见和博弈。AI能够处理这些非结构化数据，为企业决策提供更深层次的洞察。

最后，Freda强调软件必须为Agent重新设计。她以自己连接Agent到Slack和Discord的经验为例：Slack基于HTTP协议，是为人际聊天设计的，Agent使用时效率不高；而Discord基于WebSocket，支持双向实时通信，更适合Agent的高频交互。这表明，现有的软件架构需要变革以适应AI Agent的需求。

为了说明技术与生产力提升之间的时差，Freda举了两个历史案例：

1. 电力革命：电发明后，社会生产率在长达二三十年的时间里没有提升，甚至有所下降。原因是工厂最初只是简单地用电机替换掉原来蒸汽机的位置，而没有改变围绕蒸汽机设计的垂直工厂结构。直到为适应电力的特性而发明了“流水线”这一新的生产组织方式，生产率才真正腾飞。Freda将这一阶段比喻为“把电机塞进蒸汽机”。

2. 计算机革命：80年代计算机已在办公室普及，个人工作效率提升，但宏观生产率并未改变。直到90年代中后期，沃尔玛、亚马逊等公司围绕计算机和网络重新设计了业务流程（如企业数据库、早期ERP、现代供应链），生产率才出现跃升。

主持人追问，当前AI处于哪个阶段。Freda判断，正处于“把电机塞进蒸汽机”的阶段：每个人都在将AI加入自己的工作流，但很少有人反思流程和公司组织本身为何如此设计，例如为什么需要庞大的员工数量和复杂的层级结构。

Freda进一步从第一性原理分析，传统公司层级结构的核心功能是“信息传递”。由于组织庞大，无人能掌握全貌，管理层（managers）的核心作用就是自上而下传递、提炼信号，并自下而上翻译、拆解信息。开会、进度同步、季度对齐等活动，本质上都是为解决人与人之间高昂信息传输成本而设计的“信息搬运机制”。

在科技公司，这种“翻译成本”尤为明显。一个产品从PRD（产品需求文档）到设计、开发、QA、Go-to-Market，可能耗时六个月，其中充满了大量的翻译和等待。Freda引用一位创始人的观察：AI首先压缩了开发时间，使得QA成为新瓶颈；解决QA后，产品设计（PM）又成为瓶颈，接着是市场推广（Go-to-Market）。这就像“打地鼠”，说明整个流程都需要重新设计。

对于未来的组织形态，Freda提出了一个比喻：工作模式将从过去一棒接一棒的“接力赛”，转变为更像“篮球赛”的模式。即由3到5人组成具备所有必要技能的自治小分队，可以同步推进、自行决策，只有重大方向问题才需向上汇报。至于具体的成功案例，Freda坦言在美国尚未看到共识性的范例，但普遍认为中层将被压缩。她预想，未来企业内部可追踪的数据量会暴增，Agent将拥有上帝视角，辅助决策，让企业变得“更活了”。

Technology Diffusion / Economic Diffusion由Anthropic CEO Dario Amodei提出的两个概念。在本段中，“Technology Diffusion”（技术扩散）指AI模型能力本身的快速进步；“Economic Diffusion”（经济扩散）指这项技术被整个社会和经济体系实际吸收、应用并最终转化为生产力提升的速度。后者通常会显著滞后于前者。

三、软件为何脆弱：UI 份额、结构化数据与决策上下文

Freda 的软件判断不是“所有 SaaS 都会消失”，而是指出两类暴露面。第一类是软件主要替用户点击界面、搬运结构化字段、生成固定报告；代理可以通过 API、浏览器或自然语言绕开那层 UI。第二类是软件只保存“发生了什么”，没有保存“为什么这样决定”：例如折扣为何是 25%、谁反对过、客户真正担心什么。

后者反而可能成为新机会。AI 原生软件不只要把结构化数据库接给 Agent，还要保存决策过程、未决问题、权限、证据和责任链。数据仓库也不天然安全：如果 Agent 能直接访问系统并解释数据，一次性 SQL 配置的价值会下降；但治理、口径、质量和审计的重要性会上升。

四、接力赛变篮球赛：组织层级本质是信息翻译成本

节目把传统组织比作接力赛：产品把目标交给研发，研发交给测试，测试交给运营，每次交接都需要翻译上下文。层级不只是一种权力结构，也是一种信息压缩和传输机制。AI 能减少文字传输，却没有自动消除目标冲突、责任不清和优先级争夺。

Freda 因此提出小型跨职能“篮球队”：成员拥有更完整上下文，可以在同一目标下持续传球、补位和决策，中层翻译层被压缩。这个模型的风险也很明显：若没有明确的停止权、审计和资源边界，扁平组织可能只是把隐性权力集中到最能控制上下文的人手里。

旧接力式组织小分队式组织验证指标
职责边界清楚，但信息反复翻译。同一上下文中跨职能协作，围绕结果而非工序。交接次数、等待时间、返工率。
中层负责汇报和分配，风险集中在交接。代理承担部分执行，中层转向目标、资源和风险控制。决策周期、异常升级、责任可追溯性。
按岗位评价个人产出。按任务/产品结果评价团队。长期质量、维护负担、团队学习速度。
组织改革的证据要求“3–5 人小队”“中层被压缩”是设计假设，不是已普遍验证的组织定律。要看连续季度交付、人员流失、事故率和知识传承，而不是一次成功项目。

五、投资行业与应用创业：可计算的目标先被自动化

Freda 认为，若投资问题有干净数据、明确持有期、目标收益、最大回撤和可执行交易约束，AI 理论上可以构建比人更稳定的系统。但现实市场混入制度、叙事、参与者反应和数据缺口，因此 AI 更可能先压缩事件驱动、财报摘录和信息搬运，再把人推向组合目标、风险偏好、情景设计与责任。

应用创业面对模型公司的向下吞并压力，单靠法律、合规或最后一公里服务不一定够。更有潜力的是 Agent 原生基础设施：身份、浏览器、电话、支付、权限、审计和复杂 B2B 采购。消费购物的代理化可能需要信任与售后，企业采购则天然有更高客单价和更清晰的工作流。

因此“模型会吃掉应用”并非完整判断。更准确的问法是：哪一层拥有不可替代的上下文、责任和结果，哪一层能以合理成本持续改善，哪一层可以把失败变成产品资产。

六、资本市场与社会：对不确定性保持开放，而不是选择一个口号

节目讨论大模型公司的算力资本开支、负自由现金流、超大型 IPO、裁员和通缩。Freda 反复保持“open minded”：短期技术扩散可能先造成劳动力替代和价格压力，长期生产率提升又可能扩大总需求、创造新行业。两者不互相排斥，关键在速度、分配和组织能否跟上。

Anthropic 的公开 Economic Index 也把“技术能做什么”和“经济如何吸收”分开测量：使用已经扩散到更多长时任务，但真正的就业、工资和生产率结果仍需更慢的宏观数据验证。由此，投资者不应把模型调用增长直接等同于 GDP 增长，政策也不能把转型成本全部转给个人。

最后关于孤独的讨论并非情绪附录。信息交换越便宜，人与人相遇时真正稀缺的就越可能是信任、共同经历、情感与价值冲突中的诚实。AI 可以替我们做分析，但不应替我们取消关系。

原文讲解到这里。接下来才进入本文的结构化抽象、证据分层和独立判断。

核心判断：Token 是成本计量，不是价值本身

把 AI 产品写成“每个用户消耗多少 token”会产生一个危险错觉：仿佛更多计算就等于更多智能，更多智能就等于更多收入。Freda 提供了更有用的单位经济框架：

用户数 × 每用户任务数 × 每任务 token × 每 token 价格这个分解能把规模、使用频率、任务复杂度和价格分开。真正需要优化的不是 token 越多越好，而是单位任务的有效结果、成功率、延迟、人工接管和长期复购。

效率

用更少 token 完成同一任务，降低延迟和推理成本。

效果

让任务真正解决问题，而不是生成更多文字或更长轨迹。

结果定价

在可验证的场景里按解决率、节省时间或最终产出收费。

因此 Tokenmaxxing 可以同时成立为两件事：单个任务可能故意使用更多计算，以获得更高质量；总市场仍可能因为用户和任务数量增长而扩大。关键是不能把两者混为“token 消耗就是需求”。

从原文切换到独立分析

以下卡片是本笔记此前整理出的独立洞察，现统一放在核心判断之后，避免与嘉宾/作者原文混读。

Insight：AI 不是消灭软件，而是把“界面软件”逼成“决策基础设施”真正耐用的产品要让 Agent 能读懂、执行、回退、解释和审计；只提供按钮和字段的价值会被重新定价。

进一步推演：这期访谈留下的八条 Insight

  1. Token 是工业账本，不是产品。 只看 token 会把试错、浪费和价值混在一起；产品必须回到结果与责任。
  2. 单位经济要从“请求”改写为“任务”。 任务有输入、动作、验证、人工接管和后果，才能算出真实毛利。
  3. 软件的下一个护城河是决策上下文。 保存字段不够，保存原因、异议、证据与责任才可能让 Agent 长期有用。
  4. 组织层级是翻译成本。 AI 会压缩传递时间，但不会自动解决目标冲突和权力分配。
  5. “AI 训练 AI”必须经过维护账本。 自动生成更多代码只有在返工、安全、审查和未来维护都更低时才是真正递归。
  6. 应用层的机会转向 Agent 基础设施。 身份、支付、合规、浏览器和电话是把智能变成可承担行动的接口。
  7. 技术扩散和经济扩散是两个时钟。 模型能力的指数增长，不能直接替代组织重构、资本回收和劳动力再配置。
  8. 信息越便宜，人的连接越需要被主动保护。 未来的“效率”不应以消灭所有面对面关系为目标。

怎样证伪或修正这套判断

  • 若 token/task 与最终客户价值长期高度相关，结果定价的必要性会被高估。
  • 若所有 SaaS 的结构化数据都能直接转化为高质量 Agent 行动，决策上下文的差异化会减弱。
  • 若跨职能小队在规模化后持续增加事故、隐性权力和知识断层，篮球式组织不是默认答案。
  • 若模型公司无法把 Coding 反馈写回模型或产品，递归训练优势只是一种叙事。
  • 若自动化同时带来足够快的新岗位、工资和需求扩张，短期裁员/通缩的路径需要重新估计。
